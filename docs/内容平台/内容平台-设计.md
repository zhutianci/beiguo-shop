## 0. 一页结论

**定位**：把 `/forum` 从「4 个板块、5 篇帖子、客户端渲染、匿名即发」的留言板，改造成**以「可复现的原创」为核心的 AI 实用内容平台**。主打三类内容：
① 生图 / 视频**提示词**（效果图 + 可复制的 prompt + 模型参数）；
② ChatGPT / Claude / Codex 等的**功能教程与使用技巧**；
③ **AI 应用与工作流分享**（包括用户推广自家产品，放在隔离区）。
讨论和问答保留，降为第四类。

**为什么能做成 SEO 引流**：调研里真正靠搜索吃到流量的提示词站（PromptHero 约 31% 来自搜索、YouMind）和工具站（ai-bot.cn）走的是同一个公式：

> **每条内容一个独立的服务端直出页面 + 「模型 × 主题」聚合页 + 详情页之间大量内链。**

Civitai、Lexica 这类靠社区或红利起来的站，搜索流量很少，Lexica 还在快速衰落。
关键词实测也确认了需求：「gpt-image-2 提示词大全」「nano banana 提示词大全」「seedance 提示词」「chatgpt 生图提示词 / 额度 / 失败」「chatgpt 记忆 / 深度研究 / agent / skill」「claude code 教程」等都有成串的下拉联想。

**为什么必须主打原创**：
- Google 2024 年以来对「规模化内容滥用」和「站点声誉滥用」的打击都是**站点级**的，会连带商品页。本站已经有一个被标为风险的 AI 资讯模块。
- 本站 Google 只收录约 17 个 URL，信任度很低，经不起再来一批薄页。
- 所以平台的第一原则是**宁缺毋滥**：新内容默认不给搜索引擎，经审核、达到质量门槛后才逐条放开收录。

**和生意的闭环**：
- 每条 ChatGPT 提示词或教程都自然带出「这个功能要 Plus / 额度不够怎么办」，详情页的「去 ChatGPT 生成」按钮导向 `/chongzhi`。
- 达到信任等级的作者，这个按钮可以带上他自己的内推码。作者因此按现有内推系统拿返现，形成「写好内容 → 带来订单 → 作者拿钱」的正循环。这是本站相对 PromptHero 这类纯内容站独有的激励。

**分期**：
| 期 | 内容 | 预计 | 关键产出 |
|---|---|---|---|
| P0 | 地基 | ~1 周 | 安全修复、关闭匿名发帖、审核队列、服务端直出、收录闸门 |
| P1 | MVP | ~2 周 | 提示词库 + 教程、模型 hub 页、作者页、sitemap、IndexNow，加站方 40 篇种子内容 |
| P2 | 社区化 | 2~3 周 | 收藏 / 关注 / 通知、合集、同款与二创链、积分等级、原创查重、应用与自荐区、问答 |
| P3 | 增长与变现 | — | 作者内推返现、月度激励、赞助位、GitHub 仓库攒外链、公众号同步、视频托管 |

**诚实的预期**：
- 平台本身两三周就能做出来，**难的是内容**。
- 提示词页必须有真实出图，教程必须实测并标注日期。这部分要站长或运营亲手在 ChatGPT 里跑，Claude 只能帮忙起草文字、整理结构。
- 按现在的站点信任度，新页面收录要 1~4 周，有意义的排名要 2~6 个月。

## 1. 现状与约束

### 1.1 现有论坛（代码事实，2026-10-06 盘点）

| 项 | 现状 | 对改造的影响 |
|---|---|---|
| 数据 | `ForumPost`、`ForumComment`、`ForumLike`、`ForumCategory`（`prisma/schema.prisma:1271-1364`）；标签是逗号分隔字符串；图片是 JSON 字符串；没有上传表、没有 slug、点赞没有唯一约束 | 加列、加新表，**不改名、不删列**（`scripts/deploy.sh` 写死了 `--accept-data-loss`，Prisma 会把改名当成 DROP+ADD） |
| 内容量 | 4 个默认板块，约 5 篇站方原创长文 | 几乎从零开始，没有历史包袱 |
| 渲染 | 列表页和详情页都是 `'use client'`，正文从 `/api/` 拉取，而 `/api/` 被 robots 禁止抓取 → **爬虫看不到任何正文**；详情页没有自己的标题，继承列表页 | 必须拆成服务端外壳 + `generateMetadata` |
| 发帖 | 匿名可发，**即发即公开，没有审核、没有敏感词过滤、没有验证码** | P0 必须改 |
| 限流 | 已有（`src/lib/forum-throttle.ts`，09-26 安全审计 G44 加的），进程内计数 | 够用；多副本或重启会清零，现阶段可以接受 |
| 安全缺口 | ① 后台审核操作走公开接口 `/api/forum/posts/[id]`，没有同源校验；② 作者编辑时能把帖子挪进「官方公告」板块；③ `safeUrl` 放行 `//evil.com`；④ `images` 字段不校验来源；⑤ 链接 rel 缺 `ugc`；⑥ 上传不去 EXIF | 已单独开了修复任务（见对话里的任务卡片），P0 一并收口 |
| Markdown | 自研、无依赖、先整体转义再生成白名单标签；**不支持表格** | 教程和对比需要表格，P1 补 |
| 上传 | 存在本机 volume `forum_uploads`，全站上传合计配额 1.5GB；单文件 5MB；不压缩、不转格式 | 提示词平台以图片为主，P1 必须压缩；视频不能放本机（见 §10.4） |
| 分站 | 论坛只在主站开放，分站返回 404 | 继续保持只在主站 |

### 1.2 站点层面的约束

- **Google 只收录约 17 个 URL**（09-30 SEO 审计），站点信任度低，任何「批量放量」都有风险。
- **`seo/restructure` 分支（未上线）把 `/forum/*` 设成了 noindex 并移出 sitemap。** 这和本方案不冲突：老论坛先按那个分支处理；新的内容页逐条按闸门放开收录（§11.1）。**合并顺序：SEO 批 1 先上线，内容平台 P0 再 rebase 上去。**
- **AI 资讯模块**的去留是站长另一项待决事项。内容平台必须和它划清界限：**不接受任何批量 AI 生成内容**，站方自己也不例外。
- **百度**：本站未备案，sitemap 每日上限被压到 1 个，至今没带来过一单 → 百度只当附带收获。**必应**是中文 AI 用户的第二入口（ai-bot.cn 约 26% 流量来自 cn.bing），值得接 IndexNow。
- **Google Search Console 仍未验证**（交接文档 §6 第 1 条）。没有它，内容平台的效果无法衡量。**这是开工前站长唯一必须先做的事。**
- 服务器 1.8G 内存，本机构建会 OOM。新增依赖（如图片处理用的 `sharp`）要先评估构建内存。
- 收银台只支持支付宝、下单不填邮箱——内容里写到购买流程时必须和代码一致（交接文档里反复踩过这个坑）。

### 1.3 合规约束（国内）

- 《人工智能生成合成内容标识办法》+ 强制国标 GB 45438-2025 已于 2025-09-01 施行：**AI 生成的图片和视频要有显式标识（页面角标）和隐式标识（文件元数据）。**刚好 Google 也要求 AI 图片写 IPTC `DigitalSourceType = TrainedAlgorithmicMedia`，一次做完两边都满足。
- 跟帖评论服务要求「后台实名、前台自愿」，并要有审核和举报处置。本站是邮箱注册，没有手机实名。**开放 UGC 本身会抬高主体的合规风险**，所以审核和举报必须先于开放上线，而不是事后补。
- 09-30 SEO 设计里定过：**接码、账号、KYC 类教程不写**（反诈法风险）。内容平台沿用这条，同样不收。

## 2. 定位与原则

**一句话**：中文世界里「拿来就能用、作者亲手验证过」的 AI 实用内容库。

五条原则（每条都对应后面的具体机制）：

1. **可复现优先于观点。** 提示词必须附自己的出图和参数；教程必须写明测试日期和账号类型（Free / Plus / Pro）。 → §5 模板、§6「实测」徽章
2. **默认不曝光，精选后放大**（少数派模式）。 → §7 精选、§11.1 收录闸门
3. **原创有回报，搬运没出路。** 首发才能进精选、拿激励；转载能发，但不给搜索引擎。 → §6
4. **推广有出口，但有围栏。** 用户可以推广自己的 AI 产品，但只能在自荐区、必须披露、按比例。 → §9
5. **内容回到生意。** 每个内容页都有和本站商品的自然连接，但不硬塞。 → §13

**明确不做的**：
- 采集或搬运来充数量；
- AI 批量生成「教程」；
- 越狱、破限、擦边类提示词。下拉词里「chatgpt 生图破限」「豆包 擦边 提示词」确实有量，**不做**，FlowGPT 就是这么滑下去的；
- 接码、账号、KYC 教程；
- 付费墙挡正文（百度明确算违规，CSDN 的前车之鉴）。

### 3.2 选题的三条纪律

1. **标题用实测词，不用站长口语。** 和充值页同一条规矩（「代开」是零需求词）。例如写「ChatGPT 记忆已满怎么办」，不写「ChatGPT 记忆功能介绍」。
2. **「X 提示词大全」类聚合词由 hub 页去接，不让单帖去抢。** 单帖抓长尾（「gpt-image-2 证件照提示词」），hub 页抓头部（「gpt-image-2 提示词大全」）。
3. **「chatgpt plus 值得买吗」「chatgpt 和 claude 区别」这类商业词，和 `/chongzhi` 落地页存在内部竞争。** 默认由 `/chongzhi` 承接；内容平台只写「实测对比」角度的文章，并内链到落地页。动笔前先查 SEO 设计稿里的选词表，避免两页抢同一个词。

### 3.3 时效性提醒

- **Sora 独立 App 已于 2026-04-26 关停，API 于 2026-09-24 关停**（OpenAI 2026-03-24 宣布）。有报道称视频生成并入了 ChatGPT，但具体形态**未核实**。所以视频栏目按模型中立设计，「Sora 提示词」只作为历史和学习内容，不能写「去 sora.com 生成」。**写 Sora 相关内容前先实测确认 ChatGPT 里当前的视频能力。**
- 提示词站的流量和模型发布周期强绑定：GPT-4o 生图 2025-03 → Nano Banana 2025-08 → Nano Banana Pro 2025-11 → gpt-image-2 2026-04。每次发布后的头几周，谁先出「案例大全」谁就吃到流量（gpt-image-2 头部 GitHub 仓库 7 周拿下约 1.6 万 star）。**运营上要有「新模型 72 小时冲刺」预案**（§15.3）。

## 4. 信息架构与 URL

### 4.1 路由

```
/prompts                               提示词总览 hub（站方，Article）

/guides/456-chatgpt-memory-full        单篇教程

/apps                                  AI 应用与工作流
/apps/789-n8n-wechat-digest            应用分享 / 工作流
/apps/showcase                         产品自荐区（隔离）

/forum                                 讨论与问答（保留原路径）
/forum/1011                            讨论帖

/u/42                                  作者主页（ProfilePage）
/collections/12                        合集 / 系列教程
```

### 4.2 规则

- **id 主导**：路由只按 id 取数据。slug 不一致（或缺失）时 301 到规范地址。slug 只允许 ASCII（`[a-z0-9-]`），由编辑在精选时填写，作者可选填，不自动生成拼音（拼音 slug 质量差，还容易撞车）。
- **老链接**：`/forum/{id}` 中被迁成提示词、教程、应用的帖子，301 到新地址；保留为讨论的维持原 URL。
- **类型前缀用 `/m/` `/t/` `/p/`**，是为了让 `/prompts/123-...` 和 hub 在路由层不冲突，也方便 robots 规则按段处理。
- **站内搜索** `/search?q=` 和所有排序、筛选参数（`?sort=`、`?model=` 组合）一律 `noindex` + robots 屏蔽（百度劲风算法明确打击「站内搜索结果生成的页面」）。
- **分页** 用 `?page=n`，每页 canonical 指向自己，同时输出 `<a href>` 分页链接（无限滚动只作为增强）。
- **canonical 不写进带子路由的 layout**（交接文档 §28 第 ④ 条的教训），每个 page 自己写。

### 4.3 导航

- 顶部导航：「社区」改名为 **「AI 灵感库」**（名称待定，§18-1），下拉为 提示词 / 教程 / 应用 / 讨论。
- 首页加一块「本周精选」（服务端直出，最多 6 条），给新内容导入站内权重。
- 商品详情页和 `/chongzhi` 落地页加「相关教程与提示词」模块（§11.6）。

## 5. 内容类型与模板

所有类型共用一张主表（沿用 `ForumPost`，只加列），类型特有字段放附表。

### 5.1 提示词 `PROMPT`

PromptHero、GitHub 爆款仓库和即梦三家的结构合起来：

| 字段 | 必填 | 说明 |
|---|---|---|
| 标题 | ✓ | 例：「复古港风证件照（换背景色）」 |
| 模型 + 版本 | ✓ | 下拉选择：gpt-image-2 / nano-banana-pro / seedance-2 / jimeng-x / midjourney-7 / 其他（填写） |
| 提示词全文 | ✓ | 代码块展示；`[变量]` 自动高亮，例如 `[你的照片]`、`[背景色]` |
| 变量说明 | | 每个变量一行：替换成什么 |
| 是否需要参考图 | ✓ | 是 / 否；需要的话写清「上传几张、什么样的图」 |
| 参数 | | 画幅比例、质量档位、seed、风格码（`--sref` 等） |
| 负面提示词 | | 主要给 SD 和 MJ |
| **出图 / 视频** | ✓ | 至少 1 张作者**自己生成**的结果，最多 9 张；可以放「输入图 → 输出图」对比 |
| 使用场景 | ✓ | 一两句：适合做什么 |
| 心得 / 踩坑 | | 失败率、怎么调；这是让页面「不薄」的关键段落 |
| 生成日期 + 账号类型 | ✓ | Free / Plus / Pro；模型在变，日期就是可信度 |
| 来源 | ✓ | 原创 / 改编自（填链接和原作者）/ 转载（见 §6） |
| 同款自 | | 选站内某条提示词，形成二创链（§7.4） |

**详情页布局**（PromptHero 加 GitHub 仓库的写法）：
1. 首屏：效果图（大图，`<img>`，带「AI 生成」角标）
2. 提示词代码块，旁边是【复制】和【去 ChatGPT 生成】两个按钮
3. 变量说明、参数
4. 心得
5. 作者卡片
6. 三组内链：「作者的更多提示词」「同主题、其他模型」「同模型、相关主题」
7. 二创墙
8. 评论

### 5.2 教程 `GUIDE`

| 字段 | 必填 | 说明 |
|---|---|---|
| 标题 | ✓ | 用实测问句，例如「ChatGPT 记忆已满怎么办：清理、导出与迁移」 |
| 适用产品 + 账号类型 | ✓ | ChatGPT Plus / Claude Pro / …… |
| 测试日期 | ✓ | 页面上显示「2026-10 实测」 |
| 正文 | ✓ | Markdown，**支持表格**（P1 补）；可以插截图 |
| 摘要 | ✓ | 120 字以内，作为 meta description 和列表摘要 |
| 所属合集 | | 系列教程（小红书合集 / 掘金专栏的形态） |

模板引导（编辑器里给出段落占位，不强制）：「适用于谁 → 结论先说 → 步骤（截图）→ 常见问题 → 更新记录」。

### 5.3 应用 / 工作流 `APP`

ai-bot.cn 的模板，但把重心从「介绍工具」换成「我怎么用」：

- 名称、官网、价格、是否需要翻墙或海外账号
- **我用它解决了什么**（必填，至少 200 字）
- 步骤或工作流截图（n8n / dify / coze 的流程图可以直接贴）
- 优缺点、同类对比（表格）
- 可选：导入文件（例如 n8n 的 JSON，作为附件下载，P2）

### 5.4 产品自荐 `SHOWCASE`

见 §9。字段：产品名、一句话、试用方式（必填）、开发故事 / 技术选型 / 数据（必填其一）、与作者的利益关系（必选）。

### 5.5 讨论 / 问答 `DISCUSSION` / `QUESTION`

即现有论坛帖子。问答型帖子可以「采纳最佳答案」（P2）。

### 5.6 站方文章

hub 页、精选周报、新模型「案例大全」由站方撰写。和用户内容的区别在两处：
- 结构化数据用 `Article`，用户内容用 `DiscussionForumPosting`；Google 明确规定这两者不能混用；
- 作者显示为站方编辑的真实署名，并有对应的作者页。

## 6. 原创体系

本平台「主打原创」的落点，按发帖到展示的顺序：

### 6.1 发帖时：原创声明（必填，三选一）

| 声明 | 能否进精选、拿激励 | 搜索引擎 | 页面标识 |
|---|---|---|---|
| **原创首发**（本站最先发布） | ✓ | 达到门槛后收录 | 「原创首发」徽章 + 首发时间戳 |
| **原创，已在别处发布**（附原文链接） | 能进合集，不拿首发激励 | **noindex** | 「原创 · 首发于 xx」 |
| **转载 / 改编**（附来源 + 原作者 + 是否获得授权） | ✗ | **noindex** | 「转载」+ 来源链接 |

- 为什么非首发要 noindex：Google 自 2023 年起对转载的建议就是「转载方 noindex」，不再推荐跨域 canonical；而且非首发版本几乎不可能排过原文所在的大平台。
- 给作者的宽限沿用少数派规则：**发到本站之前 7 天内在个人公众号、博客发过，且没拿过第三方报酬，仍算首发。**
- 作者把本站首发的内容转发到外站时，发布成功页提示他「注明首发于贝果并回链」，并给出一段可复制的署名文字。

### 6.2 提交时：自动查重

- **SimHash**：保存时对正文（提示词类对 prompt 全文）算 64 位 SimHash，分 4 段各 16 位存入索引列；任一段相同就做候选，海明距离 ≤3 视为近重复。MySQL 加 4 个索引列即可，不需要额外服务。
- 命中站内已有内容 → 提示作者「与 #123 高度相似」，作者可以改成「同款自 #123」（变成二创），或者转人工复核。
- 站外搬运检测（P2）：抽 2~3 个长句去搜索引擎精确查找，命中就标「疑似转载」进入复核。只做提醒，最终靠人工和举报。
- 图片去重：上传时存 sha256，同一张图被不同账号重复发布时提示。感知哈希（pHash）留到 P3。

### 6.3 AI 辅助披露（必填）

- 「正文是否使用 AI 辅助撰写：否 / 部分（润色、翻译、整理）/ 主要由 AI 生成」。
- **「主要由 AI 生成」的正文不进精选、不收录**。Medium、dev.to 都是这么做的；本站还有资讯模块的历史风险，更要这样。
- 提示词的出图本来就是 AI 生成，不受这条限制。受限的是「文字是不是 AI 写的」。

### 6.4 「实测可用」徽章（PromptBase Verified 的做法）

编辑或 L3 共建者照着提示词复现成功后，点「实测可用」，记录复现日期和模型版本。模型更新后，可以批量标「待复测」。这是本站和 GitHub 搬运站拉开差距的地方，也是 AI 搜索最喜欢引用的「第一手证据」。

### 6.5 署名与授权

- **版权归作者**。发布即授予本站非独家展示授权（写进发帖协议，参照 WaytoAGI 的教训：商业站要更明确，免得用户觉得在「给卖家打工」）。
- 提示词默认许可 **CC BY 4.0**（GitHub 爆款仓库通行）：别人可以用，但要署名。作者可以改成「保留所有权利」。
- 页面输出图片版权元数据：`creator`、`creditText`、`license`（Google 图片的「可授权」标记）。

### 6.6 图片水印与元数据

- 上传时一律**去掉 EXIF**（隐私：GPS、设备信息），转成 WebP，长边不超过 2048px。
- AI 图写入 XMP / IPTC `DigitalSourceType = TrainedAlgorithmicMedia`（同时满足国内标识办法的隐式标识和 Google 的要求），页面角标「AI 生成」（显式标识）。
- 可见水印默认**不加**（会破坏「效果图」的展示价值）。只在列表缩略图右下角放很淡的站名，降低被整图搬运的价值。待定（§18-7）。

## 7. 发现与分发

### 7.1 排序

| 视图 | 规则 |
|---|---|
| **精选**（默认首页） | 编辑手选，按精选时间倒序 |
| **最新** | 只显示已过审内容，按发布时间 |
| **热门** | `hot = (复制×3 + 同款×5 + 收藏×2 + 赞 + 评论×2) / (发布小时数 + 2)^1.5` |
| **榜单** | 周榜 / 月榜，按同一套权重的累计值 |

热门不按浏览量算，而是给「被复制」「被同款」加权。这是 Sora 公开 feed 原则的取法：奖励「被拿去用」，而不是「被看到」。复制按「同一访客、同一条内容、24 小时」去重计数，沿用 `views` 的去重思路，但写进带唯一约束的表，不再是裸计数。

### 7.2 精选流程（少数派漏斗）

```
作者提交 ─▶ 待审（L0/L1）或直接发布（L2+，先发后审）
           │
           ├─ 驳回：附具体原因模板（退回修改，不直接删）
           ├─ 通过：出现在「最新」，满足 §11.1 门槛就可被收录
           └─ 通过 + 精选：进首页、周报、hub；作者 +积分；进 sitemap 第一梯队
```

- **公开审核时效**（人人都是产品经理的做法）：「工作日 24 小时内处理」。
- **公开精选标准**：有自己的出图或实测截图；有独立的心得或步骤；能直接复用；标题说清楚是什么。
- **公开不收什么**：软文、新闻稿、纯链接清单、AI 生成的长文、越狱和擦边、接码账号类。

### 7.3 Hub 页与专题（站方写）

- 每个模型 hub（如 `/prompts/m/gpt-image-2`）= 站方写的 400~800 字介绍（模型是什么、怎么用、Free 和 Plus 有什么区别、更新时间）+ 精选条目 + 最新条目 + 主题入口。**hub 页是本平台冲「X 提示词大全」这类头部词的主力。**
- 主题聚合页（如「证件照」）在可收录条目 ≥8 条、且有一段站方介绍之后，才去掉 noindex（劲风算法：空短聚合页违规）。
- 新模型发布时开「案例大全」专题页（§15.3）。

### 7.4 同款与二创链（Civitai Remix Gallery 的简化版）

- 发提示词时可以选「同款自 #123」，二创作品出现在原作的「二创墙」上。
- 原作者可以置顶 4 条，也可以隐藏不想展示的（只是从墙上隐藏，不删除二创者的内容）。
- 被同款计入原作的热度和原作者积分。这就是「署名链」：原作者因为别人的使用而受益，抄袭的动机被转成「标注同款」。
- 不做 Civitai 那套「付费投稿到画廊」，小平台用不上。

### 7.5 合集与系列

- 作者可以把自己的内容编成合集（如「gpt-image-2 电商主图 12 式」「Claude Code 从零到一 7 讲」）。合集页有自己的 URL 和介绍。
- 关注合集的用户在更新时收到站内通知（P2）。

### 7.6 站外分发

| 渠道 | 做法 | 期 |
|---|---|---|
| **每周精选邮件** | 复用营销邮件模块（站长已定：opt-out 默认可发、随时退订、CAS 防重发），每周一封，5~8 条精选 | P2 |
| **微信公众号** | 复用 `bigo-wechat` 流水线，把精选生成草稿到草稿箱（企业主体未认证，只能人工发布）。**草稿保持「首发于贝果」并回链** | P3 |
| **GitHub awesome 仓库** | 开一个中英双语的「awesome-gpt-image-2-prompts-zh」，每条只放缩略图 + 一句话 + 链回详情页，积累外链和 star（EvoLinkAI、YouMind 的打法）。**不在仓库里放完整内容**，否则仓库会排在本站前面 | P3 |
| **微信机器人** | 站长通过 iLink 机器人查「待审核内容数 / 今日新内容」（加进 AGENT_COMMANDS 只读白名单） | P1 |

## 8. 创作者体系

### 8.1 信任等级（Google「新用户帖先 noindex」的官方建议 + 简化版掘力值）

| 等级 | 怎么达到 | 权限 |
|---|---|---|
| **L0 新人** | 注册即是 | 发帖**先审后发**；外链显示为纯文本（不可点）；不能发自荐；每日发帖上限按现有限流 |
| **L1 成员** | 有 1 条内容过审，注册满 7 天，无违规 | 外链可点击（`ugc nofollow`）；评论先发后审 |

- 等级**只升不降**，违规除外（掘金规则）。
- 被驳回不扣分，被举报核实才扣。**对新人宽容**（Stack Overflow 的教训）。

### 8.2 积分

|---|---|---|
| 内容过审 | +5 | 每日 3 次 |
| 被精选 | +50 | — |
| 被收藏 | +2 | 每条内容每日 20 |
| 被复制（去重） | +1 | 每条内容每日 20 |
| 被同款 | +10 | — |
| 回答被采纳 | +20 | — |
| 打「实测可用」（L3） | +5 | 每日 10 |
| 违规（核实） | −50 / −200 | — |

积分写流水表（参照 `BalanceLog` 的做法），不在用户表上直接加减。

### 8.3 激励（从荣誉到钱，逐级打开）

| 阶段 | 激励 | 说明 |
|---|---|---|
| P1 起 | 署名、精选徽章、首页曝光、周报曝光、共建者墙 | 零成本。WaytoAGI 证明了荣誉对早期贡献者有效 |
| P2 起 | **积分兑换优惠券**（复用现有优惠券模块） | 只能在本站消费，薅羊毛的价值低 |

## 9. 产品自荐（「每个客户宣传自己的产品」）

站长明确想要这个场景。调研结论是：**给出口，但要有围栏。** 只堵会把推广挤进其他板块；不设围栏，会滑向 Google 的「站点声誉滥用」和百度的细雨算法（B2B 低质软文）。

### 9.1 四件套（V2EX + Reddit + Show HN + dev.to）

1. **隔离**：只能发在 `/apps/showcase`。其他板块出现推广内容就移区，屡犯降级。
2. **披露**：必选「我是作者 / 我在该公司工作 / 我有其他利益关系」。页面顶部显示「作者自荐」标签。
3. **必须可试用、必须有干货**（Show HN）：要提供免费试用或演示链接，另加「开发故事 / 技术选型 / 真实数据」至少一段。纯落地页、纯甩链接不收。
4. **比例与门槛**（Reddit 90/10 简化版）：L2 以上才能发；每月 1 条；新号首帖不能是自荐。

### 9.2 链接与收录

- 自荐区所有外链都加 `rel="sponsored"`（Google 对推广内容的明确要求，哪怕没收钱，从利益关系上也属于推广）。
- 自荐帖默认 **noindex**。被编辑精选、且内容本身有教程价值（真的教人怎么用 AI 做事）时，可以单独放开收录，但链接仍然是 sponsored。
- **禁止**：同行 AI 订阅代充、账号买卖、接码、「破限」类产品（默认禁止同行，§18-6）；联系方式（微信号、二维码）放进正文（细雨算法）。联系方式只放在作者主页的固定字段里。

### 9.3 付费推广位（P3，可选）

- 参考 V2EX PRO 和 dev.to Billboards：在列表页侧栏开一个明确标注「赞助」的位置，按周售卖，用支付宝付款（复用 VMQ 收银台）。
- 赞助**不影响**自然排序和精选，也不进周报正文（周报底部可以单独放一块赞助）。
- 价格参考：There's An AI For That 的 featured 收录 199 美元（含周报露出），本站流量小，起步定价要低得多。

## 10. 审核、安全与运维

### 10.1 发帖链路

```
提交 ─▶ 限流（已有）─▶ 敏感词 / 联系方式 / 外链检测 ─▶ SimHash 查重
     ─▶ 按等级：L0/L1 进待审队列；L2+ 直接发布，同时进「先发后审」抽查队列
     ─▶ 站长通知（企业微信 / 钉钉 webhook + 微信机器人「待办」）
```

- **关闭匿名发帖和匿名评论**（§18-2 默认）。内容平台需要署名和作者页，匿名内容无法积累信任；注册已经有邮箱验证码。
- 敏感词：本地词表（政治敏感、色情、赌博、诈骗常用语）+ 联系方式正则（微信号、QQ、手机号、二维码图片暂靠人工）。命中只是转人工，不直接拒绝。
- 图片审核：P0、P1 人工过目（审核页带缩略图墙）；量大以后再接阿里云内容安全（按量付费）。
- 举报：每条内容和评论都有「举报」，同一内容被 3 个不同的 L1 及以上用户举报，就自动隐藏并进队列。

### 10.2 后台

- `/admin/content`：待审队列（通过 / 驳回附原因 / 通过并精选 / 编辑 slug 和标签）、举报队列、全部内容、评论管理（现在评论只能硬删，`status` 字段从来没用过）、标签管理、hub 页编辑、积分流水、等级调整。
- **所有管理操作走 `/api/admin/content/*` 并经过 `adminGuard`**，不再复用公开接口（修掉 §1.1 的缺口①）。

### 10.3 删除与隐藏

| 情况 | HTTP | 说明 |
|---|---|---|
| 作者删除 / 违规删除 | **410** | 软删除（`deletedAt`），页面返回 410，推送 IndexNow |
| 合并到另一条 | 301 | |
| 临时隐藏（待复核） | 200 + noindex | 不要给 410，复核后可能恢复 |
| 改 slug | 301 | |

### 10.4 存储（重要的工程约束）

- 现在：上传放在本机 volume，全站合计 1.5GB，还和友链、品牌图共用。提示词平台以图片为主，一条 3~9 张图，**几百条之后就会顶到配额**。
- 图片：P1 上传时压缩成 WebP、长边 ≤2048（单张约 200~400KB）。这能撑过 P1、P2 的量级。
- 视频：**不放本机**。默认方案（§18-4）：
  - P1 只支持外链嵌入（B 站、YouTube），用 `embedUrl` 也能满足 VideoObject 的要求；
  - P3 再接对象存储：域名已经在 Cloudflare，R2 免出口流量费、有 10GB 免费额度，限单个视频 ≤30 秒、≤20MB。
- 图片处理需要新增 `sharp` 依赖。要先在服务器构建环境评估内存：本机构建现在必 OOM，服务器构建堆有上限。备选是浏览器端压缩（`canvas` 转 WebP 后再上传），服务端只校验。

## 11. SEO 技术方案

### 11.1 收录闸门（核心）

每条内容有一个计算出来的 `indexable` 布尔值，**页面的 robots meta、是否进 sitemap、是否推 IndexNow，三处共用同一个函数**（照 `shouldNoindexEvent` 的做法，避免两份实现漂移）：

```
indexable =
     status = 已发布 且 未删除
  && 审核状态 = 通过（L2+ 先发后审：发布满 24 小时且无举报，也视为通过）
  && 原创声明 = 原创首发
  && AI 辅助 ≠ 主要由 AI 生成
  && 类型不是自荐（自荐只有被精选才放开）
  && 质量门槛（按类型）：
       PROMPT     ：提示词 ≥ 20 字 且 ≥1 张自己的出图 且 已填模型 且（心得 ≥ 50 字 或 ≥2 张出图）
       GUIDE      ：正文 ≥ 600 字（不含代码块）且 有测试日期
       APP        ：「我用它解决了什么」≥ 200 字
       DISCUSSION ：正文 ≥ 300 字，或 有 ≥3 条他人的有效回复
       QUESTION   ：有被采纳的答案，或 有 ≥2 条回答
```

阈值是我们自己定的，不是官方数字。上线后按 Search Console 里的「已抓取未编入索引」比例调整。

**慢放量**：P1 上线时，只放开站方种子内容和首批精选（约 40~80 个 URL）进 sitemap。在 GSC 和必应后台观察 4 周，看收录率。收录率健康了，再让「过审即可收录」的规则生效。

### 11.2 服务端直出

- 详情页拆成 server component：在服务端直接用 Prisma 取数据并渲染 Markdown（现在的 `renderMarkdown` 是纯函数，可以直接在服务端调用），评论首屏 20 条也在服务端直出。点赞、收藏、复制、评论框是客户端小岛。
- 列表页和 hub 页同样服务端直出首屏，翻页用真实的 `<a href="?page=2">`。
- **未登录用户能看到完整正文、图片和提示词全文**。复制按钮不要求登录；收藏、评论、下载原图要求登录。百度明确把「登录才能看全文」算违规。

### 11.3 metadata

| 页面 | title 公式 | description |
|---|---|---|
| 提示词 | `{标题}：{模型}提示词（可复制）- 贝果` | 使用场景 + 是否需要参考图 + 模型 |
| 教程 | `{标题}（{YYYY-MM} 实测）- 贝果` | 摘要字段 |
| 模型 hub | `{模型} 提示词大全：{N} 条实测可复制案例（{YYYY年M月}更新）- 贝果` | 站方写 |
| 作者页 | `{昵称}的 AI 提示词与教程 - 贝果` | 作者简介 |

另外：
- `og:image` 用首图；
- 文章类输出 `article:published_time` 和 `article:modified_time`；
- `dateModified` 只在实质编辑或新增回复时更新，不做「改日期假装新鲜」；
- hub 标题里的「N 条」和「更新月份」从数据库实时算出来，**不写死**（交接文档里写死数字、后来对不上的坑踩过）。

| 页面 | 类型 | 要点 |
|---|---|---|
| 用户发的提示词、教程、讨论 | `DiscussionForumPosting` | `author.name` + `author.url`（→ `/u/{id}`）、`datePublished`、`text`、`image`、`comment`（按页面顺序嵌套）、`interactionStatistic` |

### 11.5 sitemap 与推送

- 拆成 `sitemap-prompts.xml`、`sitemap-guides.xml`、`sitemap-apps.xml`、`sitemap-hubs.xml`、`sitemap-users.xml`（只放有可收录内容的作者），再加 `image:image` 扩展。用 sitemap index 汇总。
- **只放 indexable 的 URL**；`lastmod` 取 `dateModified`。
- **IndexNow**（必应、Yandex 等）：内容过审、实质编辑、删除时都推送。同一 URL 至少间隔 5 分钟，用后台队列，失败不影响发布。
- 百度：用现有 `scripts/baidu-push.ts`，每日配额只有 10 条，只推精选。
- robots：主站对 OAI-SearchBot、PerplexityBot、Googlebot、Bingbot 维持放行（`src/app/robots.ts` 现有逻辑，主站放行、分站屏蔽，不用改）；新增屏蔽 `/search`、`/*?sort=`。

### 11.6 内链

- **商品页和 `/chongzhi` → 内容**：商品详情页和对应落地页加「相关教程与提示词」模块，服务端直出 3~6 条精选（按商品和模型、产品的映射表）。这是把商业页的权重导给新内容，也让商品页本身变厚（交接文档说商品页是全站最薄的一类）。
- **内容 → 商品**：只在相关处出现，例如 gpt-image-2 的提示词页写「Thinking 模式需要 Plus」，旁边是按钮。不在每页都硬塞。
- **内容 ↔ 内容**：§5.1 的三组相关推荐、合集、二创链、标签。
- **资讯 → 内容**：资讯详情页现有的「去论坛讨论」按钮，改成指向对应模型的 hub。

### 11.7 AI 搜索（GEO）

不额外做 llms.txt（Google 2026-07 的官方文档明说不使用）。能提高被 AI 引用概率的，是本方案本来就要求的东西：
- 带日期的实测；
- 同一提示词多模型对比的表格；
- 明确的数字（额度、价格、成功率）；
- 清晰的作者署名。

在模型 hub 页上维护一张「各模型能力与额度对比（{日期} 实测）」表，这类表格是 AI 回答里最常被引用的形态。

## 14. 分期路线

### P0 地基（约 1 周）——不上线新功能，先让现有论坛安全、可收录

1. 安全修复：同源校验、板块越权、`safeUrl`、images 校验、`rel="ugc"`（已开任务卡片，也可以并进来一起做）。
2. 关闭匿名发帖和匿名评论；L0 先审后发；后台待审队列（最小版）。
3. 加列（§12.1 的审核、原创、软删相关列）+ 老数据回填。
4. 详情页拆成服务端外壳：`generateMetadata`、canonical、DiscussionForumPosting、正文进 HTML。
5. 收录闸门函数 + robots meta 接上。**老论坛在 `seo/restructure` 上线后仍是整体 noindex，P0 不放开。**
6. 上传：去 EXIF、`MediaAsset` 表，压缩方案先定（sharp 或浏览器端）。

**验收**：`curl` 未登录访问 `/forum/1`，HTML 里有完整正文和独立 title；未审核帖返回 `noindex`；跨站 POST 到审核接口返回 403；匿名发帖返回 401。

### P1 MVP（约 2 周）——提示词库 + 教程

1. 类型、`PromptSpec`、发帖表单分类型；Markdown 支持表格。
2. 提示词详情页（§5.1 布局）、复制按钮（计数）、CTA 按钮（暂不带作者 ref）。
3. `/prompts`、`/guides` 列表 + 3 个模型 hub（gpt-image-2、nano-banana、seedance）+ 3 个产品 hub（chatgpt、claude、codex）。
4. `Tag`、`PostTag`；主题聚合页（带 ≥8 条才收录的门槛）。
5. 作者页 `/u/{id}`（ProfilePage）。
6. sitemap 拆分 + image sitemap + IndexNow 队列。
7. 后台：审核、精选、slug、hub 介绍编辑、「实测可用」。
8. 老 `/forum/{id}` → 新地址的 301。
9. 商品页、落地页的「相关教程与提示词」模块。
10. **同时进行**：站方种子内容 40 篇（§15.1），上线当天就有内容。

**验收**：40 篇种子内容全部服务端直出、indexable；hub 页数字和数据库一致；Rich Results Test 通过；IndexNow 返回 200/202；Lighthouse SEO ≥95；**手机端轻量模式下首帧可见**（`use-lite.ts`、`tailwind lite:`、`globals.css` 三处判定不改）。
