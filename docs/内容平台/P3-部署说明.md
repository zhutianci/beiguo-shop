### 作者内推返现（设计 §13.1）

- 内容页的「开通 / 续费」入口改为 `落地页?from=c{内容 id}`；作者满足以下全部条件时再加 `&ref={作者内推码}`：
  - L2 及以上：3 篇精选、积分 ≥300、共建者，或通过认证；
  - 已经开通内推码（「我的 → 推广返现」，打开即生成；这里不替作者生成，参加是作者自己的选择）；
  - 账号正常、不是管理员（站方内容不带 ref）；
  - 编辑没有对这一篇点「关闭作者返现」（内容页管理按钮，`forum_posts.cta_ref_off`）。
- 落地页 `/chongzhi/*` 新增 `RefCapture`：
  - **把 ref 存进 localStorage**（与商品页同一个 key）。以前落地页不记 ref，从落地页点进商品页时 ref 会丢；
  - 带 `from=c{id}` 的访问记一次「带来访问」（同一访客同一天一次）。作者在「我的投稿」里能看到。
- **钱的部分完全沿用现有内推**：商品页按推广人专属价成交，订单完成后 `settleReferral` 把返现记进可提现的返现格。内容平台这边不碰钱。
- **作者不能手写带 ref 的购买链接**：正文里指向本站的链接，渲染时 `ref` 参数会被剥掉（`lib/markdown.ts stripSiteRef`）。

## 三、改动到的既有模块（上线时留意）

- **优惠券后台**：来源筛选多了「积分兑换」（`source='POINTS'`），和抽奖券一样显示兑换人、只能作废。
- **钱包**：月度奖走 `adminAdjust`，流水类型 `ADJUST`，充值格；`check-tenant-boundary` 规则 16 通过（没有别处写余额）。
- **落地页 layout**（`/chongzhi/layout.tsx`）：只挂了一个不渲染内容的客户端组件，页面 HTML、metadata、canonical 都不变。
- **Markdown**：正文里本站链接的 ref 参数被去掉。站外链接、其他参数不受影响。

## 四、两个生成脚本怎么用

```bash
# GitHub awesome 仓库（站长决定仓库名和账号后，把生成的 README 推上去）
DATABASE_URL=... npx tsx scripts/build-awesome-repo.ts --out out/awesome-ai-prompts-zh
# 每条只放缩略图 + 标题 + 一句话 + 链接，不放提示词全文（设计 §7.6：放全文仓库会排在本站前面）

# 公众号稿件（之后在 bigo-wechat 里 npm run preview / npm run draft）
DATABASE_URL=... npx tsx scripts/content-to-wechat.ts --featured 3
DATABASE_URL=... npx tsx scripts/content-to-wechat.ts --ids 12,34
# 文首「首发于贝果 AI 学习」、文末原文链接、source_url = 原文（阅读原文）
# 微信只收 jpg / png：webp 图会被跳过，没有可用图时封面留空，draft 会提示补
```

两个脚本都只依赖 `@prisma/client`，读生产库时照 `db push` 的方式在临时容器里跑，或者本地连只读账号。

## 五、没做的（需要站长提供外部账号或决定）

- **视频托管（Cloudflare R2）**：要 R2 账号与密钥。目前视频仍只支持 B 站 / YouTube 嵌入。
- **站外搬运检测**：要搜索引擎 API（Bing Web Search API 已停）。站内的 SimHash 查重与图片查重已经有了。
- **赞助位在线购买**：目前站长手工录入；要做「按周售卖、支付宝付款」再接收银台。
- **「内容带来的订单」归因**：现在能看到带来访问；订单层面只有作者内推码能归因（走内推返现）。要统计不带 ref 的内容带单，需要在下单时记 `from`，涉及订单表与下单接口，单独做。
