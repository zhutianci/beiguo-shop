## 二、去重与筛选方法

- **排除已用原帖**：10-10 从库内 1480 个文件里（10-11 续做前对合并后的 1867 个文件又查了一遍，182 条待写候选无一命中）取出所有 `status/` 推文 ID（422 个）、YouMind 画廊 id（167 个）、`cms-assets.youmind.com/media/` 图片名和 seedream 条目锚点，候选池里命中任何一项的都剔除；同一推文同时出现在两个仓库的只留一条。
- **关键词初筛**：标题 / 描述 / 提示词里含品牌、知名 IP、名人、擦边词的条目整条剔除（词表沿用 i1 并扩充），得到约 1 万条候选；再按偏薄的主题（贴纸、Logo、证件照、老照片、漫画分镜、角色设定、室内建筑、穿搭、壁纸、PPT、电商）挑出 568 条下载示例图；10-11 续做时又按贴纸、Logo、穿搭、手办、室内、绘本、封面与卡片设计等关键词补挑了三轮共 100 条。
- **目检两遍**：第一遍把候选的首图拼成联系表用 Read 工具逐张看，568 条留下 293 条（10-11 补挑的 100 条留下 30 条）；第二遍起草时对准备收录的每一张图（已压成上线用的 JPEG）再用 Read 工具核对——单张打开，或拼成每格约 1000px 的 2×2 复核图——并核对"图与提示词对得上"。由子代理起草的批次，协调者把它们选用的图全部再看一遍，并剔除了一部分（见第六节"协调者复核"）。
- **查重**：起草前在现有标题里按关键词查同用途条目；生成时用与 `src/lib/content/simhash.ts` 逐位一致的 Python 实现（已用两段样例对照 tsx 输出验证）对中文 `prompt` 字段算 SimHash，与库内任何一条、与本批任何一条的海明距离都 >8 才写入。
- **示例图处理**：只用该条目自己的图；长边 ≤1200px、单张 ≤250KB 的 JPEG；成图在前、输入图在后，每条 1～3 张。除 3538（电商首页长图样机）裁掉了最底部约 5% 含虚构客服电话的服务栏外，未对图片内容做遮盖或裁切。

## 三、每条的处理方式

- 原提示词译为中文、可替换部分改成 `[变量]`；原文（英 / 日 / 中）完整保留在正文"原版"一节；`changes` 字段逐条写明改了什么（CC BY 要求）。
- `source.url`：有原帖的写原帖（X 或即梦作品页）；仓库没给原帖的写该条目所在 README 版本的固定链接（`blob/<commit>/README.md#no-…`）。`imageCredit.url`：YouMind 画廊条目链接；条目没有画廊 id 的写示例图原始地址。
- 作者：能从仓库记录的作者主页还原出 X 账号的写 `@handle`，即梦作品写"即梦用户 xxx"。
- nano-banana 条目原作者多用 Nano Banana Pro 生成，个别示例图右下角带 Gemini 的四角星标记（模型自带标记，i2 也保留了）。
