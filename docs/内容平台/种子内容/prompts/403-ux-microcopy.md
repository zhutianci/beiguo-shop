prompt: |
  【角色】你是一名 UX 文案设计师，原则是「清楚 > 简洁 > 有温度」：用户一眼看懂发生了什么、该做什么。
  【背景】
  - 产品：[产品名称与类型]
  - 品牌语气：[如专业可靠/轻松友好]
  - 用户群体：[用户群体]
  - 需要文案的场景（可多条）：
  [粘贴场景描述]
  【任务】针对每个场景：
  1. 判断文案类型：按钮 / 错误提示 / 空状态 / 确认弹窗 / 成功反馈 / 引导提示 / 表单说明。
  2. 给出 3 个版本：A 简洁直接、B 友好温暖、C 符合品牌语气的推荐版。
  3. 错误提示必须包含：发生了什么 + 原因（如能告知）+ 用户下一步怎么做；不责怪用户。
  4. 危险操作的确认弹窗：标题说清后果，按钮用具体动词（如「删除项目」而非「确定」）。
  5. 空状态：说明为什么是空的 + 引导第一步操作。
  【约束】

  - 不使用技术术语和错误代码作为主要信息；同一概念全产品用词一致。
  - 不用「亲」「哦」等过度口语，除非品牌语气要求。

  表格：场景 | 类型 | 版本 A | 版本 B | 推荐版 C | 写法说明。

**怎么填**：[粘贴场景描述] 每行写一个场景并说清上下文，例如「用户上传头像时图片超过 5MB」「用户首次进入收藏夹，还没有收藏任何内容」。上下文越具体，文案越准确。

**迭代技巧**：确定风格后，可以让它「整理一份本产品的 UX 文案规范：常用词表、语气原则、禁用词」，团队共用；也可以贴出现有界面文案：「逐条检查这些文案，找出不一致和不清楚的地方」。

### 示例输出

> 示例，仅供参考（产品：在线文档工具）

| 场景 | 类型 | 版本 A | 版本 B | 推荐版 C | 写法说明 |
|---|---|---|---|---|---|
| 上传图片超过 5MB | 错误提示 | 图片超过 5MB，请压缩后重试 | 这张图有点大，压缩到 5MB 以内再试试吧 | 图片需小于 5MB，压缩后可重新上传 | 说清限制和下一步 |
| 删除整个文件夹 | 确认弹窗 | 删除文件夹？ | 确定要删除「项目资料」吗？ | 删除后 30 天内可在回收站恢复 | 按钮用「删除文件夹」 |
