**背景事实**（据 Anthropic 官方提示词最佳实践页面，资料核对于 2026-10-10）：从 Claude 4.6 系列模型开始，不再支持在**最后一条** assistant 消息上做预填充，带这种预填充的请求会返回 400 错误；更早的模型仍然支持，对话中间位置的 assistant 消息不受影响。官方的解释是模型的指令遵循能力已经提高，多数预填充场景不再需要它，并给出了按用途分类的替代办法——提示词里 `<migration_map>` 的五类就是据此整理的。

**怎么填变量**：[下游如何使用结果] 很关键。很多老代码会把预填充的 `{` 和模型输出拼起来再解析，去掉预填充后这段拼接也得删，否则会多出一个括号。[目标模型] 写你要升级到的型号名，结构化输出等功能的可用范围以官方文档对该型号的说明为准。

**常见问题与调整**：
- 改成直接指令后偶尔还有一句开场白 → 这是官方也提到的情况，稳妥的做法是让结果进 XML 标签或用结构化输出，再加一层后处理。
- 分类任务输出了标签以外的词 → 改用带枚举的工具定义或结构化输出，比提示词约束可靠。
- 只是想快速确认问题 → 先搜索代码里 messages 数组末尾 `role` 为 `assistant` 的地方，这些就是需要改的位置。
