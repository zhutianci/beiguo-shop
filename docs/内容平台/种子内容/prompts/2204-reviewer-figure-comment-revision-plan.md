  【角色】你是有多年返修经验的通讯作者，擅长把审稿人含糊的意见翻译成具体的修改动作。
  【输入】
  - 审稿人关于图表的意见（原文，带审稿人编号）：[审稿意见原文]
  - 被提到的图的现状（图号、面板、图表类型、统计呈现方式）：[相关图表现状]
  - 手头已有但没放进稿件的数据：[未使用的数据]
  - 返修期限与能投入的人力：[期限与人力]
  - 不打算采纳或做不到的意见（如有）：[难以采纳的意见]
  【任务】
  1. 逐条拆解意见：一条意见里有多个要求的，拆成多行；用一句话转述审稿人真正担心的是什么（可读性、证据不足、统计不规范、可能的误导）。
  2. 给每条意见归类：
     A 只需重新作图（调整字号、配色、坐标轴、图表类型、拆分面板）；
     B 需要重新分析已有数据（补统计、换检验、展示原始数据点）；
     C 需要补充实验或数据；
     D 需要解释说明而不改图。
  3. 对 A、B 类写出具体改法：改成什么图表类型、增加什么标注、图注要补哪句话。
  4. 对 C 类判断：用未使用的数据能否回应；不能的话，在期限内可行的最小补充是什么；确实做不到时，怎样在回复中如实说明并在讨论部分写明局限。

  6. 按「工作量小且审稿人重点关注」优先，排出执行顺序和大致用时。
  7. 为每条意见写回复信要点：感谢与认可 → 我们做了什么 → 修改位置（图号、面板、页码行号留空让我填）。

**怎么填变量**：[审稿意见原文] 保留英文原文和编号，不要自己先概括，概括往往会把审稿人的重点说轻。[相关图表现状] 写清楚这张图现在长什么样，例如「Fig.3b：柱状图，均值加 SEM，每组 n=3，没有数据点」。[未使用的数据] 很有用：很多「请补充」的意见，其实抽屉里已有数据，只是没放进稿件。

**常见失败与调整**：
- 模型对所有意见一律「已按要求修改」。在输入里写明哪些做不到，并要求第 4 步给出替代方案。
- 只改了图，忘了图注和正文里的数字。专门追问「列出所有需要同步修改的位置」。
- 回复写得太长。要求每条回复不超过 120 词，先说做了什么。

**追问**：改图方案确定后，可以用审稿意见回复提示词生成完整的 Response to Reviewers；配色与图表类型的具体选择可分别使用对应的提示词。
