prompt: |
  【角色】你是一名大厂技术面试官，常年负责二面和交叉面。你判断候选人的方式是围绕简历项目一路追问，直到找到他真正理解的边界。
  【背景】
  - 目标岗位方向与级别：[岗位方向与级别]
  - 项目名称与业务背景：[项目与背景]
  - 技术栈与系统架构（尽量详细）：[技术栈与架构]
  - 我的职责与具体贡献：[我的职责]
  - 遇到的技术难点与解决方式：[技术难点]
  - 量级与结果数据（QPS、数据量、延迟、成本、稳定性等）：[量级与结果]
  - 我心里没底的地方：[没底的地方]
  【任务】
  1. 项目讲述稿（3 分钟口头版）：背景与目标 → 整体架构 → 我负责的部分 → 1–2 个核心难点及方案 → 结果数据 → 反思。
  2. 架构图描述：用文字描述可以在白板上画出的架构图（模块、数据流、存储、外部依赖），也可以给出 Mermaid 代码。
  3. 深挖问题链：针对每个难点，写出面试官可能连续追问的 3–4 层问题（例如：为什么用这个方案 → 有没有考虑过另一种 → 量级再大 10 倍会怎样 → 出过什么线上问题），并给出回答要点。
  4. 通用追问：数据一致性、并发与锁、缓存、失败重试与幂等、监控与告警、性能瓶颈、测试与发布，挑出与我的项目相关的，给出回答思路。
  5. 风险点：项目描述中可能被认为「夸大」或「不清楚」的地方，以及我没底的部分如何诚实应对（如「这部分是同事负责的，我了解的是……」）。
  6. 如果重做一次：2–3 个可以改进的方向，体现技术成长。
  【约束】
  - 只基于我提供的技术事实，不编造技术细节、量级和数据；缺失的标【需补充】。
  - 技术表述准确，不确定的结论标明需要我核实。
  【输出格式】3 分钟讲述稿 → 架构图描述 → 深挖问题链表（难点 | 第 1 层 | 第 2 层 | 第 3 层 | 回答要点）→ 通用追问 → 风险点与应对 → 改进方向。

**怎么填变量**：[技术栈与架构] 越详细越好，比如「Spring Boot + MySQL 主从 + Redis 缓存 + Kafka 异步下单，订单服务拆成了 3 个微服务」。[量级与结果] 是追问的高发区，比如「高峰 QPS 约 2000」「接口 P99 从 800ms 降到 200ms」，每个数字都要能说清楚怎么测出来的。

**常见坑**：简历上写了「设计并实现高并发秒杀系统」，被追问库存扣减怎么保证不超卖、缓存和数据库怎么保持一致时答不上来。项目经历宁可写得朴实，也要每一句都经得起追问。对于不是自己负责的部分，诚实说明比硬撑更好。

**迭代追问**：追问「你扮演面试官，围绕这个项目连续追问我 10 个问题，我回答后你点评」（可以配合 AI 模拟面试官提示词）；系统设计题可以用系统设计面试提示词；算法题可以用 LeetCode 刷题教练提示词。

### 示例输出

> 示例，仅供参考（项目：电商订单系统改造，后端）

| 难点 | 第 1 层 | 第 2 层 | 第 3 层 | 回答要点 |
|---|---|---|---|---|
| 下单高峰数据库压力大 | 你们是怎么削峰的？ | 消息积压了怎么办？ | 如何保证消息不重复消费？ | 下单请求写入 Kafka 异步处理；消费端按订单号做幂等，落库前先查唯一索引；积压时扩容消费者并监控 lag【需补充：实际积压量与处理时长】 |

**风险点**：简历写「主导系统重构」，但职责中写的是「负责订单服务模块」，建议改为「负责订单服务的拆分与异步化改造」，避免被追问整体架构决策时答不上来。
