prompt: |
  【角色】你是计算机与工程领域的资深论文作者，写相关工作的原则是：这一节的任务是给本文定位，而不是展示读过多少论文。
  【输入】
  - 本文要解决的问题与主要贡献（2–4 条）：[本文问题与贡献]
  - 文献笔记（每篇含：引用键、做了什么、核心方法、主要结论、与我的关系）：[文献笔记]
  - 投稿目标与篇幅限制：[投稿目标与篇幅]
  - 这一节放在引言之后还是结论之前：[章节位置]
  - 写作语言：[写作语言]
  【任务】
  1. 分组方案：提出 2–3 种把这些文献分成 3–5 组的方式（按技术路线、按要解决的子问题、按假设条件），说明哪一种最能衬托本文贡献，让我选；每篇文献放进哪组列成表，放不进任何组的单独列出并建议是否删去。
  2. 为选定方案的每一组写一段，结构为：
     - 主题句：这一类工作的共同思路；
     - 代表性工作：按思路的演进而不是发表时间串起来，每篇一句，写它推进了什么，句末放引用键；
     - 局限或未覆盖之处：这一类方法在什么条件下不适用（必须能从我的笔记里找到依据）；
     - 差异句：本文与这一类工作的具体区别（假设不同、设置不同、目标不同），不写「优于」这类需要实验支撑的结论。
  3. 检查与本文最接近的 1–3 篇工作是否被正面、具体地讨论了；如果我的笔记里对它们的描述太少，提醒我补充，否则审稿人会认为在回避。
  4. 表述检查：标出贬低性词语（如「简单地」「未能」「忽视了」）并给出中性改写；标出没有引用支撑的断言。
  5. 给出压缩版（约为完整版一半篇幅），以及可以合并进引言的两三句。
  6. 列出覆盖缺口：按分组看，哪一类工作只有一两篇、可能需要补查文献（只说应补哪一类，不要给出具体论文）。
  【约束】
  - 只引用我笔记里的文献，引用键原样保留；不新增任何文献、作者或年份。
  - 对他人工作的描述不超出我笔记的内容；笔记不足以支撑的句子标【需回原文确认】。
  - 不写本文实验结果，那属于实验部分。
  【输出格式】分组方案对比 → 文献分组表 → 各组段落 → 最接近工作的检查 → 表述问题与改写 → 压缩版 → 覆盖缺口。

**怎么填变量**：[文献笔记] 每篇三四行就够，但「与我的关系」一定要写，例如「和我们一样做长文档检索，但假设文档已经分好段」。差异句的质量取决于这一栏。引用键用你的 BibTeX 键（如 zhang2024retrieval），模型原样保留，粘回 LaTeX 即可。[本文问题与贡献] 直接复制引言末尾的贡献列表。

**常见失败与调整**：
- 输出变成「A 提出了……B 提出了……C 提出了……」的流水账。回到第 1 步重选分组方式，并要求每段先写主题句。
- 差异句写成「与上述方法不同，我们的方法更高效」。「更高效」需要实验证明，改写为设置或假设上的区别。
- 模型为了让段落丰满，添了你没给的「代表性工作」。这些引用很可能是编造的，对照引用键逐一检查。

**追问**：「审稿人可能认为本文与 [某引用键] 太相似，请写一段更细的对比」「把这一节改写成中文学位论文的国内外研究现状口吻」。

Building on this idea, \cite{chen2024outline} further uses the table of contents as a routing index. These approaches assume that reliable structural markup is available 【需回原文确认：chen2024outline 是否讨论了无目录文档】.
