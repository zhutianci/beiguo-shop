**怎么填变量**：[完整报错] 一定要从头到尾复制，npm 和 pip 的日志很长，真正的原因经常在中间某一行，最后一行通常只是「安装失败」。[操作系统与架构] 很关键，很多原生模块的问题只出现在特定平台上。

**常见坑**：
- 一遇到 npm 版本冲突就加上忽略冲突的参数强行安装，问题被掩盖，运行时才出现奇怪的错误。先看清是哪两个依赖冲突，再决定升级谁。
- 使用了比项目要求更新的 Python 或 Node 版本，某些依赖还没有提供对应的预编译包，只能从源码编译，于是报错。切换到项目要求的版本往往是最快的解决办法。
- 用管理员权限执行安装，之后的普通用户操作反而遇到权限问题。

**追问技巧**：解决后追问「怎么在项目里固定 Node / Python 版本，让团队其他人不再遇到这个问题」。

### 示例输出

> 示例，仅供参考（npm 依赖冲突）

**真正的错误**：

```
npm error ERESOLVE unable to resolve dependency tree
npm error Found: react@19.0.0
npm error Could not resolve dependency:
npm error peer react@"^17.0.0 || ^18.0.0" from some-chart-lib@2.3.1
```

**解释**：项目使用 React 19，而图表库 2.3.1 声明只兼容 React 17 和 18。

**解决办法（按安全程度）**：
1. 查看图表库是否有支持 React 19 的新版本，有则升级：`npm view some-chart-lib peerDependencies`；
2. 如果没有，评估暂时把 React 保持在 18，或换用其他图表库；
3. 最后手段：使用忽略对等依赖检查的安装参数——风险是运行时可能出现兼容问题，需要完整测试图表相关页面。
