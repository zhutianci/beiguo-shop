  ### 角色
  用户增长产品经理。你做推荐机制的原则：只有当老用户真心觉得「这个值得推荐给朋友」时，裂变才能持续；奖励是加速器，不是发动机。

  ### 输入
  - 产品与核心价值：[产品与价值]
  - 老用户为什么会推荐（最常见的推荐场景）：[推荐场景]
  - 新用户的获客成本参考：[获客成本]
  - 可用的奖励资源：[奖励资源]
  - 主要分享渠道：[分享渠道]
  - 活动周期：[活动周期]

  ### 请设计
  1. 机制选择：比较「双向奖励（邀请人和被邀请人都得）」「阶梯奖励（邀请越多奖励越高）」「组队 / 拼团」三种机制在我的业务下的适用性，推荐一种。
  2. 奖励结构：邀请人与被邀请人各得什么、什么条件下发放（建议以被邀请人完成首次真实使用或首单为准，而不是注册即发），单人奖励上限；用我给的获客成本检验奖励是否算得过账。
  3. 用户路径：从老用户看到入口 → 生成邀请 → 朋友收到 → 朋友完成条件 → 双方收到奖励，每一步的页面或消息要点，以及各环节的文案。
  4. 分享内容：给 3 个分享话术，让用户能用自己的口吻发出去，而不是硬广截图。
  5. 防作弊规则：同设备 / 同支付账户 / 同收货地址识别、奖励延迟发放、异常订单回收奖励等。
  6. 合规检查：
     - 不做「转发 X 个群才能领取」「不分享就无法使用」这类诱导或强制分享；
     - 不设置多层级返佣（只奖励直接邀请关系），避免涉嫌传销式分销；
     - 遵守分享渠道的平台规则（如微信对诱导分享的限制）；
     - 活动规则清楚公示。
  7. 指标：参与率、人均邀请数、被邀请用户 30 日留存、单个新客成本，并与其他渠道对比。

**怎么填变量**：[推荐场景] 决定了邀请入口放在哪里——例如用户刚完成一次满意的服务后，比在「我的」页面角落里更容易分享。[获客成本] 用来算账：单个新客的奖励成本加上被邀请人的留存情况，应该比投放获客更划算。

**常见坑**：
- 注册即发奖励，很快被批量注册的小号薅光，奖励要和真实使用挂钩；
- 设计「邀请好友的好友也算你的」，这是多级返佣，存在法律风险；
- 只看邀请人数，不看被邀请用户的留存，拉来一堆只为领奖励的用户。

**迭代追问**：「为这个活动写完整的规则页文案」「设计 3 种邀请卡片的文字和画面描述」「活动上线两周后邀请率很低，帮我列出排查清单」。

### 示例输出

> 示例，仅供参考（虚构：家政保洁 App）

**推荐机制**：双向奖励。老用户邀请朋友，朋友完成首次保洁服务（不少于 2 小时、未退款）后，双方各得一张 30 元服务券；每位用户每月最多获得 5 张。

**分享话术（节选）**：「我家每两周约一次保洁，阿姨挺细心的。你第一次用可以领 30 元券，我们俩都有。」

**防作弊**：被邀请人与邀请人的手机设备、服务地址相同时不发放奖励；奖励在服务完成 7 天后发放。
