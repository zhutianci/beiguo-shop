     - 这些操作失败或结果不确定时，禁止直接重试，必须先查询是否已经生效；

**怎么填变量**：[报错示例] 直接贴工具返回给模型的原文，哪怕只是一行「Error: 400」，这正是要改进的对象。[不可重复的操作] 要认真列，凡是「执行两次会多扣一次钱、多发一条消息、多建一条记录」的都算。[程序层重试情况] 很多 SDK 自带重试，如果不说明，模型设计的规则可能与它叠加。

**常见失败与调整**：
- 报错只返回「失败」两个字，模型只能瞎猜。按第 4 步改写，尤其要告诉它「能不能重试」和「下一步建议」。
- 写操作超时后模型立刻重发，结果创建了两条记录。把这类操作归入结果不确定，规定先查询。
- 工具失败后，模型在回复里写得好像成功了一样。把「不得编造工具结果」写进规则，并在测试场景里专门验证。

**追问**：「把处理规则表改成我可以直接实现的中间件逻辑说明」「这些工具里哪几个最值得先加幂等标识，按风险排序」。工具本身的名称、参数和说明怎么写，可以参考站内的工具定义提示词。

> 示例，仅供参考（虚构：能查询与创建工单、发送通知的智能体）

| 错误类别 | 识别特征 | 谁处理 | 次数与动作 | 放弃条件 |
