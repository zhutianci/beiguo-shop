**怎么用**：先用「提取」模式跑原文，人工审一遍术语表（这一步不能省），再把确认后的术语表放到翻译提示词里（例如本站的中英互译保风格、字幕翻译提示词都有术语栏）。翻译完成后，用「质检」模式把术语表和原文、译文一起交给模型检查。

**怎么填变量**：[已有术语要求] 很重要，比如客户要求「Workspace 统一译为工作空间，不译为工作区」，写进去后模型会优先遵守。[领域] 写细一点：「云计算 / 数据库」比「IT」得到的译名更准。

**常见坑**：
- 模型会把普通词也收进来，表格变得很长——让它「只保留在全文出现 2 次以上或有歧义的条目」；
- 产品界面译名一定要以对方软件的实际中文界面为准，模型不知道最新版本的菜单名；
- 原文很长时分段提取，最后让模型「合并去重这几张术语表」。

**迭代追问**：「把术语表按类别排序，并给每条打上优先级：必须统一 / 建议统一」「给出这份术语表的英文版说明，发给海外同事确认」。

### 示例输出

> 示例，仅供参考（英译中，SaaS 产品帮助文档）

```
源术语,目标译法,类别,变体,词性,原文例句,备注
workspace,工作空间,N,"Workspace, workspaces",n.,Invite members to your workspace.,客户指定，不译为「工作区」
rate limit,速率限制,T,rate limits,n.,Requests above the rate limit return 429.,
Settings,设置,U,,n.,Go to Settings > Billing.,与软件界面一致
API key,API 密钥,T,API keys,n.,Keep your API key secret.,API 不译
```
