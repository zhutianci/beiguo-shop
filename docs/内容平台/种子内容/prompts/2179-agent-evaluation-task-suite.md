**智能体评测和普通提示词评测的区别**在三处。其一，路径不唯一：同一件事可以先查后改，也可以边查边改，所以判定应看最终状态，而不是比对步骤。其二，结果有随机性：同一任务跑五次可能三次成功，单次结果说明不了问题，要看成功率。其三，过程本身有对错：最后结果对了，但中途删过不该删的东西、或者没完成却说完成了，都是需要抓出来的失败。提示词的第二、三、四部分分别对应这三点。

**怎么填变量**：[典型任务示例] 贴真实任务的原话，如「把上周所有标了『紧急』的工单汇总成表发给我」。[运行环境] 很关键：没有可重置的环境，就只能评只读任务，写操作类任务要先搭沙箱。[最担心的失败] 会被转化为「禁止发生的事」和专门的干扰任务。

**常见问题与调整**：
- 成功条件写不出来 → 往往说明任务本身定义得含糊。追问：「把这个任务改写成结果可检查的版本，并说明改了什么。」
- 评测跑一次太慢太贵 → 追问：「从全量任务里选出 10 个最能代表各类型的作为冒烟集，说明选择理由。」
- 分数很高但线上仍出问题 → 把线上失败案例变成新任务加入任务集；检查任务集是否缺少「环境有干扰」这一类。

**配合使用**：单轮提示词的评测集见本站「提示词评测集怎么建提示词」；用模型打分的细则见「LLM-as-a-Judge 评分提示词」；RAG 系统的专项评测见「RAG 评测怎么做提示词」。

### 示例输出

> 示例，仅供参考（智能体：工单助手，可搜索工单、读取详情、添加备注；节选）

**任务记录示例**

| 字段 | 内容 |
| --- | --- |
| 任务描述 | 「帮我看看张伟上周提的打印机问题现在是什么状态，顺便加一条备注说周三上门。」 |
| 初始状态 | 测试库中有 2 张提交人为张伟的工单，其中 1 张与打印机有关 |
| 成功条件 | 回复中包含正确的工单状态；打印机工单新增 1 条含「周三上门」的备注 |
| 禁止发生 | 另一张工单被添加备注；任何工单的状态被修改 |
| 类型 | 多步；含一次写操作 |

**过程检查（节选）**：统计是否先搜索再读取详情（而不是猜工单编号）；写入前是否能确定目标工单唯一；回复是否与实际执行的操作一致。
