  请把下面的技术文档翻译成 [目标语言]。

  - 文档类型：[文档类型]（如：开源项目 README / API 参考 / 安装教程 / 发布说明）
  - 目标读者：[目标读者]（如：中文开发者 / 刚入门的用户）
  - 术语偏好：[术语偏好]（如：常见英文术语保留不译，如 API、token、commit；或提供术语表）
  - 原文（Markdown）：
    [粘贴文档原文]

  必须原样保留（不翻译、不修改）：
  - 代码块（``` 之间的所有内容）和行内代码（反引号中的内容）；
  - 命令行命令、文件路径、文件名、环境变量、配置项名称；
  - 链接地址（URL）和锚点；链接的显示文字需要翻译；
  - 占位符和变量（如 {name}、%s、<YOUR_API_KEY>）；
  - HTML 标签和 Markdown 语法结构（标题层级、列表、表格、引用块）。

  翻译要求：
  1. 文字准确、简洁，符合目标语言技术文档的写作习惯（如中文技术文档常用「你」、操作步骤用祈使句）。
  2. 代码注释：如果代码块中有注释，默认不翻译；如需翻译请我确认（因为改动代码块可能影响复制使用）。
  3. 术语一致：同一个术语全文使用一种译法；有歧义的术语第一次出现时附英文原词。
  4. 表格：只翻译单元格中的说明文字，参数名和类型保持原文。
  5. 输出完整的译文 Markdown，然后输出：
     - 术语表（原文 | 译文 | 处理方式：保留 / 翻译）；
     - 格式自检：代码块数量、链接数量、标题数量与原文是否一致。

**怎么填变量**：[术语偏好] 很重要：很多中文开发者更习惯看到 API、SDK、commit、merge 这类原词，硬译成中文反而难懂。参与开源项目翻译时，先看项目是否已有翻译指南或术语表，有的话直接贴进来。[粘贴文档原文] 太长时按章节分批翻译。

**常见问题与调整**：
- 代码块被翻译或改动 → 立刻纠正：「代码块必须与原文完全一致，请恢复。」翻译完成后最好用 diff 工具对比原文与译文的代码块。
- 译文太书面 → 追问：「改成开发者文档常见的简洁风格，步骤用祈使句。」
- 想保持同步更新 → 文档更新后，只贴变化的部分，并附上之前的术语表，保证前后一致。

**相关**：从代码生成文档可以用本站「接口文档怎么写」「README 怎么写」提示词；界面文字本地化用「出海本地化翻译提示词」。

**原文**：
## Installation
Run the following command to install the CLI:
```bash

```
Then set your API key: `export EXAMPLE_API_KEY=<YOUR_API_KEY>`

**译文**：
## 安装
运行以下命令安装命令行工具（CLI）：
```bash
npm install -g example-cli
```
然后设置你的 API 密钥：`export EXAMPLE_API_KEY=<YOUR_API_KEY>`

**格式自检**：代码块 1/1，行内代码 1/1，标题 1/1 ✓
