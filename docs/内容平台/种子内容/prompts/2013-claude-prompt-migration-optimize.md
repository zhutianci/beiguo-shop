useCase: 以前给旧模型或别家模型写的提示词，搬到新版 Claude 上出现「执行过头」「太听话太死板」「工具调用过于频繁」等情况时用：让 Claude 按官方迁移建议逐条审查你的旧提示词，标出问题句、给出改写和理由，并输出一份完整的新版本。
prompt: |
  下面是一份为较早的模型写的提示词，我要把它用在新版 Claude 上。请你按「审查规则」逐句检查并改写。

  <old_prompt>
  [粘贴旧提示词]
  </old_prompt>

  这份提示词的用途：[用途]
  在新版 Claude 上观察到的问题（没有可以写「尚未测试」）：[观察到的问题]

  <review_rules>
  1. 过度强调：全大写、「必须」「绝对」「务必」「CRITICAL」「MUST」之类的重复强调。新版模型对系统提示词更敏感，这类措辞容易导致执行过头。改为平实的陈述，例如「在……情况下使用这个工具」。
  2. 只下命令不给原因：把「不要做 X」补成「因为……，所以……」，让模型能推广到没写到的情况。
  3. 否定式的格式要求：把「不要用 Markdown」这类说法改成正面描述想要的样子，如「用连贯的段落来写」。
  4. 催促更努力的话：如「务必全面」「拿不准就调用工具」「不要偷懒」。新版模型本身更主动，这些话会造成过度搜索、过度展开。删掉或改成有条件的说明。
  5. 含糊的期望：只说「做个报表」而没说要做到什么程度。新版模型更按字面执行，想要更完整、更讲究的结果需要明确写出来。
  6. 「建议」与「执行」不分：例如「你能建议一些修改吗」会只得到建议。想让它动手就直接写「请修改」。
  7. 混在一起的内容：指令、背景、示例、待处理材料没有分开的，用 XML 标签分区。
  8. 依赖预填充（让模型接着一段写好的开头继续）的用法：标出来，改成在指令里说明输出要求。
  </review_rules>

  请输出：
  一、问题清单（表格）：原句 | 属于第几条规则 | 可能造成的现象 | 改写后的句子。
  二、完整的新提示词，放在 <new_prompt> 标签里，可以直接复制使用。保留原提示词的全部业务要求，不要增加我没提过的功能。
  三、3 条测试输入的建议，用来比较新旧提示词的差别（各写明预期新版应有什么不同）。
  对于你不确定是否该改的句子，保留原样并在清单里注明「建议对比测试后决定」。

**审查规则的依据**：八条规则整理自 Anthropic 官方「Prompting best practices」页面（资料核对于 2026-10-10），对应的官方说法包括：较新的模型对系统提示词响应更强，原来为了防止「该用工具却不用」而写的强硬措辞，现在可能导致过度触发，建议把「CRITICAL: You MUST…」换成普通的「Use this tool when…」；解释指令背后的原因；告诉 Claude 要做什么，而不是不要做什么；以前鼓励模型「更彻底」的提示要调低；从 Claude 4.6 系列起，最后一条 assistant 消息的预填充不再支持。不同型号的差异官方另有各自的页面，升级到具体型号前建议再看一眼对应说明。

**怎么填变量**：[观察到的问题] 很有用，比如「每个问题都去搜索，很慢」「回答特别长」「让它提建议它直接把文件改了」，Claude 会优先处理与现象对应的句子。没测过就写「尚未测试」。

**用完之后**：新提示词不要直接替换上线。用第三部分给出的测试输入，把新旧两版各跑几次对比，再决定采用哪些改动——官方页面也提醒，针对某个型号得出的经验要用自己的评测复核。

**常见问题与调整**：
- 改写后丢了业务规则 → 追问：「逐条对照旧提示词，列出新版本里没有体现的要求。」
- 想保留个别强调 → 可以。只在确实反复被忽略的那一条上加强调；处处强调等于没有强调。
