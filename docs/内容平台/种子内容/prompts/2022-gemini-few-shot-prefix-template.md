**模板虽短，每个部分都有讲究**。Google AI 开发者文档的「提示词设计策略」对示例的建议是（资料核对于 2026-10-10）：
- **尽量总是带上少量示例**（few-shot）。示例能告诉模型输出的格式、措辞、范围和规律；示例足够清楚时，甚至可以省掉一部分文字说明。
- **示例之间格式必须一致**——前缀、换行、标点都一样，否则模型可能输出你不想要的格式。
- **不要给太多示例**，否则模型容易对示例「过拟合」，照着示例的内容而不是规律来回答。一般 3–5 个。
- **使用前缀**：「输入：」「输出：」这样的标记帮助模型分清各部分；提示词以一个空的「输出：」结尾，模型会顺着这个模式接着写，这是官方文档介绍的「补全」策略。

**怎么填变量**：
- 示例要覆盖不同情况，并且**标签分布要均衡**：做情感分类时不要三个示例全是「正面」。
- 第四个示例专门放一个边界情况（内容为空、与任务无关、同时符合两类），示范你希望的兜底输出，比如「无法判断」。
- [口径说明] 写一两句容易混的地方怎么算，例如「只催发货、没有表达不满的，算『咨询』不算『投诉』」。
- 每次只把最后一行的 [待处理的内容] 换掉，前面保持不动。

**批量使用的建议**：通过 API 调用时，把任务说明和示例放在系统指令里固定下来，每次请求只传「输入：……输出：」。输出要给程序用，可以配合结构化输出功能，并在代码里校验取值是否在允许范围内。

**常见问题与调整**：
- 输出老是偏向某个示例的内容 → 示例太相似或太多。删到 3 个，并让它们在长度、话题上拉开差距。
- 输出后面多了解释 → 检查每个示例的「输出：」是否都只有结果本身；示例里带解释，模型就会跟着解释。
- 一个标签总被误判 → 针对这个标签补一个容易混淆的示例，比加长文字说明更有效。

**和本站其他提示词的关系**：怎样挑选和编写示例的完整方法见「Few-shot 示例怎么写提示词」；标签体系怎么定见「文本分类提示词怎么写」。这一条提供的是可以直接套用的排版骨架。

### 示例输出

> 示例，仅供参考（任务：把用户留言归为 咨询 / 投诉 / 建议 / 无法判断 之一）

```
输入：你们周末发货吗？
输出：咨询

输入：等了五天还没发，再不发我就退款了。
输出：投诉

输入：要是能在订单页直接改地址就好了。
输出：建议

输入：哈哈哈
输出：无法判断

输入：包装盒压坏了，里面的杯子倒是没事，下次能不能多垫点泡沫？
输出：建议
```
