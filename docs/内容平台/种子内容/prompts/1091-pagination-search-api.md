**怎么填变量**：[前端交互] 决定方案：需要「跳到第 37 页」时只能用页码分页；下拉加载更多、上一页下一页，用游标分页更快也更准确。[表结构与现有索引] 要贴，分页性能最终取决于索引能否覆盖筛选和排序。

**常见坑**：
- 只按创建时间排序，同一秒内创建的记录顺序不确定，翻页时会出现重复或漏掉。追加主键作为第二排序键。
- 信息流使用偏移量分页，用户翻页期间有新内容插入，下一页就会出现上一页已经看过的内容。
- 每次请求都统计总数，在大表上非常慢。很多场景下只需要知道「还有没有下一页」。

**追问技巧**：追问「列表需要同时支持按金额和按时间排序，游标该怎么设计」，或「这个列表接口如何加缓存，数据更新后怎么失效」。

### 示例输出

> 示例，仅供参考（订单列表，按创建时间倒序，游标分页）

```sql
-- 索引：等值筛选字段在前，排序字段在后
CREATE INDEX idx_orders_user_status_time ON orders (user_id, status, created_at DESC, id DESC);

-- 第一页
SELECT id, order_no, amount, created_at FROM orders
WHERE user_id = ? AND status = ?
ORDER BY created_at DESC, id DESC
LIMIT 21;                       -- 多取 1 条，用于判断是否还有下一页

-- 下一页：游标解码得到上一页最后一条的 (created_at, id)
SELECT id, order_no, amount, created_at FROM orders
WHERE user_id = ? AND status = ?
  AND (created_at < ? OR (created_at = ? AND id < ?))
ORDER BY created_at DESC, id DESC
LIMIT 21;
```
