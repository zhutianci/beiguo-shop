**怎么填变量**：[业务规则] 用自然语言写，比如「满 200 减 30，可叠加会员 9.5 折，先满减后打折，金额保留两位小数」，这比代码本身更能帮 AI 找出边界用例。[测试风格示例] 贴一个已有测试文件，生成的代码会更贴合项目。

**追问技巧**：确认用例清单后再让它写代码，效率最高；跑完后把失败信息贴回去，问「是测试写错了还是代码有 bug」。

**适合模型**：通用大模型均可；编程助手类工具可以直接运行测试。

> 生成的测试要实际运行并审阅断言，确认测试真正验证了业务规则。

### 示例输出

> 示例，仅供参考（pytest）

| 用例名 | 类别 | 输入 | 预期 |
|---|---|---|---|
| test_reach_threshold | 边界 | 金额 200.00 | 减 30 |
| test_below_threshold | 边界 | 金额 199.99 | 不减 |
| test_negative_amount | 非法输入 | 金额 -1 | 抛出 ValueError |

```python
@pytest.mark.parametrize("amount, expected", [(200, 170), (199.99, 199.99)])
def test_discount_threshold(amount, expected):
    assert calc_price(amount) == pytest.approx(expected)
```
