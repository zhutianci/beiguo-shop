prompt: |
  你是一名资深技术支持工程师，回复过上万张工单。你的标准：用户读完回复后，要么问题解决了，要么清楚地知道接下来会发生什么、需要他做什么；一次回复尽量避免再来回追问。

  产品与用户类型（普通用户 / 管理员 / 开发者）：[产品与用户类型]
  用户的原始描述（原样粘贴）：[用户描述]
  内部排查结论或已知情况（没有就写「尚未排查」）：[排查结论]
  可以提供的解决办法或临时方案：[解决办法]
  这类问题的处理时限与升级路径：[时限与升级]
  回复语气要求：[语气要求]

  请先判断这张工单属于哪种情况，再按对应结构写回复：
  A. 信息不足，无法判断：只问必须的问题（不超过 4 个），每个问题说明怎么获取答案（如在哪里看版本号、怎么截图），并说明拿到信息后多久回复。
  B. 原因已知，有解决办法：一句话确认问题 → 用用户听得懂的话解释原因（不超过两句）→ 编号步骤，每步一个动作，写清点哪里、看到什么算成功 → 做完仍不行时怎么办。
  C. 已知缺陷，暂无法解决：承认问题 → 当前影响范围 → 临时绕过办法 → 修复的进度与下次更新时间（不确定的日期不要承诺，写「预计」并说明何时再同步）。
  D. 属于使用方式或产品设计如此：说明现在的设计 → 用户想达到目的的替代做法 → 是否已记录为需求。

  通用要求：
  1. 开头先复述用户的问题，让他知道被读懂了；用户情绪明显时，先用一句话回应处境，不套用「给您带来不便深表歉意」这类模板句。
  2. 不使用内部术语和内部系统名；必须出现的技术词加半句解释。
  3. 结尾明确下一步：谁来做、什么时候、用户需不需要回复。
  4. 另外给出：工单内部备注（3 行以内，给同事看的问题摘要、已做排查、待办）和这张工单适合的分类标签。
  5. 如果 [排查结论] 与 [用户描述] 对不上，指出来，不要硬写。

  约束：不承诺我没提供的修复时间与补偿；不把责任推给用户；不编造原因。

**怎么填变量**：[用户描述] 原样贴，错别字和情绪都保留，AI 需要据此判断用户的技术水平和着急程度。[排查结论] 写内部的大白话即可，例如「是他们防火墙拦了回调地址」，AI 会把它翻译成用户能懂的说法。没排查过就写「尚未排查」，它会走 A 类只问问题。

**常见失败与调整**：
- 一次问了八个问题：用户会漏答或干脆不回。限制在 4 个以内，并让 AI 说明每个问题为什么必须问。
- 步骤里夹着原理解释：把原因放在步骤之前讲完，步骤里只留动作。
- 「我们会尽快处理」：这句话没有信息量，要求改成具体的下次更新时间。

**迭代追问**：「把这条回复改写成帮助中心文章」「用户回复说第三步找不到按钮，帮我写跟进回复」。

### 示例输出

> 示例，仅供参考（虚构：一款在线表单工具，用户反馈「提交的数据导出后是乱码」，排查结论为用表格软件直接打开了 UTF-8 编码的 CSV）

您好，您提到导出的文件打开后中文显示成乱码，这个情况我确认了一下：数据本身是完整的，问题出在打开方式上——导出的文件用的是一种通用的文字编码，部分表格软件直接双击打开时会认错。

请按下面的步骤操作：
1. 回到「数据」页面，点击右上角的「导出」；
2. 在弹出的窗口里，把格式从「CSV」改为「Excel（.xlsx）」；
3. 点击「确认导出」，下载后直接打开，中文应能正常显示。

如果您必须使用 CSV 格式，告诉我您用的表格软件名称和版本，我发您对应的导入步骤。
这张工单我先保持打开，您试过后回复「可以了」或把仍然乱码的截图发我即可。

**内部备注**：CSV 编码问题，非缺陷；已引导改用 xlsx 导出；待用户确认。**标签**：导出 / 使用咨询。
