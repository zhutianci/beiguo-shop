**怎么填变量**：[粘贴需求文档] 直接贴原文，包括原型图的文字说明。图片里的信息可以简单描述一下，比如「按钮在页面右下角，灰色时不可点」。[本次测试范围] 写清楚可以避免输出几百条用例。

**常见坑**：
- 需求本身没写清楚时，AI 会自己「脑补」一个预期结果写进用例，看起来很完整，实际可能和产品意图不一致。所以模板把「需求疑问」单独列出来，这部分往往是整个输出里最有价值的。
- 预期结果写成「操作成功」「显示正确」，执行的人没法判断。要求写到具体文案和数据变化。
- 有状态的业务（订单、审批）一定要做状态流转用例，「已取消的订单还能不能付款」这类非法流转最容易出 Bug。

**追问技巧**：产品经理回复疑问后，把答复贴回去，说「根据这些答复更新用例，标出新增和修改的条目」。需要导入工具时，追问「输出为 CSV，用英文逗号分隔，步骤用分号连接」。
