  我要把一项任务交给一个 AI 智能体独立完成。它只能看到我给它的这份任务说明，不知道我们之前聊过什么，中途我也不一定在线。请帮我把任务说明书写好。

  我想让它做的事（口语描述即可）：[任务的口语描述]
  它能使用的工具或权限：[可用工具与权限]
  我已经知道或已经排除的情况：[已知信息与已排除项]
  我担心它会做错的地方：[担心的问题]

  第一步：检查我的描述
  站在「对这件事一无所知的执行者」的角度，列出它开工前一定会想问的问题（最多 6 个），按重要性排序，等我回答。已经能从我的描述推断出来的不要问。

  第二步：输出任务说明书（等我回答后），包含以下部分：
  1. 目标：一两句话说明要达成什么结果，以及这件事是为了什么——让它在遇到没写到的情况时能自己做出合理判断。
  2. 背景与已知信息：它需要知道的事实、相关文件或资料的位置；我已经试过、排除过的方向，避免重复劳动。
  3. 范围：
     - 要做的；
     - 明确不做的（容易顺手做、但我不希望它碰的）；
     - 可以自行决定的细节。
  4. 约束：必须遵守的规则，每条附一句原因。
  5. 需要先停下来问我的情况：会产生不可逆后果的操作（删除、覆盖、对外发送、花钱、改生产环境）、超出上述范围的改动、发现任务前提不成立时。
  6. 完成标准：用可以检查的条件来写（什么命令通过、哪份文件存在且包含什么、哪个数字达到多少），而不是「做好」「完善」。
  7. 汇报格式：完成后按这个顺序向我报告——结论；实际做了什么；用什么证据证明完成（运行的检查及其结果）；没做完或不确定的地方；建议我接下来做什么。要求它如实说明失败和跳过的部分，不要只报好消息。
  8. 卡住时怎么办：同一个办法试了两次不行就换思路或停下来说明情况，不要无限重试，也不要通过降低标准来「完成」。

  写作要求：用平实的陈述句；一份说明书只交代一个任务；长度以执行者读完能直接开工为准，不要为了显得完整而堆砌通用要求。

  第三步：另外用三句话告诉我，这份说明书里哪一处最可能被误解，以及我可以怎样提前验证（例如先让它复述计划）。

**为什么要专门写「任务说明书」**：和聊天不同，交给智能体的任务往往是你发出去就不再看的。它不知道你的背景、不知道你已经试过什么，手里只有这一页纸。常见的翻车都出在说明书上：目标只说了动作没说目的，于是遇到岔路选了错的一边；没写范围，它顺手「优化」了不该动的东西；没写完成标准，它觉得差不多了就停；没要求证据，汇报里全是「已完成」。

**怎么填变量**：[已知信息与已排除项] 最容易被省略，却最省时间——例如「已确认不是网络问题」「上个月试过升级依赖，无效」。[担心的问题] 直接写你的直觉，如「怕它为了让测试通过去改测试」「怕它把结果发到群里」，模型会把它们转成约束和停下条件。[可用工具与权限] 写实际情况：能不能联网、能不能写文件、能不能执行命令。

**常见问题与调整**：
- 说明书写得太长 → 追问：「删掉任何一个合格执行者不看也会做对的句子。」
- 任务其实是好几件事 → 让它拆：「把这份说明书拆成可以独立执行的 2–3 份，并说明先后依赖。」
- 想更稳妥 → 在交给智能体时加一句：「开工前先用五句话复述你的计划和完成标准，等我确认。」

### 示例输出

> 示例，仅供参考（任务：让编程智能体找出并修复「导出报表偶尔缺少最后一行」的问题；节选）

**目标**：找出导出报表偶发缺少最后一行的原因并修复。财务每月用这份报表对账，缺行会导致金额对不上，所以正确性优先于导出速度。

**已知信息**：问题只在数据超过 5000 行时出现；已确认数据库查询结果是完整的，问题在写文件环节；上周尝试过增大缓冲区，无效。

**明确不做**：不更换导出所用的库；不改报表的列顺序和格式。

**需要先问我**：需要修改数据库查询或表结构时；需要新增依赖时。

**完成标准**：新增一个用 6000 行数据的测试，能在修复前稳定失败、修复后通过；现有测试全部通过。

**汇报格式**：根因一句话 → 改动的文件 → 测试命令与输出 → 仍不确定的地方。
