**怎么填变量**：[业务规则与字段之间的关系] 最能体现数据质量，写得越细，造出来的数据越不容易在联调时「一看就是假的」或触发莫名其妙的校验错误。[脚本语言] 写你项目里用的，比如 Python 或 Node.js。

**常见坑**：
- 让 AI 直接输出几千条数据，往往中途截断，或者后面的数据开始大量重复。超过几十条就让它写脚本。
- 只生成「完美」的数据，测不出问题。模板要求按比例混入边界值，并列出特殊数据清单，方便写断言。
- 不要为了「更真实」把生产数据库导出来改一改再用，这仍然有泄露风险。造数据比脱敏生产数据更安全。

**追问技巧**：追问「再生成一批专门用于测试排序和分页的数据：同名、同时间、同金额的记录各若干条」，这类数据很容易测出排序不稳定的问题。
