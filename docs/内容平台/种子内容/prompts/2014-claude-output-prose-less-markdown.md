**这段说明用到的官方方法**：Anthropic 的提示词最佳实践给了四种控制输出格式的办法（资料核对于 2026-10-10）：一是告诉 Claude 要做什么，而不是不要做什么——与其写「不要用 Markdown」，不如写「用流畅衔接的段落来回答」；二是用 XML 标签指明格式，比如要求把某部分写在指定标签里；三是让提示词本身的风格贴近你想要的输出，提示词里少用 Markdown，输出里的 Markdown 也会减少；四是需要精细控制时，给出详细明确的格式说明。上面的模板把四条都用上了：通篇是正面描述，正文装进 `<article>`，说明本身尽量写成句子。

**怎么填变量**：[读者是谁] 和 [阅读场景] 是给原因——「领导在手机上看」「会被朗读出来」「要粘贴进邮件」，Claude 会据此自己判断很多你没写到的细节。[多少字以上] 常用 800，[加粗上限] 常用 2 或 3。

**放在哪里**：只管一次回答就直接和任务一起发；想长期生效，把 `<writing_format>` 整块放进 Claude 项目（Projects）的项目指令，或 API 的 system 提示词。

**常见问题与调整**：
- 仍然列表偏多 → 检查你贴的任务材料是不是本身满是列表和加粗，可以先请它「把材料改写成纯文字要点」再写；也可以把模板里列表那一条收紧为「只有操作步骤可以用列表」。
- 反过来想要更多结构 → 较新的型号本身格式就用得少（官方针对个别新型号提醒过这一点），这时删掉这段说明，或只保留篇幅与语气一条。
- 数学公式想要纯文本 → 另加一句：「数学表达式用普通字符书写，不使用 LaTeX 记号。」

### 示例输出

> 示例，仅供参考（任务：向非技术同事说明这次系统升级的影响）

```
<article>
本周六晚上十点到周日早上六点，订单系统会停机升级。这段时间里无法新建和修改订单，已经提交的订单不受影响，升级完成后会照常流转。

之所以选在周末夜间，是因为过去三个月这个时段的下单量最低。升级后最直接的变化是查询速度：以前按客户名搜索历史订单需要十几秒，之后基本在两秒以内。操作界面没有改动，不需要重新学习。

**如果周六当晚有必须录入的紧急订单**，请先记在共享表格里，周日上午由值班同事统一补录。
</article>

需要确认：共享表格的链接是否沿用上次升级时的那一份？
```
