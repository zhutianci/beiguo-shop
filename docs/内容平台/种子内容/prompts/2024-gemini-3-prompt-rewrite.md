prompt: |
  # 任务
  下面「原提示词」是为其他模型或旧版本写的，我现在要在 Gemini 3 系列上使用。请依据「审查清单」检查并改写，目标是保留全部业务要求，只调整表达和排布。

  # 审查清单
  1. 劝说与强调过多：反复的「非常重要」「务必」「请一定」、冗长的情绪化措辞。改为直接、简洁地陈述目标和要求。
  2. 结构标记混用：同一份提示词里既有 XML 标签又有 Markdown 标题、还夹杂自定义符号。统一成一种，全篇一致。
  3. 关键要求位置靠后：角色、硬性约束、输出格式散落在中后部。移到开头。
  4. 长材料与问题的顺序：大段材料之后才是具体问题更合适；问题在材料之前的，调到材料之后，并用「根据以上信息」之类的话衔接。
  5. 详略没有说明：原提示词默认模型会展开论述。需要详细的地方，明确写出展开到什么程度；可以简短的地方也写明。
  6. 多余的「请一步步思考」：模型自带推理过程，通常不需要要求它把逐步推理写出来。确实需要展示推理过程的，改为明确要求「在答案中写出推导步骤」。
  7. 时间敏感内容：提示词涉及「最新」「今年」等说法而没有给出当前日期的，补一行今天的日期，并说明哪些内容需要以检索到的资料为准。
  8. 示例：没有示例且对输出格式有严格要求的，建议补 2–3 个格式一致的示例（由我提供内容，你先留出位置）。
  9. 参数类建议：原提示词附带「把温度调低」之类的说明的，提示我 Gemini 3 建议保持默认采样参数。

  # 输出
  一、修改清单：原文片段 | 对应审查清单第几条 | 改法。
  二、改写后的完整提示词，放在一个代码块里，可以直接复制。
  三、你没有改动、但建议我实际对比测试后再决定的地方。
  四、原提示词里你认为相互矛盾或含义不清的要求，列出来问我，不要自行取舍。

  # 背景
  用途：[提示词用途]
  在 Gemini 上看到的问题：[观察到的问题]

  # 原提示词
  [粘贴原提示词]

  根据以上信息，开始审查并改写。

**审查清单的依据**：九条整理自 Google AI 开发者文档「提示词设计策略」中针对 Gemini 3 的部分（资料核对于 2026-10-10）。官方的说法包括：直接说明目标、避免过度劝说式的语言；用 XML 风格标签或 Markdown 标题组织提示词，但要保持一致、只选一种；Gemini 3 默认回答直接简短，需要更详细要明确提出；角色、约束和输出格式放在开头；长上下文时把指令或问题放在材料之后；Gemini 2.5 和 3 系列自带内部思考，一般不必再要求逐步输出推理；采样参数建议保持默认，把 temperature 调到 1.0 以下可能造成循环或推理质量下降；对时间敏感的任务，可在系统指令里说明当前年份。

这条提示词自身也按这些建议排版：只用 Markdown 标题，规则在前，原提示词（长材料）在后，最后一句用「根据以上信息」收尾。

**怎么填变量**：[观察到的问题] 写现象，如「只回答了三句话」「后半段的格式要求被忽略」「用的是去年的数据」，它会优先处理对应的审查项。还没测过就写「尚未测试」。

**常见问题与调整**：
- 改写后要求变少了 → 追问：「逐条对照原提示词的每一项要求，列出新版本里对应的句子；缺失的补回去。」
- 新版本反而回答太长 → 把「详略」那几句调整为具体的字数或句数范围。
- 不同型号表现不一 → 官方文档中有些建议只针对特定型号，换型号后用同一批测试输入重新对比一次。

**和本站 Claude 那条的区别**：两家官方的建议方向相近（少强调、多说明），但细节不同——例如 Claude 侧强调解释原因和预填充的迁移，Gemini 侧强调结构标记二选一、问题放在材料后和保持默认采样参数。给哪个模型用，就按哪家的清单改。

### 示例输出

> 示例，仅供参考（原提示词为一份客服质检提示词，节选）

| 原文片段 | 清单 | 改法 |
| --- | --- | --- |
| 「非常非常重要！！请务必仔细阅读每一句对话！」 | 1 | 删除；在「任务」中写「逐句检查对话」即可 |
| 评分标准写在对话记录之前，输出格式写在最末尾 | 3、4 | 评分标准与输出格式移到开头；对话记录放在后面，结尾加「根据以上对话，按评分标准打分」 |
| 「请一步步思考后再打分」 | 6 | 改为「每一项得分后用一句话写出扣分依据」 |

**建议对比测试后决定**：原提示词要求「总评不超过 50 字」，在 Gemini 3 上可能偏短，可对比 50 字与 100 字两个版本。
