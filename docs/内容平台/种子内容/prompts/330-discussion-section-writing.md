useCase: 结果写完、讨论不知从何下笔或写成了「结果复述」时用：按标准结构组织讨论，解释发现、与你提供的文献对比、写出真诚的局限性和有依据的展望。
prompt: |
  【角色】你是一名资深期刊审稿人和写作导师，擅长写出有深度、不过度推论的讨论部分。

  【背景】
  - 研究问题与假设：[研究问题与假设]
  - 主要发现（含关键数字）：[主要发现]
  - 是否支持假设：[假设检验结果]
  - 可对比的文献及其发现（附引用标记）：
    [对比文献要点]
  - 我知道的局限：[已知局限]
  - 研究设计类型：[研究设计类型]
  - 字数要求：[字数要求]

  【任务】
  1. 设计讨论结构：概括主要发现 → 解释可能机制 → 与既往研究的一致与不一致及可能原因 → 理论与实践意义 → 局限性 → 未来研究方向 → 结论。
  2. 每段先写主题句，再展开；解释机制时区分「数据直接支持」和「推测」，推测用谨慎措辞。
  3. 与文献对比时，对不一致的结果从样本、方法、测量、情境等角度分析原因。
  4. 局限性要具体，并说明每项局限对结论可能的影响方向。
  5. 未来方向要具体可行，与局限对应。

  【约束】
  - 只使用我提供的结果和文献，不编造任何引用；需要支持的推测标「【需补引用】」。
  - 结论用语不超出研究设计（观察性研究不用因果语言）。
  - 不简单重复结果部分的数字。

  【输出格式】
  结构大纲（段落 | 主题句 | 要点）→ 讨论全文 → 需补引用清单 → 过度推论自查表。
negativePrompt: null
source: null
verify:
  - 用横断面研究的结果实测，检查是否避免了因果措辞

**怎么填变量**：[对比文献要点] 每条写「作者, 年份：发现了什么、用的什么样本」，方便 AI 分析一致或不一致的原因；[已知局限] 写实话，审稿人往往比你更清楚。

**追问技巧**：初稿后追问「哪些句子属于过度推论，给出更谨慎的写法」；字数超限时追问「保留哪三点最重要」。

**适合模型**：通用大模型均可；推理模式在机制解释上更有条理。

> 讨论中的所有文献都需亲自阅读核实；机制推测应明确标注为推测。
