**怎么填变量**：[触点数据样例] 至少要包含用户标识、渠道、触点时间，以及转化事件和转化时间。[分析目的] 会影响模型选择：评估拉新能力看首次触点，评估收割效率看末次触点，做整体预算分配建议对比多种模型。

**常见坑**：
- 只看广告平台后台的数据，每个平台都按自己的规则把转化算给自己，加起来比实际转化数多得多。
- 只用末次触点归因，得出「搜索广告和私域效率最高」的结论，砍掉了负责拉新的信息流预算，几个月后搜索量和私域新增也下降了。
- 把归因结果当作因果结论。归因是在分配功劳，渠道是否真的带来增量，需要实验来验证。

**追问技巧**：追问「设计一个按城市分组的渠道暂停实验，验证信息流广告的真实增量」，或「把归因结果做成每周自动更新的看板」（可配合 432 号看板设计提示词）。

路径：信息流广告 → 公众号文章 → 社群 → 搜索广告 → 购买（金额 1000 元）

| 模型 | 信息流 | 公众号 | 社群 | 搜索 |
|---|---|---|---|---|
| 首次触点 | 1000 | 0 | 0 | 0 |
| 末次触点 | 0 | 0 | 0 | 1000 |
| 线性 | 250 | 250 | 250 | 250 |
| 位置（首尾各 40%，中间平分 20%） | 400 | 100 | 100 | 400 |

```python
def position_based(path, value, head=0.4, tail=0.4):
    n = len(path)
    if n == 1:
        return {path[0]: value}
    if n == 2:
        return {path[0]: value / 2, path[1]: value / 2} if path[0] != path[1] else {path[0]: value}
    share = {}
    middle = (1 - head - tail) * value / (n - 2)
    for i, ch in enumerate(path):
        w = head * value if i == 0 else tail * value if i == n - 1 else middle
        share[ch] = share.get(ch, 0) + w
    return share
```
