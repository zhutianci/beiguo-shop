**怎么填变量**：[中文描述] 不要只写「用户数据」，要写清楚「已登录用户最近 30 天的订单列表」这种程度，名字才能准确。[已有命名] 很重要，如果项目里已经统一用 `fetchXxx` 表示调用接口，新函数就不该改用 `getXxx`。

**常见坑**：
- 名字里用 data、info、temp、handle、manager 这些泛词，等于没起名。让 AI 说明候选名「具体比泛词多表达了什么」。
- 函数名说的是 get，实际却会写数据库或发请求，读代码的人会被误导。名字要诚实反映副作用。
- 金额、时间、大小这类数值不带单位，是很多线上事故的源头（秒和毫秒、元和分弄混）。

**追问技巧**：一次性给一批名字时，可以把整个函数或类贴进去，说「检查这段代码里所有命名，列出需要改的及建议名」。

### 示例输出

> 示例，仅供参考（Python；作用：判断优惠券在下单时间点是否还能用）

| 候选名 | 理解 | 评价 |
|---|---|---|
| `is_coupon_usable_at(order_time)` | 某个时间点优惠券是否可用 | 推荐：布尔函数用 is 开头，时间参数说明了判断基准 |
| `check_coupon(order_time)` | 检查优惠券 | 含糊：看不出返回布尔还是会抛异常 |
| `coupon_valid` | 优惠券有效 | 像变量不像函数，且没有体现时间点 |

推荐 `is_coupon_usable_at`。另外，已有命名中的 `get_coupon_and_lock()` 既查询又加锁，建议拆成 `find_coupon()` 和 `lock_coupon()`，或者改名为 `acquire_coupon_lock()` 明确副作用。
