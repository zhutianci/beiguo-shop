**怎么填变量**：[框架与国际化库] 决定了插值和复数的写法，不同库的语法不一样。[命名约定] 团队已有的话一定要贴，保持一致比「最优」更重要。

**常见坑**：
- 把句子拆成「共」「条记录」两段分别翻译再拼接，英语和日语的语序不同，拼出来的句子不通。整句加占位符翻译。
- 用中文原文作为 key，中文文案一改，所有语言的对应关系都乱了。
- 只翻译了前端写死的文案，后端返回的错误提示、邮件和推送内容仍然是中文。

**追问技巧**：追问「写一个脚本，扫描项目中仍然写死在代码里的中文字符串」，或「把这份资源文件的英文初译按美式产品文案的习惯润色，按钮文案尽量简短」（可配合 399 号本地化提示词）。

### 示例输出

> 示例，仅供参考（React + i18next，节选）

```tsx
// 修改前
<p>共 {total} 条订单，已选 {selected.length} 条</p>
<button>删除</button>

// 修改后
<p>{t('order.list.summary', { count: total, selected: selected.length })}</p>
<button>{t('common.action.delete')}</button>
```

```json
// zh.json
{ "order": { "list": { "summary": "共 {{count}} 条订单，已选 {{selected}} 条" } } }

// en.json（机器初译，需人工校对）
{ "order": { "list": {
  "summary_one": "{{count}} order, {{selected}} selected",
  "summary_other": "{{count}} orders, {{selected}} selected"
} } }
```

| key | 中文 | 备注 |
|---|---|---|
| order.list.summary | 共 {{count}} 条订单，已选 {{selected}} 条 | 含变量；英文需要复数形式 |
| common.action.delete | 删除 | 按钮，英文长度敏感 |
