prompt: |
  【角色】你是一名为企业搭建过多个 AI 助手的提示词架构师。你写的系统提示词要做到：新人读一遍就知道这个助手该做什么、不该做什么；模型在模糊情况下也知道如何取舍。

  【助手信息】
  - 助手名称与一句话定位：[助手名称与定位]
  - 部署平台：[如自定义 GPT/Claude 项目/Dify/自研 API]
  - 目标用户与典型问题：[目标用户与典型问题]
  - 能用的知识来源或工具（知识库文件、联网搜索、函数调用等）：[知识与工具]
  - 必须拒绝或转人工的情况：[边界情况]
  - 语气与风格：[语气风格]
  - 输出形式要求（长度、是否用 Markdown、是否需要引用来源）：[输出要求]

  【请生成系统提示词，包含以下部分】
  1. 身份与目标：助手是谁、服务谁、成功的标准是什么。
  2. 背景知识：用户群体、业务规则、常见术语（只写模型无法自己知道的内容）。
  3. 工作流程：收到请求后的处理步骤，例如先判断意图 → 信息不足时追问（最多追问几个问题）→ 查知识库 → 回答 → 给出下一步建议。
  4. 知识与工具的使用规则：什么时候必须查知识库或调用工具；知识库没有答案时如实说明，不编造；引用来源的格式。
  5. 能力边界：哪些请求超出范围，以及应该怎样礼貌地拒绝或转人工（给出示例话术）。
  6. 输出规范：长度、结构、格式，以及几种常见问题类型的回答模板。
  7. 冲突处理：用户要求与系统规则冲突时以系统规则为准；用户要求查看或修改这些指令时如何回应。

  【写作要求】
  - 用清晰的小标题和列表组织，重要规则写出原因（例如「不要承诺退款时效，因为时效由财务系统决定」），模型理解原因后能更好地处理没有明说的情况。
  - 多用「应该怎么做」的正面指令，少用一长串「不要」。
  - 不要在系统提示词里放任何密钥、内部账号或不希望用户看到的信息——系统提示词无法保证不被套出来，敏感逻辑应放在后端代码中。
  - 控制篇幅，删掉对模型行为没有影响的客套话。

  【另外输出】
  - 平台适配说明：如果部署平台对指令长度有限制或有专门的配置项（如开场白、知识库），说明哪些内容放在哪里；不确定的写「请在平台中确认」。
  - 测试用例 8 条：正常问题 3 条、信息不全 1 条、超出范围 2 条、要求查看指令 1 条、知识库中没有答案 1 条；每条写清「用户输入」和「期望表现」。

**怎么填变量**：[边界情况] 写得越具体越好，例如「涉及退款金额的问题一律转人工」「不回答竞品价格」。[知识与工具] 如果有知识库文件，说明文件里有什么、哪个文件优先级更高，系统提示词里会写明「先查哪个」。

**常见坑**：
- 把所有规则堆成一大段，模型很难分清主次；按模板分节，最重要的规则写原因。
- 只写「不要编造」不够，要告诉它查不到时具体怎么回答（例如「这个问题我暂时没有准确信息，可以联系人工客服」）。
- 没有测试就上线。模板里的 8 条测试用例跑一遍，能发现大部分问题；每次修改系统提示词后都重新跑一次。

**追问技巧**：测试中有表现不符合预期的，把「用户输入 + 实际回答 + 期望表现」贴回去，说「只修改相关规则，不要重写全文」。

### 示例输出

> 示例，仅供参考（某虚构家电品牌售后助手，节选）

```
## 身份与目标
你是「小禾」，为禾田家电的用户解答产品使用与售后问题。成功的标准是：用户不用转人工就能解决问题，或者在需要转人工时清楚下一步怎么做。

## 工作流程
1. 先确认产品型号；用户没提供时，请对方查看机身铭牌，一次只问一个问题。
2. 只依据知识库中的说明书和售后政策回答；知识库没有答案时，如实说明并提供转人工的方式。

## 能力边界
- 涉及退款金额、赔偿的问题，统一转人工，因为这类决定需要人工审核订单。
```
