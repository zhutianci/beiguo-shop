**怎么填变量**：[原文样例] 选有代表性的几段，最好包含标题、正文、列表、带数字和专名的句子各一些，规则才能覆盖到。[参考译文] 很有价值，客户认可过的旧译文就是最直接的风格证据，哪怕只有几百字。[目标读者与场景] 例如「中国大陆的中小企业 IT 管理员，在产品后台里查阅帮助文档」，决定了正式程度和是否保留英文术语。

**常见失败与调整**：
- 指南写成原则宣言（「译文应准确、流畅、地道」），没法执行。要求每条规则必须带正反例，不能举例的规则删掉。
- 规则太多，没人读。让模型把最常用的十条放在最前面，并用第 5 步的精简版配合日常使用。
- 模型自作主张定了「你」还是「您」。凡是样例中看不出来的，应进入第 3 步的待决定事项，由你或客户决定。

**追问**：「用这份指南检查下面这段译文，逐条指出违反了哪一条」「把精简版改写成给机器翻译后编辑人员看的版本」。术语部分建议另用站内的翻译术语表提取提示词单独建表。

### 示例输出

> 示例，仅供参考（虚构：一款项目管理软件的帮助文档，英译简体中文）

**优先顺序**：客户明确要求 → 术语表 → 本指南 → 一般语言规范。

**2.1 人称与语气**
- 规则：称呼读者用「你」，不用「您」；操作步骤用祈使句，不加「请」。
- 正例：点击「新建项目」，然后输入项目名称。
- 反例：请您点击「新建项目」按钮，随后您需要输入项目的名称。

**2.3 界面文字**
- 规则：界面元素用直角引号「」标示，名称与产品中文界面保持一致；尚未本地化的界面元素保留英文并同样加引号。
- 正例：在「设置」中打开「Beta features」。
- 反例：在设置里打开 beta 功能。

**2.4 数字与单位**
- 规则：数字用阿拉伯数字；英制单位换算为公制，括注原值。【请对照所用规范确认中文与数字之间是否加空格】
- 正例：文件大小上限为 25 MB。

**待决定事项**：产品名之后是否加「软件」「平台」等类别词（原文样例未体现）。可选：一律不加；首次出现时加。
