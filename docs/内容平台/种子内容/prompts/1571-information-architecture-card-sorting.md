**怎么填变量**：[内容清单] 可以直接从网站后台、站点地图或 App 的功能列表导出，几十到几百项都可以。[已知问题] 很有价值，比如站内搜索日志里「发票」被搜了很多次，说明发票相关内容可能藏得太深。[一级导航数] 一般 5～7 项。

**常见坑**：
- 导航按公司部门划分（「市场部资料」「技术支持」），用户根本不知道该点哪个；
- 卡片上的文字用了内部术语，参与者看不懂，分类结果也失真；
- 改完导航不做测试，上线后才发现用户还是找不到。

**迭代追问**：「根据卡片分类的结果，帮我画出新的导航结构」「为树状测试写出参与者说明和结束问卷」「把新的信息架构整理成给开发的页面层级说明」。

### 示例输出

> 示例，仅供参考（虚构：家电品牌官网的服务与支持栏目）

**初版结构（待卡片分类验证）**
- 服务与支持
  - 我的产品（注册产品、查看保修）
  - 安装与使用（安装预约、说明书下载、使用视频）
  - 维修与售后（报修、进度查询、维修网点）
  - 常见问题

**树状测试任务（节选）**：「你家的洗衣机显示 E3 错误，想知道是什么意思。你会去哪里找？」——正确路径：服务与支持 → 常见问题 / 安装与使用 → 说明书。
