**怎么填变量**：[粘贴报错信息] 一定贴**完整**堆栈，不要只贴最后一行；[已尝试的方法] 能避免 AI 重复推荐你试过的办法。

**追问技巧**：照着验证方法跑完后，把结果贴回去（「加了日志，发现 config 是 None」），让它缩小范围；修好后追问「为这个 bug 写一个回归测试」。

**适合模型**：通用大模型均可；复杂问题开启推理模式，或用能直接读取项目文件的编程助手。

> 贴报错前删掉密钥、令牌、数据库密码等敏感信息。

> 示例，仅供参考

**报错解释**：`KeyError: 'user_id'` 表示字典里没有 user_id 这个键，出错位置在 handlers.py 第 42 行。

| 排名 | 假设 | 验证方法 |
|---|---|---|
| 1 | 前端字段名改成了 userId | 打印 request.json 的所有键 |
| 2 | 部分请求未登录，未注入 user_id | 查看出错请求是否带有 Cookie |

**修复**：先确认字段名，再用 `data.get("user_id")` 并在缺失时返回 400 错误。
