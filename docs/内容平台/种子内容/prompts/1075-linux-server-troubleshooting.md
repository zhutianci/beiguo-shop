**怎么填变量**：[现象] 描述得越具体越好，「SSH 也卡」和「只有某个接口慢」排查方向完全不同。[开始时间与最近的变更] 经常就是答案：刚上线了新版本、刚跑了数据导入、刚改了定时任务。

**常见坑**：
- 看到空闲内存很少就以为内存不够了。Linux 会把空闲内存用作缓存，要看「可用」内存一栏。
- 磁盘满了删掉大日志文件，空间却没有释放，因为写日志的进程还开着这个文件。需要让进程重新打开日志文件（或者清空内容而不是删除）。
- 慌乱中直接重启服务器，现场证据全部丢失，下次还会再发生。先收集诊断信息再处理。

**追问技巧**：排查完后追问「根据这次的情况，我应该加哪些监控项和告警阈值」，或「写一个一键收集诊断信息的只读脚本，下次出问题先跑它」。

### 示例输出

> 示例，仅供参考（现象：磁盘告警）

**第 1 步（只读）**：

```bash
df -h            # 看哪个分区满了
df -i            # 看索引节点是否用尽（文件数量过多也会「满」）
sudo du -xh --max-depth=1 / 2>/dev/null | sort -rh | head -15   # 根分区下各目录大小
```

请把输出贴给我。重点看：使用率 100% 的分区是哪个；如果 `du` 统计的总和明显小于 `df` 显示的已用空间，说明可能有「已删除但仍被进程占用」的文件，下一步执行：

```bash
sudo lsof +L1 | sort -k7 -rn | head    # 列出已删除但仍被打开的文件
```

**处理（需要你确认后执行）**：如果是某个服务的日志文件被删除但仍被占用，重启该服务或让它重新打开日志即可释放空间。影响：服务会短暂中断。
