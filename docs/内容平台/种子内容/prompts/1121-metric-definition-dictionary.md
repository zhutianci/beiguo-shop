**怎么填变量**：[现有口径] 是最有价值的输入。把各部门实际使用的计算方式（甚至他们的 SQL）都贴进来，AI 可以逐项对比差异在哪里，往往一眼就能看出为什么数字对不上。

**常见坑**：
- 指标定义只有一句话（「GMV 是成交总额」），没有写清包含什么、排除什么，每个人都可以按自己的理解去算。
- 口径改了没有记录生效日期，看趋势图时出现莫名其妙的跳变，却没人记得是口径变了。
- 名称相近的指标混用（GMV、实付金额、收入），对外汇报时用错了数字。

**追问技巧**：追问「检查我们现有看板上的所有指标，标出与这份字典口径不一致的地方」，或「把这份字典整理成可以放在数据平台上的表格格式」。

### 示例输出

> 示例，仅供参考（指标卡片节选）

**GMV（商品交易总额）**

| 项目 | 内容 |
|---|---|
| 业务定义 | 统计期内用户提交订单的商品原价总额，反映交易规模 |
| 计算公式 | 求和（商品单价 × 购买数量），按下单时间统计 |
| 包含 | 已支付、待支付、已取消、已退款的订单（GMV 衡量下单意愿，不扣除取消与退款） |
| 排除 | 测试账号订单、内部员工福利订单（待确认）、运费 |
| 相近指标 | 实付金额：扣除优惠后用户实际支付的金额，只统计已支付订单；收入：按财务确认口径，扣除退款 |
| 负责人 | （待确认） |

**分歧说明**：运营的报表按「下单即计入」，财务按「扣除退款后」，两者在 9 月相差约 12%。建议对外统一使用「实付金额」，GMV 只用于内部衡量交易规模（待确认）。
