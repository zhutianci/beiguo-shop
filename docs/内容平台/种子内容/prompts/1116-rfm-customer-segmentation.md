**怎么填变量**：[业务与购买周期] 决定统计期和 R 的阈值：生鲜复购以周计，家电复购以年计，用同一套阈值毫无意义。[订单字段] 中一定要说明有没有退款和订单状态字段，否则 M 值会被未支付和退款订单夸大。

**常见坑**：
- 很多业务中大部分客户只买过一次，F 按五等分打分时，多个分段的边界都是 1，分段失去意义。可以改为按「1 次、2 次、3 次及以上」这类业务阈值划分。
- 统计时包括了未支付、退款和测试订单，高价值客户名单里混进了薅羊毛和刷单的账号。
- 分完层就直接给所有「流失客户」发大额优惠券，没有对照组，事后无法判断是优惠券起了作用，还是他们本来就会回来。

**追问技巧**：追问「每个月自动更新一次分层，并输出客户在各层之间的流转情况（例如从重要价值客户掉到重要挽留客户的人数）」。

### 示例输出

> 示例，仅供参考（分群定义与策略节选）

| 类别 | R | F | M | 运营策略 |
|---|---|---|---|---|
| 重要价值客户 | 高 | 高 | 高 | 专属客服、新品优先体验，避免频繁打折 |
| 重要唤回客户 | 低 | 高 | 高 | 曾经的高价值客户，近期没有购买：个性化召回与定向权益 |
| 重要发展客户 | 高 | 低 | 高 | 刚完成大额消费：引导第二次购买 |
| 一般挽留客户 | 低 | 低 | 低 | 低成本渠道触达，控制营销预算 |

（R「高」表示最近购买过，即距今天数少。）

```sql
WITH base AS (
  SELECT user_id,
         DATEDIFF('2026-09-30', MAX(DATE(pay_time))) AS r_days,
         COUNT(DISTINCT order_id)                   AS f_cnt,
         SUM(paid_amount)                           AS m_amt
  FROM orders
  WHERE status = 'PAID' AND pay_time >= '2025-10-01' AND pay_time < '2026-10-01'
  GROUP BY user_id
)
SELECT *,
       CASE WHEN r_days <= 30 THEN 5 WHEN r_days <= 60 THEN 4 WHEN r_days <= 90 THEN 3
            WHEN r_days <= 180 THEN 2 ELSE 1 END AS r_score,
       CASE WHEN f_cnt >= 5 THEN 5 WHEN f_cnt >= 3 THEN 4 WHEN f_cnt = 2 THEN 3 ELSE 1 END AS f_score
FROM base;
```
