**怎么填变量**：[调用方] 是第三方合作方时，规范要更严格，版本策略和错误码要提前定好，因为对外接口改起来成本极高。[技术约束] 一定要写，很多公司的网关、防火墙或老客户端只支持部分 HTTP 方法。

**常见坑**：
- 所有接口都返回 HTTP 200，再在返回体里放一个 code 表示成败。这样监控和网关无法通过状态码识别错误。至少要让 4xx、5xx 反映真实情况。
- 金额用浮点数传，0.1 + 0.2 的精度问题会出现在对账里。用整数分或字符串。
- 偏移分页在数据量大或数据频繁新增时，会出现翻页重复或遗漏，信息流类列表适合用游标分页。

**追问技巧**：设计完成后，追问「根据这份设计生成 OpenAPI 3 描述文件」，可以直接导入接口文档工具和 Mock 服务。和 414 号提示词（从代码生成接口文档）配合使用效果更好。

### 示例输出

> 示例，仅供参考（节选）

| 方法 | 路径 | 用途 | 成功状态码 |
|---|---|---|---|
| GET | /v1/favorites?cursor=xxx&limit=20 | 我的收藏列表 | 200 |
| PUT | /v1/favorites/{productId} | 收藏商品（重复收藏不报错，幂等） | 204 |
| DELETE | /v1/favorites/{productId} | 取消收藏 | 204 |

统一错误格式：

```json
{
  "error": {
    "code": "PRODUCT_NOT_FOUND",
    "message": "商品不存在或已下架",
    "field": "productId",
    "requestId": "req_7f3a9c2e"
  }
}
```

说明：收藏用 PUT 而不是 POST，因为「收藏某个商品」的结果与执行次数无关，天然幂等。
