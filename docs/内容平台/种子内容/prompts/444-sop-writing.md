  【角色】你是一名做过质量管理体系和运营标准化的流程顾问。你写的 SOP 标准只有一条：一个第一次接触这项工作的新人，照着做就能做对。

  - 流程名称：[流程名称，如门店开店检查、客服退款处理]

  [粘贴现有做法]
  - 常出错的地方：[常见差错]
  - 涉及的系统 / 工具 / 表单：[系统与表单名称]
  - 需要符合的要求：[如食品安全、财务审批权限，没有写无]

  【任务】
  1. 先指出现有做法里缺失、矛盾或依赖「经验判断」的步骤，逐条向我确认（最多 5 个问题），确认前在文档中标【待确认】。
  2. 按以下结构写 SOP：
     - 文件信息：编号【待填】、版本 V1.0、生效日期、编制 / 审核 / 批准岗位；
     - 目的、适用范围（含不适用的情形）、术语定义；
     - 职责：每个岗位负责什么，用 RACI 简表；
     - 操作步骤：编号到二级（如 3.1、3.2），每步以动词开头、只写一个动作，写清「谁、在哪个系统、做什么、做到什么标准」；能量化的标准一律量化（时间、数量、温度、金额阈值）；
     - 关键控制点：容易出错或影响大的步骤用【检查点】标出，写明检查方法；
     - 异常处理：常见异常 → 判断条件 → 处理办法 → 上报给谁；
     - 相关记录表单与保存期限；
     - 修订记录表。
  3. 用 Mermaid flowchart 画出主流程，判断节点用菱形。
  4. 附一张可打印的「执行检查表」（勾选式）。

  - 涉及的法规或行业标准只提醒我去核对，不自行编造条款编号。

**怎么填变量**：[目前的做法] 不用整理，直接让老员工口述、录音转文字后粘进来就行；[常出错的地方] 是 SOP 价值最大的部分，问问最近半年的客诉、返工都出在哪一步。

**常见坑**：写成了「制度」而不是「操作手册」——满篇「应当」「负责」却没有具体动作。好的检验方法是写完让一个新人照做一遍，卡住的地方就是要补的步骤；也可以追问 AI「假设你是第一天上班的新人，照这份 SOP 做，哪一步你会不知道怎么办」。

**迭代追问**：需要上墙版说「压缩成 A4 一页的图文步骤卡」；流程变了就说「生成 V1.1，修订记录写明改了哪几步」。

### 示例输出

> 示例，仅供参考（流程：客服退款处理）

**3. 操作步骤**

3.1 客服在工单系统打开退款申请，核对订单号、支付金额、申请原因三项信息。
3.2 【检查点】退款金额 ≤ 200 元：客服直接审批；> 200 元：转组长审批，组长须在 2 小时内处理。
3.3 审批通过后，在系统点击「原路退回」，并给客户发送退款到账时间说明。

**异常处理**

| 异常 | 判断条件 | 处理 | 上报 |
|---|---|---|---|
| 重复申请 | 同一订单 24 小时内第二次申请 | 合并工单，回复客户进度 | 无需上报 |
