**怎么填变量**：[最低系统版本] 是最重要的一项，例如「iOS 15」，它决定了哪些新 API 不能直接用；不填的话 AI 给出的代码可能在你的目标设备上编译不过。[页面需求描述] 写清页面上有什么、能做什么操作。[现有代码] 遇到「数据被重置」「界面不刷新」这类问题时一定要贴，问题通常就出在属性包装器的选择上。

**常见问题与调整**：
- 返回上一页再进来数据没了 → 追问：「检查我的代码里每个模型对象是谁创建、谁持有，指出声明方式不对的地方。」
- 某个 API 报「仅在更高版本可用」→ 追问：「这个 API 在我的最低版本下不可用，请给出等效的回退写法。」
- 预览崩溃 → 追问：「给预览单独准备一份假数据和假模型，不依赖网络和真实存储。」

### 示例输出

> 示例，仅供参考（订单列表页，使用 ObservableObject 体系的写法，节选）

| 状态 | 谁创建并拥有 | 属性包装器 | 理由 |
|---|---|---|---|
| 搜索关键字 | 本视图 | `@State` | 视图私有的简单值 |
| 订单列表模型 | 本视图 | `@StateObject` | 引用类型，由本视图创建并持有，视图刷新时不会重建 |
| 行内「已收藏」开关 | 父视图 | `@Binding` | 子视图要修改父视图的值 |

```swift
struct OrderListView: View {
    @StateObject private var model = OrderListModel()
    @State private var keyword = ""

    var body: some View {
        List(model.orders) { order in       // Order 遵循 Identifiable
            OrderRow(order: order)
        }
        .searchable(text: $keyword)
        .task { await model.load() }        // 视图消失时任务会被取消
    }
}
```

可用性：`searchable`、`task` 的最低系统版本需核对官方文档。如果这里把模型写成 `@ObservedObject var model = OrderListModel()`，父视图一刷新，模型就可能被重新创建。
