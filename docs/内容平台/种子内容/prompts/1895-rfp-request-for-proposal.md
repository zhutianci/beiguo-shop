prompt: |
  【角色】你是企业采购部的资深采购经理，负责为一次软件或服务采购起草征求建议书（RFP）。你的目标是：收回来的几份应答能放在一张表里逐项对比。
  【背景】
  - 要采购的内容：[采购内容]
  - 业务背景与要达成的目标：[业务背景与目标]
  - 已经梳理的需求：[需求清单]
  - 预算范围与时间要求：[预算与时间要求]
  - 评选小组成员：[评选小组]
  【任务】按下面的结构起草。
  1. 项目背景与目标：让供应商明白我们要解决什么业务问题。
  2. 需求说明：把需求分为「必须满足」「期望满足」「加分项」三级并逐条编号。需求写「要达到什么效果」，不指定实现方式；带有品牌或排他倾向的写法请提醒我。
  3. 供应商应答要求：
     - 逐条应答表：对每条需求只能选「满足 / 部分满足 / 需定制开发 / 不满足」，并填写说明；
     - 公司资质与同类案例（写明案例的行业、规模、可否联系核实）；
     - 实施方案与项目团队（核心成员履历与投入比例）；
     - 服务与支持（响应时限、升级路径）。
  4. 报价格式：统一分项——软件许可或订阅、实施服务、定制开发、培训、年度运维；区分一次性费用与持续性费用；要求列出三年总成本和报价未包含的内容。
  5. 评分标准：列出评分维度与权重，合计 100 分，并说明价格分的计算办法。权重我没给时提供一套建议值，标明「待评选小组确认」。评分标准要在发出 RFP 之前定稿。
  6. 时间表：发出、书面答疑截止、统一答复、应答截止、演示、结果通知。任何一家的提问与答复都同步给全部参与方。
  7. 演示要求：供应商按我方给定的 2–3 个业务场景演示，不做自由发挥的产品介绍。
  【约束】
  - 是否披露预算由我决定，默认不写具体金额。
  - 我没有提供的需求不要自行添加；你认为可能遗漏的，放在文末「建议补充的需求」里单列。
  - 文末提醒我核对本单位的采购或招投标制度是否有强制流程。
  【输出格式】RFP 正文 → 附件一：逐条应答表模板 → 附件二：报价表模板 → 附件三：评分表 → 建议补充的需求。

**怎么填变量**：[需求清单] 贴业务部门整理的原始需求即可，模型会分级并改写成「要达到什么效果」。[预算与时间要求] 包括希望什么时候定下供应商、什么时候上线。[评选小组] 写清有哪些部门参与，评分维度会参考他们各自的关注点。

**常见失败与调整**：
- 让供应商自由发挥写方案。收回来三份格式完全不同的文件，根本没法比。逐条应答表和统一报价表是 RFP 里最有用的两页。
- 评分标准等应答收回来才定。很容易变成先看中某一家，再凑权重。
- 需求照着某个产品的功能清单写。等于提前选定了供应商，其他家会直接放弃或陪跑。
- 报价只要一个总价。第二年才发现年费和接口开发另算，所以要求列三年总成本和未包含项。

### 示例输出

> 示例，仅供参考（虚构：某连锁口腔诊所采购客户预约与回访系统）

**需求说明（节选）**

| 编号 | 级别 | 需求 |
|---|---|---|
| M-01 | 必须满足 | 患者可通过手机自助预约、改约、取消，前台实时看到变更 |
| M-02 | 必须满足 | 支持 15 家门店分别管理医生排班，总部可查看全部门店 |
| E-01 | 期望满足 | 就诊后按治疗项目自动生成回访任务并提醒到责任护士 |
| P-01 | 加分项 | 提供与现有收费系统对接的成熟方案 |

**逐条应答表模板**

| 需求编号 | 满足 / 部分满足 / 需定制开发 / 不满足 | 说明 | 定制所需工期与费用 |
|---|---|---|---|

**评分表（建议值，待评选小组确认）**

| 维度 | 权重 |
|---|---|
| 需求满足度（按逐条应答表与演示核实） | 35 |
| 实施方案与团队 | 20 |
| 同类案例与核实结果 | 15 |
| 三年总成本 | 20 |
| 服务与支持 | 10 |
| 合计 | 100 |
