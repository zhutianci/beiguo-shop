**这个顺序的依据**：Google AI 开发者文档的「提示词设计策略」针对 Gemini 3 系列给了几条建议（资料核对于 2026-10-10）：
- **直接、简洁地说明目标**，不需要长篇的劝说式措辞；
- **结构要一致**：用 XML 风格的标签或 Markdown 标题来分区都可以，但一份提示词里只选一种——所以这个模板通篇只用 Markdown 标题；
- **关键内容放前面**：角色、约束、输出格式放在系统指令或提示词的开头；
- **长上下文时材料在前、问题在后**：先给完所有材料，把具体指令或问题放在最后，并用「根据以上信息」这类话衔接；
- **需要详细就明说**：Gemini 3 默认倾向直接、简短的回答，想要展开论述要在指令里写出来。

官方还建议 Gemini 3 保持默认的采样参数，不要随手把 temperature 调低，否则可能出现循环或推理质量下降——通过 API 使用时注意这一点。

**怎么填变量**：[详细程度要求] 是这条模板里最常被忽略、对 Gemini 又最有用的一项，嫌回答太短时优先改这里，而不是加「请详细回答」这种笼统的话。[输出格式] 写成能照着检查的样子，如「三级标题 + 每节一段 + 最后一张对比表」。没有材料时删掉「材料」一节，把背景写进「任务」。

**想要稳定的格式时**：在「输出格式」后面加一两个完整示例。官方文档建议尽量在提示词里包含少量示例，并保持示例之间格式一致。

**常见问题与调整**：
- 回答涉及最近的事却用了旧信息 → 在「约束」里加一行「今天是 [今天日期]」，并开启搜索（Grounding）功能。
- 把这个模板长期复用 → 把「角色、约束、输出格式」三节放进 Gemini 的自定义技能（Skills，原 Gems）指令里，每次只发材料和任务。

### 示例输出

> 示例，仅供参考（角色：社区活动策划；任务：根据往届反馈提出今年改进点；输出格式：三条改进，各含依据与做法）

**改进一：报名改为分时段入场**
依据：材料中 14 条反馈提到「排队超过半小时」，集中在上午 9–10 点。
做法：报名表增加时段选择，每个时段限 80 人；现场设两个签到口。

**改进二：增加儿童活动区**
依据：材料显示带孩子的家庭占报名人数约四成，但往届没有专门区域。
做法：划出一块 30 平方米的场地，安排两名志愿者。

**材料外信息**：场地是否允许搭建临时围栏，材料中没有说明，需要向场地方确认。
