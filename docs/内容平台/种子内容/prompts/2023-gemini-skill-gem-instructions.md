  我想在 Gemini 里创建一个可重复使用的技能（Skill），请帮我把它的名称、描述和指令写出来。

  第二步：输出技能内容（等我回答后）

  2. 描述：一两句话，明确写出「当用户……时使用」，让它能判断何时该自动调用，同时写出一个不适用的情形。

  4. 整份指令保持简短，控制在 [指令长度] 字以内。

**Gems 还是 Skills**：按 Google 帮助中心和官方博客，Gemini 的 Gems 正在分批换成 Skills（技能），个人账号的 Gems 到期会自动转为技能，具体时间表以官方通知为准。现在新建可复用指令，建议直接用技能；手动创建时需要填写名称、描述和指令，技能名要求全小写、用连字符分隔。详细步骤见本站「Gemini 使用技巧」教程。（资料核对于 2026-10-10）

**三条官方建议，模板都对应上了**：Google 对写好一个技能的建议是——写清楚什么情况下该用它；只写这个任务特有的要求，保持简短；给出期望输出的具体示例。所以模板里「描述」强调触发条件，「步骤」要求只写特有要求，最后必须带一个完整示例。

**怎么填变量**：[现在的做法] 尽量写成步骤，哪怕很啰嗦，例如「先看上周的周报，把没做完的挪过来，再按项目分组，每项写一句结果」。[满意的产出样例] 是决定质量的关键，没有就先手动做一次再回来。[指令长度] 建议 400–800 字。

**常见问题与调整**：
- 技能该触发时没触发 → 多半是描述写得太抽象。把描述改成用户会说的话，如「当用户贴出一周的工作记录并要求整理周报时使用」。
- 不该触发时乱触发 → 在描述里补上不适用的情形。
- 用了一阵想改进 → 把不满意的那次输入输出贴给 Gemini：「这是技能的一次失败案例，请修改指令中最相关的一条，并说明改动。」
- 仍在使用 Gems 的账号 → 指令正文可以原样粘贴到 Gem 的指令框里，名称格式不受上述限制。

### 示例输出

> 示例，仅供参考（任务：把一周的零散工作记录整理成周报；节选）

**技能名称**：weekly-report

**描述**：当用户贴出一周的工作记录、聊天摘录或待办清单，并要求整理成周报时使用。不用于月报、项目总结或代写未发生的工作。

**指令正文（节选）**
目标：把零散记录整理成一份领导两分钟能看完的周报。
步骤：
1. 按项目归类，而不是按日期罗列；
2. 每项写「做了什么 + 结果或进度」，有数字的保留数字；
3. 单列「需要支持的事」，没有就省略这一节。
信息不足时：记录里出现「跟进了」「沟通了」但没有结果的，先问我结果是什么，因为没有结果的条目领导会追问。
输出格式：三节（本周进展 / 下周计划 / 需要支持），总长不超过 300 字。
