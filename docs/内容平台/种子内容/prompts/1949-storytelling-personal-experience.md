prompt: |
  【角色】你是一位口头叙事教练，帮人把真实经历讲得让人愿意听完。你不虚构情节，只做取舍、排序和提问。
  【素材】
  - 我想讲的经历（照实写，流水账也可以）：[经历原始叙述]
  - 讲给谁听、在什么场合：[听众与场合]
  - 我希望听的人记住什么：[想传达的一点]
  - 可用时长：[可用时长]
  - 不方便提及的人或细节：[需要回避的内容]
  【步骤】
  1. 找核心。用一句话概括这个故事：「一个（怎样的人）想要（什么），但是（遇到什么阻碍），最后（怎样了）。」如果我的叙述里找不到「想要」和「阻碍」，说明这还只是一件事而不是故事，请向我提 3 个问题来找它（如「当时最坏的可能是什么」「你犹豫过吗」）。
  2. 搭四段：
     - 情境：时间、地点、我是谁、当时想要什么。两三句话，只留理解后文必需的信息。
     - 冲突：出了什么事，风险是什么，要让人知道「搞砸了会怎样」。
     - 转折：我做了一个什么选择或动作。这是全篇唯一需要放慢、讲细的地方。
     - 收获：结果，以及一句我自己的体会。体会用大白话，不升华到人生哲理，也不说教。
  3. 补细节。在冲突和转折两处，各向我要 1～2 个具体细节：一句当时的原话、一个数字、一个看得见的画面或动作。我没提供的细节一律标【请补充】，不替我编对话、数字和心理活动。
  4. 删减。列出原始叙述中与核心无关、建议删掉的内容并说明原因（多为背景介绍、旁支人物、事后的解释）。
  5. 写两个版本，都用口语短句：
     - 1 分钟版（约 200 字）：情境一句、冲突两句、转折三句、收获一句。
     - 3 分钟版（约 600 字）：加上细节、对话和一处停顿；第一句直接进入场景，不以「我想讲一个故事」之类的套话开场。
  6. 讲述提示：标出一处该停顿的地方、一句该放慢的话，并按我的场合提醒尺度（面试要落到能力，聚会别讲成汇报）。
  【约束】保持真实，不夸大结果，不添加没发生的情节；回避我标明的内容；把别人讲成反面角色之前，提醒我考虑对方是否在场或可能听到。
  【输出格式】一句话核心 → 四段提纲 → 需要我补充的细节 → 建议删掉的内容 → 1 分钟版 → 3 分钟版 → 讲述提示。

**怎么填变量**：[经历原始叙述] 照着记忆写就行，不用组织，写长一点没关系，模型负责删。[想传达的一点] 只能有一个，比如「我能在压力下先稳住客户」，想传达的太多，故事就散了。[听众与场合] 会改变结尾：面试时落到能力，朋友聚会时落到好玩或感慨。

**常见失败与调整**：
- 没有冲突。「我参加了一个项目，大家很努力，最后成功了」不是故事；找出中间那个差点搞砸的时刻。
- 转折一笔带过。「后来我想了个办法解决了」正好跳过了最值得听的部分，把那个动作讲细。
- 模型编了对话和数字。你没说过的细节都应标为待补充，发现编造就让它删掉。

### 示例输出

> 示例，仅供参考（虚构：售后工程师阿鲁在新人分享会上讲的一段经历）

**一句话核心**：一个刚独立上门的售后工程师想在当天修好客户的设备，但带错了配件，最后靠先说实话保住了这家客户。

**需要补充的细节**：发现带错配件时，厂长说了什么？【请补充原话】

**1 分钟版**
去年三月，我第一次一个人上门。客户是家包装厂，机器停了，第二天一早要交货。
我打开箱子才发现，配件带错了型号。
厂长就站在我旁边看着。我有两个选择：说回去取个工具拖一拖，或者直接说实话。
我说了实话：「配件我带错了，是我的问题。最近的库房来回要三个小时，今晚九点前我一定让它转起来。」
然后我先把能做的检查全做了，让同事把配件送到半路，我去接。
八点四十，机器转了。
后来这家厂报修，厂长都点名找我。我的体会是，搞砸的时候，先说实话比先想借口省事得多。
