prompt: |
  你是一位熟悉价值主张设计（Value Proposition Design）方法的产品与市场顾问。请带我完成一张价值主张画布，并像一个严格的评审一样检查匹配度。

  目标客户细分：[客户细分]
  我们的产品 / 服务：[产品服务]
  已掌握的客户信息（访谈、反馈、数据）：[客户信息]
  产品主要功能：[主要功能]

  一、客户概况（右侧圆形）
  1. 客户任务（Jobs）：功能性任务、社交性任务、情感性任务各 2–4 条，写成「客户想要……」。
  2. 痛点（Pains）：完成任务时的障碍、风险、不想要的结果，每条按严重程度标「高 / 中 / 低」。
  3. 收益（Gains）：客户期望或惊喜的结果，按重要性标「必需 / 期望 / 惊喜」。
  每条注明依据：来自我提供的信息，还是你的推测（推测项标「待验证」）。

  二、价值地图（左侧方形）
  4. 产品与服务：列出我们提供的内容。
  5. 止痛方案（Pain Relievers）：每条对应一个具体痛点。
  6. 增益方案（Gain Creators）：每条对应一个具体收益。

  三、匹配度检查
  7. 用表格连线：痛点 / 收益 ↔ 对应方案，标出：已解决 / 部分解决 / 未解决。
  8. 指出三类问题：高严重度痛点却无方案；我们投入很多但客户不在乎的功能；仅凭推测、急需验证的假设。
  9. 给出 3 个最值得验证的假设，以及最便宜的验证方式（访谈问题、落地页测试、原型测试）。

  四、价值主张语句
  10. 用「我们的【产品】帮助【客户细分】在【任务】时，通过【止痛 / 增益】，【减少痛点 / 获得收益】」句式写 3 版。

**怎么填变量**：[客户信息] 越真实越好，访谈记录、客服聊天、差评都可以贴进来；没有资料时 AI 只能推测，所有推测都会被标成「待验证」，这本身也是一个有用的输出。[客户细分] 一次只填一类客户，多类客户请分别做画布。

**常见坑**：
- 客户任务写成「使用我们的产品」——客户的任务是他自己要完成的事，和你的产品无关；
- 价值地图里的功能清单很长，但匹配检查发现一半功能对不上任何痛点，这正是这个工具的价值所在；
- 画布做完不验证：第 9 步给出的假设和验证方式要真的去做。

**迭代追问**：「为第 2 类客户细分再做一张画布，并比较两者的差异」「根据未解决的痛点，提出 3 个产品改进方向，并用 RICE 打分」「把价值主张语句改写成落地页首屏文案」。

### 示例输出

> 示例，仅供参考（虚构：面向自由职业设计师的报价与收款工具）

**痛点（节选）**
| 痛点 | 严重度 | 依据 |
|---|---|---|
| 报价后客户反复压价，不知道怎么解释价格 | 高 | 访谈 6 人中 5 人提到 |
| 尾款拖欠，催款很尴尬 | 高 | 访谈 + 社群讨论 |
| 开发票流程复杂 | 中 | 待验证 |

**匹配度检查**：「尾款拖欠」目前只有提醒功能，属于部分解决；产品投入较多的「作品集模板」没有对应任何高严重度痛点。
