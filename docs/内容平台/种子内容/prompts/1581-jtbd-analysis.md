prompt: |
  你是一名熟悉 JTBD 方法的产品战略顾问。你常说的例子是：用户不是想买一个电钻，而是想在墙上挂一幅画；所以竞争对手不只是别的电钻，还有无痕钉和请师傅。

  产品 / 服务：[产品或服务]
  用户信息来源（访谈记录、换用原因、评价、客服记录）：[用户信息]
  用户在使用我们之前的做法：[之前做法]
  我们知道的用户转换时刻（什么事件让他开始找新方案）：[转换时刻]

  请完成：
  1. Job 陈述：写出 3–5 个核心任务，格式为「当【情境】时，我想要【动机】，以便【期望结果】」。区分功能性任务、情感性任务、社会性任务。
  2. 转换时间线：用户从「第一次意识到问题」到「开始使用我们」经历了哪些阶段（首次想法 → 被动寻找 → 主动寻找 → 决定 → 首次使用 → 持续使用或放弃），每个阶段发生了什么。
  3. 四力分析：
     - 推力（Push）：现状中让用户不满、推动改变的因素；
     - 拉力（Pull）：新方案吸引用户的地方；
     - 焦虑（Anxiety）：对新方案的担心（学不会、浪费钱、数据迁移）；
     - 习惯（Habit）：让用户留在旧方案的惯性。
     每一项列出具体内容，并标注证据来源。
  4. 竞争替代方案：用户为完成同一个任务可能「雇佣」的所有方案（包括非同类产品、手工方法、什么都不做），比较它们在这个任务上的优劣。
  5. 启示：
     - 产品：如何降低焦虑与打破习惯（如迁移工具、免费试用、模板）；
     - 营销：在用户「转换时刻」用什么信息出现；
     - 新机会：被现有方案服务得不好的任务。
  约束：基于提供的证据，推测要标注；Job 陈述不写成产品功能。

**怎么填变量**：[用户信息] 最有价值的是「换用故事」——用户从旧方案换到你的产品时，具体发生了什么。可以问老用户：「你是哪一天开始找新的办法的？那天发生了什么？」[转换时刻] 写出你知道的触发事件，比如「公司来了第一个全职员工，需要发工资」。

**常见坑**：
- Job 陈述写成「我想要一个好用的记账 App」，这是产品，不是任务；
- 只看同类竞品，忽略了用户最常用的替代方案（比如 Excel 或「找会计朋友帮忙」）；
- 只关注拉力（我们的功能多好），忽略了焦虑和习惯，这往往是用户迟迟不转换的真正原因。

**迭代追问**：「根据四力分析，重写我们落地页的首屏文案」「为降低用户的焦虑，设计 3 个产品或服务改进」「设计一份 JTBD 访谈提纲，用于下一轮用户研究」。

### 示例输出

> 示例，仅供参考（虚构：小团队在线排班工具）

**Job 陈述**：当店里突然有员工请假时，我想要在几分钟内找到能顶班的人，以便门店正常营业而我不用自己顶上。

**四力分析（节选）**
| 力 | 内容 | 来源 |
|---|---|---|
| 推力 | 在微信群里一个个问谁能来，常常问了半小时没人回 | 访谈 4 人提到 |
| 焦虑 | 员工都是兼职，担心他们不愿意装新软件 | 访谈 3 人提到 |
| 习惯 | 排班表已经在 Excel 里用了 3 年 | 访谈 |

**产品启示**：员工端无需下载 App，通过链接即可查看和认领班次，直接回应「焦虑」。
