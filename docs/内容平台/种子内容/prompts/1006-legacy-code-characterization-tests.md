**怎么填变量**：[这次要做的修改] 要具体，表征测试的覆盖重点会围绕这次修改涉及的分支展开。依赖的外部资源写全，AI 才能判断哪些地方需要先「开接缝」。

**常见坑**：
- 最大的误区是「顺手把看起来不对的地方都改掉」。遗留代码里的奇怪行为常常有下游在依赖，这一步只记录、不修改，确认没人依赖后再单独处理。
- AI 推测的期望值不一定是代码真实的输出，尤其涉及浮点数、字符串格式、排序时。模板要求「以实际运行结果为准」，第一次运行时把失败的断言改成实际值即可。
- 为了可测而做的接缝改造本身也有风险，改完先跑一遍原有的手动验证流程。

**追问技巧**：表征测试跑通后追问「还有哪些输入组合没有覆盖，按风险排序」；准备重构时追问「在不改变这些测试结果的前提下，第一步最安全的重构是什么」。

### 示例输出

> 示例，仅供参考（节选：老的运费计算函数直接调用了当前时间）

**疑似 Bug，先保留**：重量为 0 时返回 12 元（首重运费），而不是 0。可能有业务依赖，先用测试锁住。

**接缝**：函数内部调用了 `LocalDate.now()`，改为增加一个带 `Clock` 参数的重载，原方法调用它并传入系统时钟，行为不变。

```java
private final ShippingCalc calc =
    new ShippingCalc(Clock.fixed(Instant.parse("2026-03-01T00:00:00Z"), ZoneOffset.UTC));

@Test
void 重量为零时按首重收费_现有行为() {
    assertEquals(new BigDecimal("12.00"), calc.fee(BigDecimal.ZERO, "上海"));
}

@Test
void 偏远地区加收_现有行为() {
    // 期望值以第一次运行的实际输出为准
    assertEquals(new BigDecimal("30.00"), calc.fee(new BigDecimal("2.5"), "新疆"));
}
```
