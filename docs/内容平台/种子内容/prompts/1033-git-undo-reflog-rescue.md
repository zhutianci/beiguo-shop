**怎么填变量**：[执行过的命令] 尽量准确，可以用终端的历史记录查。[相关提交是否已经推送到远程] 和 [这个分支是否有其他人在用] 决定了能不能改写历史，是最关键的两个信息。

**常见坑**：
- 遇事先 `reset --hard`，结果把还没提交的改动也丢了。工作区里从未提交过的改动，Git 是无法帮你找回的。
- 已经推送到公共分支的提交，用 reset 加强制推送撤销，会打乱其他人的本地仓库。公共分支用 revert。
- 以为提交「消失」了就是没了。只要提交过，本地的 reflog 通常会保留一段时间（具体期限由配置决定），可以找回。

**追问技巧**：不确定当前状态时，先把 `git status`、`git log --oneline --graph -n 20`、`git reflog -n 20` 三条命令的输出都贴给 AI，它能更准确地判断。

### 示例输出

> 示例，仅供参考（情况：执行了 git reset --hard HEAD~2，丢了两个本地提交，未推送）

**判断**：可以恢复。被 reset 掉的两个提交仍在 reflog 中。

```bash
git branch backup-before-rescue          # 1. 先备份当前位置
git reflog -n 10                          # 2. 找到 reset 之前的记录
# 输出类似：
# a1b2c3d HEAD@{0}: reset: moving to HEAD~2
# 9f8e7d6 HEAD@{1}: commit: 完成优惠券校验
git reset --hard 9f8e7d6                  # 3. 回到 reset 之前的提交
git log --oneline -n 5                    # 4. 确认两个提交已回来
```

注意第 3 步的 `--hard` 会丢弃当前工作区未提交的改动，执行前先用 `git status` 确认工作区是干净的。

**以后怎么避免**：执行 reset 之前先 `git branch backup` 留一个书签。
