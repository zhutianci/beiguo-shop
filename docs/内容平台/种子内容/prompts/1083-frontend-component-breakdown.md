**怎么填变量**：[页面描述] 按区块写清楚：每块显示什么、有哪些操作、操作后会影响哪些区块。例如「顶部筛选栏修改后，列表刷新并回到第一页；点击某行在右侧抽屉显示详情，抽屉中修改后列表对应行更新」。

**常见坑**：
- 把接口返回的数据复制到全局状态里再手动同步，数据不一致的问题层出不穷。服务端数据交给数据请求库管理。
- 筛选条件和页码放在组件内部状态，刷新页面就丢失，也没法把链接分享给同事。
- 为了「以后可能复用」，把业务组件抽象成一堆配置项，最后谁都不敢改。先在业务里用起来，出现第二、第三次重复时再抽象。

**追问技巧**：设计确认后追问「按这个设计生成组件骨架代码，每个组件只写 Props 类型和结构，不写样式」，再逐个填充。

### 示例输出

> 示例，仅供参考（订单列表页，节选）

```
OrderListPage                 页面容器：读取地址栏查询参数，组合各区块
├─ OrderFilters               筛选栏：修改后更新查询参数并重置页码
├─ BatchActionBar             批量操作：仅在有选中项时显示
├─ OrderTable                 表格：展示数据、行选择
│  └─ OrderStatusTag          状态标签（通用，可放入组件库）
├─ Pagination                 分页：读写查询参数中的页码
└─ OrderDetailDrawer          详情抽屉：根据查询参数中的订单编号加载详情
```

| 状态 | 类型 | 位置 | 读取者 | 修改者 |
|---|---|---|---|---|
| 筛选条件、页码 | 地址栏状态 | 查询参数 | 页面容器、列表请求 | 筛选栏、分页 |
| 订单列表数据 | 服务端数据 | 数据请求缓存 | 表格 | 批量操作成功后使缓存失效 |
| 选中的行 | 界面状态 | 页面容器 | 表格、批量操作栏 | 表格 |
| 当前查看的订单编号 | 地址栏状态 | 查询参数 | 详情抽屉 | 表格行点击 |
