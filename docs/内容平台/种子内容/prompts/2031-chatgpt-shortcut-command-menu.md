prompt: |
  在这个对话里，请把我发的以斜杠开头的消息当作快捷命令，按下面的命令表执行。命令后面跟着的内容，或我紧接着贴的内容，就是要处理的对象。

  通用规则：
  - 直接输出结果，不要复述命令、不要寒暄、不要在结尾问「还需要什么」。
  - 只做这条命令规定的事，不顺手做别的（例如 /翻译 时不要润色原文观点）。
  - 我的身份是 [我的身份]，默认读者是 [默认读者]，用词深浅按这个来。
  - 原文里的数字、人名、日期、专有名词保持原样；不确定的地方用「【?】」标出，不要猜。
  - 命令可以叠加，按从左到右的顺序执行，例如「/总结 /英」表示先总结再译成英文。
  - 不认识的命令：回复「没有这条命令」，并列出命令表。

  命令表：
  - /总结：用 [总结条数] 条要点概括，每条不超过 30 字，按重要性排序；最后一行写「一句话结论：……」。
  - /改写：保持原意，改成 [常用文风] 的文风；附一行说明主要改了什么。
  - /缩：压缩到原文一半左右的长度，保留全部数字和结论。
  - /扩：扩写到约两倍长度，只展开已有观点，不添加新的事实。
  - /英：译成自然的英文；/中：译成自然的简体中文。术语保留原文并在首次出现时括注。
  - /表格：把内容整理成 Markdown 表格，自行确定合适的列；无法归入表格的信息列在表格下方。
  - /找茬：以挑剔的审稿人身份，列出最多 5 个问题（逻辑漏洞、事实存疑、表达不清），按严重程度排序，每个问题给出修改建议；不要夸奖。
  - /待办：从内容中提取待办事项，输出「事项 | 负责人 | 截止时间」，原文没写的填「未提及」。
  - /回复：替我起草一条回复，语气 [回复语气]，不超过 [回复字数] 字；给出两个版本：一个直接，一个委婉。
  - /解释：用 [默认读者] 能听懂的话解释这段内容，先一句话说明它是什么，再举一个生活中的例子。
  - /帮助：列出以上命令及一句话说明。

  收到这段话后，只回复「命令已就绪」和命令清单，不要做其他事。

**怎么用**：这是一份「个人指令大全」的做法——与其收藏一百条提示词每次去翻，不如把自己最常用的十来条固化成短命令。三种放法：

1. **单次对话**：把整段发在对话开头，之后在这个对话里用命令。对话很长以后它可能逐渐不那么守规矩，新开一个对话重发即可。
2. **项目指令**：在 ChatGPT 的项目（Projects）里把这段粘贴为项目指令，该项目下每个新对话都自带这些命令，适合固定的工作场景。
3. **自定义指令**：放进 设置 → 个性化 → 自定义指令 后对所有对话生效，但要注意字符上限，且会影响所有对话——建议只保留最常用的三四条命令。

（另外，在部分界面里，输入框中打出斜杠可能会唤出官方的工具菜单；这里的中文命令只是普通文字约定，和它没有关系，照常输入并发送即可。界面以实际为准。）

**怎么填变量**：[常用文风] 如「简洁的商务书面语」；[回复语气] 如「礼貌但不卑微」；[默认读者] 如「不懂技术的业务同事」。命令表可以随意增删——把你发现自己第三次重复输入的要求，加成一条新命令。

**设计命令的三个要点**：
- 每条命令写清「输出长什么样」，而不只是动作。「/总结」后面跟着条数、字数和排序规则，结果才会每次一致。
- 写清「不做什么」。模型的默认倾向是多做一点，命令越短越需要边界。
- 命令名用你自己顺手的词，不必拘泥于示例。

**常见问题与调整**：
- 执行命令后又加了解释 → 回复：「以后严格按通用规则第一条。」多数情况一次就能纠正。
- 想临时改规则 → 直接在命令后补充，如「/总结 这次要 8 条」。
- 换成其他模型使用 → 这段命令表不依赖 ChatGPT 的特有功能，贴到别的对话模型里同样可用。
