prompt: |
  请你同时扮演一个需求评审会上的五个角色，帮我做会前演练：
  - 后端 / 前端研发负责人：关心可行性、接口、数据、性能、工作量；
  - 测试负责人：关心边界条件、异常流程、验收标准是否可测；
  - 设计师：关心用户流程、交互细节、状态；
  - 运营 / 客服：关心上线后的运营动作、用户会问什么；
  - 业务负责人：关心目标、优先级、投入产出。

  我的需求文档（或要点）：
  [需求文档]
  项目背景与目标：[项目目标]
  计划的上线时间：[上线时间]
  我担心的地方：[我的担心]

  请完成：
  1. 每个角色提出 4–6 个最可能在评审会上问的问题，按「如果答不上来会卡住评审」的程度排序。
  2. 对每个问题，判断我的需求文档中是否已有答案：
     - 已有：指出位置；
     - 部分有：说明缺什么；
     - 没有：给出我需要补充的内容方向。
  3. 逻辑漏洞清单：需求中前后矛盾、范围不清、验收标准不可测、依赖没写清楚的地方。
  4. 范围建议：如果时间紧，哪些内容可以拆到二期，并说明理由。
  5. 评审议程（45–60 分钟）：背景与目标（5 分钟）→ 核心流程走查 → 重点讨论问题 → 排期与分工 → 待办确认；标出需要会上拍板的问题。
  6. 会后跟进模板：评审结论、修改点、负责人、截止时间。
  约束：问题要具体到我的需求，而不是泛泛的「性能怎么样」；不替我做业务决策，只指出需要决策的地方。

**怎么填变量**：[需求文档] 直接粘贴 PRD 全文或核心章节即可。[我的担心] 写出你心里没底的地方，比如「不确定第三方支付回调失败时怎么处理」，AI 会重点围绕这里提问。

**常见坑**：
- 评审会上被研发问到「这个数据从哪来」答不上来，整个评审只能延期；
- 验收标准写成「体验流畅」「加载快」，测试没法测；
- 需求范围在会上不断被加，最后排期失控——会前就要想好哪些可以放到二期。

**迭代追问**：「根据这些问题，帮我修改 PRD 中缺失的部分」「把逻辑漏洞清单中的第 1 条展开成完整的异常流程说明」「为评审会写一页开场的背景与目标讲稿」。

### 示例输出

> 示例，仅供参考（虚构需求：电商 App 新增「预售」功能）

| 角色 | 问题 | 文档中是否有答案 |
|---|---|---|
| 研发 | 定金和尾款是两笔独立订单还是一笔订单的两次支付？ | 没有：需要明确订单模型 |
| 测试 | 用户付了定金后没付尾款，定金退不退？什么时候关闭订单？ | 部分有：缺少超时时间 |
| 客服 | 预售商品可以申请七天无理由退货吗？从什么时候开始算？ | 没有：需要和法务、平台规则确认 |

**需要会上拍板**：定金是否可退，以及尾款支付的截止时间。
