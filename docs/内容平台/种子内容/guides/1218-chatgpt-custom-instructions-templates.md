> 本文根据 OpenAI 帮助中心《Custom Instructions in ChatGPT》整理，资料核对于 2026-10-28。**官方文章没有给示例指令，**第三节的 10 套模板是本站自拟，供你改写，不是官方模板，也不代表实测效果。配图为本站整理的示意图，不是界面截图。自定义指令的整体介绍见 [/guides/chatgpt-custom-instructions](/guides/chatgpt-custom-instructions)。

## 适用于谁

- 想让 ChatGPT 每次都按自己的习惯回答（简短、中文、先给结论）的人；
- 不知道自定义指令该怎么写的人；
- 想知道字数上限、怎么关闭的人。

## 结论先说

1. **设置路径**（官方）：网页和桌面版 **设置 → Personalization**；手机 **设置 → Customize ChatGPT**。先打开 **Enable customization**，再在 **Custom Instructions** 里写内容。
2. **字符上限**：**Free 和 Go 是 1,500 字符**；**Plus、Pro、Business、Enterprise、Education 是 5,000 字符**。所有套餐、所有平台（网页、桌面、iOS、Android）都有这个功能。
3. **写短、写具体、写可执行的**：Free 和 Go 只有 1,500 字符，下面每套模板都控制在这个范围内，可以直接用。
4. **关闭**：把 **Enable customization** 关掉，可选再清空文字。
5. **隐私**：官方说指令不会被分享链接的查看者看到；指令包含在数据导出里；账号删除时，关联的指令在 30 天内删除。**不要在里面写密码、证件号等敏感信息。**
6. **官方对「是否影响已有对话」的说法不一致**，所以改完后，在**新对话**里观察效果最稳。

## 一、写指令的几条原则（本站经验，不是官方要求）

1. **一条指令只管一件事**：比如「先给结论」「不确定要说明」；
2. **用动作词**：「用中文回答」「列出三点」比「请专业一些」更容易被执行；
3. **别互相打架**：一边要「尽量详细」，一边要「尽量简短」，效果会不稳定；
4. **留出例外**：加一句「我明确要求时，以我的要求为准」；
5. **定期删**：用一段时间后，把不再需要的条目删掉，免得占字数。

## 二、先看官方的数据处理说明

官方文章写的几点：你可以随时编辑或删除指令，只影响以后的对话；指令不会给分享链接的查看者看到；第三方插件可能收到你指令里的相关信息；指令数据可能用于改进模型，你可以通过官方文章里链接的方式退出，见 [/guides/chatgpt-data-controls-privacy](/guides/chatgpt-data-controls-privacy)；想从以前的聊天里去掉指令的影响，要清除那些对话。官方还说**没有自定义指令的 API**，要类似效果可以用 Chat Completions API 的 system 消息。

## 三、10 套可复制的模板（本站自拟）

下面每套都是纯文字，放进 **Custom Instructions** 里即可，可按需删改。**带 [ ] 的地方请换成你自己的内容。**

### 1. 简洁直接

```
先给结论，再给理由。
默认控制在 200 字以内，除非我要求详细。
不要客套话和重复我的问题。
我明确要求时，以我的要求为准。
```

### 2. 中文写作润色

```
用简体中文回答。
润色时保留我的原意和语气，只改病句、啰嗦和不通顺的地方。
先给修改后的版本，再用三条以内列出主要改动。
不要擅自增加我没写的事实。
```

### 3. 学习辅导

```
我在学习[科目]，水平是[初学/进阶]。
先用最简单的话解释，再给一个生活里的例子。
讲完后问我一个小问题检查是否理解。
不要直接给作业答案，先给思路。
```

### 4. 编程助手

```
我主要用[语言]，运行环境是[系统/版本]。
先说明思路，再给可运行的完整代码。
关键代码加简短注释。
不确定的版本差异要明确说出来，不要编造不存在的函数。
```

### 5. 工作邮件与汇报

```
我的身份是[职位]，对象通常是[同事/客户/领导]。
邮件和汇报用正式但不生硬的语气，先说结论或请求，再说背景。
每次给我一版简短的和一版完整的。
不要使用夸张的形容词。
```

### 6. 翻译

```
默认在中文和英文之间互译。
译文要自然，不要逐字翻译，保留原文的语气。
遇到专有名词或有歧义的地方，在译文后用一行说明。
```

### 7. 资料核对与研究

```
回答事实性问题时，区分「确定的」和「不确定的」。
不确定时直接说不确定，不要编造来源或数据。
需要最新信息时，说明需要联网查证。
给出结论时附上你的依据。
```

### 8. 比较与决策

```
我让你比较方案时，用表格列出优缺点。
最后给出你的倾向和理由，并说明在什么情况下结论会反过来。
不要只说「看情况」。
```

### 9. 数据与表格

```
处理数据时，先说明你的步骤，再给结果。
表格用 Markdown，列名清楚，数字保留合理的小数位。
发现数据有缺失或异常，先告诉我，不要自行补全。
```

### 10. 文案创作（减少「AI 腔」）

```
写文案时多用具体的细节和短句。
少用「赋能」「打造」「全方位」这类空泛词。
每次给我三个不同风格的版本，并各用一句话说明风格。
```

## 四、用的时候注意

- **字数**：Free 和 Go 上限 1,500 字符，上面的模板每套都远低于上限，**可以叠加 2 到 3 套**，但要检查是否自相矛盾；
- **效果**：同一套指令在不同模型、不同任务里的效果可能不同，官方也没有承诺必然执行；
- **和别的功能的关系**：记忆见 [/guides/chatgpt-turn-off-memory](/guides/chatgpt-turn-off-memory)，项目里的指令是另一套，见 [/guides/chatgpt-projects](/guides/chatgpt-projects)；官方文章没有写它们如何叠加；
- **回答太啰嗦**：见 [/guides/chatgpt-too-wordy-answer-style](/guides/chatgpt-too-wordy-answer-style)；
- 想要更多额度和更长的指令（5,000 字符），可以看 [/chongzhi/chatgpt-plus](/chongzhi/chatgpt-plus)，具体以官方为准。

## 常见问题

**Q：1,500 字符是多少字？**
官方写的是字符数。中文一个汉字算一个字符，所以大约是 1,500 字以内，具体以输入框的计数为准。

**Q：改了指令，旧对话会变吗？**
官方说法不一致，建议在新对话里观察。

**Q：可以在里面写我的名字和职业吗？**
可以写你愿意让模型知道的信息，但不要写密码、证件号、银行卡等敏感信息。

**Q：怎么临时不用？**
关掉 Enable customization，或者用临时聊天，见 [/guides/chatgpt-temporary-chat](/guides/chatgpt-temporary-chat)。
