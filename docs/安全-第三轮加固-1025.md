# 第三轮安全加固（2026-10-25）

> 站长 10-25：攻击、恶意注册、模拟付款回调越来越多，要求「以企业级、银行级的标准」全面复查并升级，防止被爆破造成资金损失。
> 本文 = 线上证据 + 全项目复查结果 + 站长的取舍 + 实施与部署记录。前两轮见 `docs/安全-攻防加固设计-1015.md`、`docs/安全-第二轮加固-1024.md`。
> 时间一律北京时间；数据库与 nginx 日志里是 UTC。

## 一、线上证据（10-22 ～ 10-25，生产库 audit_events / users / nginx 安全日志）

- **恶意注册全是 Gmail「+」别名**：`irontmp+…`、`sisatmp+…`、`wipetmp+…`、`dueltmp+…`、`joykrissa+…@gmail.com`。注册是严格白名单，
  但 Gmail 在白名单里，一个收件箱能开无限个号；10-25 当天 10 个新号里 6 个是这类（都已被越权 / 探测计数自动封禁，没有下过单）。
- **爆破**：一个国内 IP 一天对 `/api/auth/reset-password` 打了 79 次（43 次 400 + 36 次 429）；`/api/external-orders/lookup/verify` 验证码、
  `/api/auth/login`、`/api/auth/send-code` 都有成批的 400 / 429。重置密码接口当时**不看 IP 封禁**。
- **越权试探**：`/api/orders/3380` 18 次、`POST /api/receipts` 58 次（别人的订单号）、`/api/pay/vmq/status` 收款单号枚举、带买家登录态打 `/api/admin/users`。
- **模拟付款回调**：43 次 / 37 个 IP 打在臆造的回调地址上（全被蜜罐接住、封 IP）；真实回调 `/api/pay/sms-notify` 全部来自站长两台手机（CN），
  **两台手机 10-24 20:51 起都已改成签名模式**（支付宝、微信各有签名到账记录，此后再没有用过 token）。
- 近 3 天已付订单逐条核对，**没有发现资金损失**。
- 服务器：阿里云安全组 **1～65535 全端口对公网开放**（含 3306、3389）；**0 个云盘快照、没有任何自动备份**；94 个待装安全更新；
  `JWT_SECRET` 只有 26 位；MySQL 里还留着已废弃的 `wxpad@%` 账号；对外发卡接口近 30 天 0 次调用但密钥开着。

## 二、全项目复查（两路只读审查 + 我核对代码）

### 2.1 资金链路

| # | 问题 | 级别 | 处置 |
|---|---|---|---|
| F1 | **聊天消息冒充到账**：支付宝标题行就是聊天对象的显示名，以前「元」后面任意字符、整数金额也认；微信正文、标题都可以用「群名 / 昵称 = 微信收款助手」凑出来 | 高 | 改：支付宝标题必须整行是「你已成功收款X.XX元」+（新/老顾客消费）/「.」，金额两位小数；微信金额两位小数、括注后不能再有字。**微信这条模板挡不全，根治在运营侧（见第六节第 1 条）** |
| F2 | **抢占整数原价**：第一张单拿到的就是 135.00，攻击者先占住，别人付错的整数金额就记到他的单上自动发卡（充值单过期后还会自动退进他的余额） | 高 | 改：收款金额从原价 +1 分起，**永远不分配整数原价**（尾差 1～49 分）；付错的整数金额一律进人工核实 |

| F8 | 推广返现：人人都是推广人，只防「自己推自己」；退款不自动扣回返现 | 中 | 别名邮箱拦截 + 同 IP 每天最多注册 5 个后，开小号自推的成本大增；**是否退款自动扣回仍待站长拍板**（代码里原本就标了待定），本轮不改 |

查过没问题的（摘要）：到账按「状态 + 金额」CAS、同一通知原文去重、重放无效；发起收款锁订单行复核金额与归属；发卡「待付→已付」CAS + 单卡 CAS 不超发；
下单价格全在服务端、数量 1～10、券 CAS；钱包扣款带条件单条更新不会扣成负数、流水业务键唯一；充值入账与翻已付同一事务；接码退款三道幂等；
抽奖一单一抽；站内兑换只认已付未取消；微信机器人三道闸 + 权限等级 + 每日上限；发票付税费校验归属。

查过没问题的（摘要）：验证码 `crypto.randomInt`、10 分钟、每码 5 次、用途隔离；发码 / 注册 / 找回 / 登录四处响应与时延拉平防枚举；JWT 固定 HS256、绑店面、会话版本查库吊销；
每个后台接口都有守卫与同源校验；Markdown 先转义、链接只放 http(s) 与站内；登录回跳没有开放重定向；`safe-fetch` 防 SSRF（含云元数据地址）；上传按文件头、不收 SVG。

### 2.3 人机验证（站长选「无感算力验证」）

`lib/security/pow.ts` + `lib/pow-client.ts`：登录、注册、发验证码、找回密码、邮箱查订阅提交前，浏览器先取一道题（`GET /api/auth/pow`），
在 Web Worker 里算 SHA-256 使前 18 位为 0（期望 26 万次，电脑约 0.2 秒、手机 1 秒内，与按钮转圈同时发生），请求头带 `x-pow`。
服务端验签名（HKDF 子密钥）、用途、3 分钟有效、一次性；**最近被限流 / 验码失败过的 IP 难度升到 21 位（8 倍）**。不依赖第三方，国内访问不受影响。
应急：`POW_MODE=off`。

## 五、站长要知道的变化

- **上线那一刻所有人（含你）要重新登录一次**；你在新设备上登录会照常要邮箱验证码。
- 后台每个请求都要求浏览器里有「受信设备」：换浏览器、清了 cookie、点了「退出登录」之后，都要重新走一次邮箱验证码。
- **管理员不能在网页上找回密码了**：忘了密码告诉我，临时设 `ADMIN_WEB_RESET=1` 改完再关。
- 补单要填交易号（支付宝 / 微信账单详情里的「订单号」/「交易单号」）；账单里查不到这笔钱就别补。
- 收款金额都会带 1～49 分的尾差（原来第一张单是整数）：买家付整数会进「待核实」，核对账单后补单。
- 新密码至少 8 位、要有字母和数字。
- 后台登录态在新 IP 上用会推告警：换网络（手机流量、VPN）也会推，同一 IP 只推一次。

## 六、仍要站长做 / 未做

1. **收款微信号、支付宝号只用来收钱：不加任何好友、不进任何群、关掉陌生人消息与聊天通知预览**。
   这是聊天冒充到账唯一的根治（技术上只能把模板收紧，挡不住「昵称叫微信收款助手的好友」）。如果收款号就是公开的客服微信，请尽快换一个独立的收款号。
2. 自动数据库备份已装（本机每日导出）；**整机级备份（云盘快照）站长本轮未选**——磁盘损坏 / 整机被删时本机导出也一起没了。
3. 推广返现退款自动扣回、返现冻结期：待站长拍板。
4. Cloudflare：**先加一条「跳过」规则再开任何质询**——安全性 → WAF → 自定义规则：URI 路径等于 `/api/pay/sms-notify` 且方法为 POST →
   跳过（所有剩余自定义规则、速率限制、托管规则，更多组件里勾「安全级别」「浏览器完整性检查」），排第一位。
   10-25 晚开全站质询期间收款推送全部 403。免费版 Bot Fight Mode 跳不过，别开。之后再考虑 Tor（T1）访问 `/api/auth/*` 质询。
6. 镜像里带着构建时的 `.env.production`（Next 启动时读）：镜像外泄 = 当时的密钥外泄；关变量要写空值（见 4.1）。改成构建时不打包 env 文件需另行改 Dockerfile 与部署流程。
5. Next 15/16 升级（另立项）；`__Host-` cookie 前缀（A14）。
