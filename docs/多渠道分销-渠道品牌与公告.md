# 多渠道分销 · 渠道品牌与公告（2026-10-05）

站长 10-05 提出三件事，本期一起做：

1. 渠道主上传客服二维码时报「图片存储空间已满，请联系平台」。
2. 给渠道主更大的自主权：可以改网站名称、logo 和平台介绍（有的渠道不想显示「贝果科技」）。
3. 渠道分站开通公告功能。

第 1 条不是代码问题，是服务器磁盘满了（第 1 节）。第 2、3 条是本文的契约，它修订了设计 D1「统一品牌」：品牌从「全站一样」改成「渠道可选自定义，没设就和主站一样」。

## 1. 「图片存储空间已满」的根因与处理

**根因**：上传接口要求磁盘至少剩 2GB（`UPLOAD_MIN_FREE_MB`，防止写满磁盘连带打挂 MySQL），而 10-05 生产磁盘只剩 141MB。上传代码按设计拒收，报 507「图片存储空间已满」。

**磁盘为什么满**：MySQL 二进制日志（binlog）每两天涨 1GB。保留期是默认的 30 天，`binlog_row_image=FULL` 会把整行的修改前、修改后两份镜像都写进去。抽样 `binlog.000075` 的 6 万个事件：

- `sms_offer_cache`（短信接码报价缓存）约占 80%；
- `news_events`（大事记排序，每行约 4.5KB）约占 19%。

**已处理**（2026-10-05，服务器上执行）：

- `PURGE BINARY LOGS BEFORE '2026-10-04'`：删掉约 3.2GB 旧日志。没有从库，这些日志只用于按时间点恢复数据。
- `SET PERSIST binlog_expire_logs_seconds = 259200`：保留期改为 3 天。
- `SET PERSIST binlog_row_image = 'MINIMAL'`（站长同意）：只记主键和真正变化的列，日志量约降 90%。按时间点恢复不受影响。
- `docker builder prune -f`：清掉旧的构建缓存。
- 处理后磁盘剩 6GB 左右，上传恢复正常。

**后续**：`sms_offer_cache` 的写入量另开任务处理（只写有变化的行）。大事记会话会把 `score_debug` 改成只在输入项变化时才重写。

## 2. 数据模型（只新增，零 DROP / MODIFY）

`tenants` 加 8 列，全部可空或带默认值：

| 列 | 类型 | 说明 |
|---|---|---|
| `brand_name` | VARCHAR(40) | 网站名称，2–12 字 |
| `brand_logo_url` | VARCHAR(160) | 站标地址，只由服务端写入，读写两端都校验 `/uploads/brand/<名>.(png\|jpg\|webp)` |
| `brand_intro` | VARCHAR(600) | 页脚简介，≤200 字 |
| `hero_title` | VARCHAR(80) | 首页大标题，≤20 字 |
| `hero_subtitle` | VARCHAR(240) | 首页副标题，≤80 字 |
| `seo_title` | VARCHAR(120) | 浏览器标题（首页 `<title>` 与分享标题），≤40 字 |
| `seo_description` | VARCHAR(360) | 分享摘要，≤120 字 |
| `brand_locked` | BOOLEAN 默认 0 | 超管锁定：渠道不能再改，已有值保留 |

新表 `tenant_announcements`：

- 字段：`id`、`announcement_no`（唯一，12 位随机 base32 公开编号）、`tenant_id`（外键 → `tenants`，RESTRICT）、`title`、`content`、`level`、`enabled`、`pinned`、`start_at`、`end_at`、`blocked`、`created_by`、`created_at`、`updated_at`。
- 索引 `(tenant_id, enabled)`。
- 与主站的 `announcements` 表**分开**：主站公告的查询、后台、前台一行不改。

## 3. 品牌的回退规则与展示点

**唯一实现**：`resolveStoreBrand`。每个字段各自回退，没填或库里的值读出来不合规，都按「未设置」处理，组件渲染主站原样。站名没填时为「贝果科技」，此时 `custom=false`。

**白标**：改了站名或传了 logo（`isWhiteLabel`）就算白标。白标时：

- 页面上不再出现「贝果科技」与贝果图标；
- 页脚底部多一行经营主体小字。

**主站逐字不变**：

- 主站店面的品牌是常量，不查库。
- 组件约定字段为 null 就渲染原来写死的那一套。
- 页脚版权行在非白标分支保留原 JSX：React 会在相邻文本节点之间插注释，写法一变 HTML 就不再逐字相同。
- `mods-brand` B2 用 git 基线与工作区在同一进程各渲染一遍，逐字比较。

| 展示点 | 白标渠道 | 没有白标（主站与普通渠道） |
|---|---|---|
| 页头 | 有 logo 用 logo，只改名用站名首字的圆角块；站名文字 | 原样 |
| 页脚 | logo（或首字块）＋站名；简介用渠道填的，没填用默认简介并把站名换成渠道的；版权行用渠道站名，下面一行经营主体小字 | 原样 |
| 浮动客服 | 「{站名}专属客服为你服务」 | 原样（站名就是贝果科技） |
| 首页大标题 / 副标题 | 渠道填了就整句换掉（副标题不带打字机与服务清单） | 原样 |
| 筹备中页面 | 渠道站名 | 原样 |
| 根布局 metadata | 标题 / 描述用渠道的浏览器标题、分享摘要，没填则把原文里的「贝果科技」换成站名；`applicationName`、`og:site_name` 用站名；图标：有 logo 用 logo，否则用站名首字 SVG（data URL，不落盘）；分享图：有 logo 用 logo，否则不给（主站分享图印着贝果字标） | 原样 |
| 各页面标题（登录、注册、找回密码、订单、个人中心、发票抬头、隐私、条款、客服中心、商品列表、商品详情、首页） | `brandMetadata` 把标题、描述里的「贝果科技」换成站名，分享图同上 | 原样（返回原对象） |
| 买家交易邮件、验证码邮件 | 标题【站名】、抬头、发件人名用站名（`MailOpts.brand`） | 原样 |
| 不换的 | 「关于我们」页、服务条款与隐私政策正文的主体、收据收款方、发票、渠道后台（给渠道成员看的，平台口吻）、渠道成员邀请与后台通知邮件 | — |

**进程内缓存**：`getTenantBrand(tenantId)`（`src/lib/tenant/brand.ts`）缓存 60 秒，给没有请求上下文的流程用，比如邮件、微信机器人推送。渠道保存后立即失效同一进程的缓存。页面与接口每个请求都读 tenants 行，改完下一个请求就生效。

## 4. 写入校验（`checkBrandTextFormat` / `checkBrandText`）

- 折叠空白，单行。
- 按码点计长度。
- 拒绝控制字符、零宽字符与方向控制字符、尖括号。
- 拒绝网址：`http:`、`www.`、常见顶级域。
- 站名额外要求：
  - 字符集只允许汉字、字母、数字、空格与 `· - _ & （ ） ( )`；
  - 不能含冒充官方、AI 厂商或支付机构、平台名的词，例如官方、官网、旗舰、授权、直营、OpenAI、ChatGPT、GPT、Claude、Anthropic、Gemini、Google、谷歌、微软、苹果、支付宝、微信支付、bigolab、必高；
  - 要过阿里云邮件禁发词（会进邮件标题与发件人名）。
- 其余字段不能含官方、官网、旗舰店、官方授权、授权经销、授权代理、直营。可以写 ChatGPT、Claude，那是在卖的东西。
- logo：≤1MB；按文件头只收 png / jpg / webp（SVG 能带脚本，gif 没必要）；文件名随机；每渠道每小时 10 次。换图、清除、超管恢复默认后，旧文件按引用计数删除。

## 5. 渠道公告

**规则与主站公告相同**：

- 同一时刻只弹一条，强提醒优先，其次最新发布的；
- 普通公告买家看过就不再弹，内容修改后会重新弹；
- 强提醒每次进入都弹。

**接口**：同一个弹窗组件、同一个接口 `/api/announcement`，按店面分流：

| Host | 返回 |
|---|---|
| 主站（含休眠期任何 Host） | 原来的 `announcements` 查询，一行不改 |
| 渠道 | 只查本渠道的 `tenant_announcements`。被超管下架的不给；筹备中的渠道一律 `null`（前台整站是暂停访问页，公告不能先漏出去） |
| 未登记 / 停用的域名 | 404 |

**其余约定**：

- 前台返回的 `id` 是公开编号，不是全局自增 id（弹窗组件按 id 在 localStorage 里记已读，各域名各自隔离）。
- nginx 渠道 `/api` 白名单加 `announcement`；`(shop)` 布局在渠道站也挂弹窗。
- 渠道后台「店铺公告」页（settings.write，仅店主；暂停营业时只读）：增删改查、启用 / 停用、强提醒、展示时间。
- 按公开编号寻址；他站编号、乱码一律 404。正文字段叫 `body`，因为 `content` 是渠道响应禁用键。
- 标题 ≤100、正文 ≤2000 字，纯文本，去掉控制字符与零宽字符。
- 每渠道最多 50 条：锁渠道行后计数。
- 被平台下架的公告：可以改内容，不能启用。

## 6. 超管

渠道详情新增「品牌与公告」卡片（`/api/admin/tenants/[id]/brand`、`/api/admin/tenants/[id]/announcements/[announcementNo]`，均为 adminGuard）：

- **查看**：品牌原值、logo、锁定状态、公告列表。
- **恢复默认**：七个品牌字段清空，锁定状态保留，旧 logo 按引用删除。写审计 `tenant.brand_reset`（publicDiff 只有 `{reset:true}`），渠道收到站内通知。
- **锁定 / 解锁**：写审计 `tenant.brand_lock`，渠道收到站内通知。
- **公告下架 / 恢复**：下架同时停用，恢复后不自动启用。写审计 `tenant.announcement_block`，渠道收到站内通知。
- **渠道侧审计**：`settings.brand`，diff 只记字段名；`settings.announcement`，diff 只记操作与编号。
- **站长群告警**：渠道每次改品牌都发一条，内容含改了哪几项与新站名。

## 8. 上线步骤

**有 DDL**：先 DDL、再构建、再换 app。nginx 要 force-recreate，cron 不动。

1. 上线前给并行会话发消息，确认服务器空闲；`df -h /` 至少剩 2G。
2. 回滚标签；`git pull`；临时容器 `nginx -t`。
3. DDL 预览（闸门：语句开头零 DROP / MODIFY / CHANGE / RENAME）。只应有：`tenants` 加 8 列、建 `tenant_announcements`（含唯一索引与外键）。会话级 `lock_wait_timeout` 后直接执行预览 SQL。
4. `build-with-swap.sh` 构建 → `up -d --no-deps --force-recreate app` → `force-recreate nginx`。
5. 冒烟：
   - 主站首页、登录页 200，标题与改动前相同；
   - lulu、shop、mysticboy 首页 200，没设品牌时仍是贝果科技；
   - 渠道 Host `/api/announcement` 经 nginx 返回 200（`null` 或本站公告）；
   - 主站 `/api/announcement` 不变；
   - `/api/account/wallet` 在渠道仍是 404。

**回滚**：切回上一版镜像即可，新列和新表旧镜像不读。nginx 回滚到上一版文件后，渠道 `/api/announcement` 重新是 404，无害。
