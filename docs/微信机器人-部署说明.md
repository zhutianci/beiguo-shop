# 微信机器人 · 部署说明

> 设计契约：`docs/微信机器人-设计.md`（下文 §x 均指它）。本文只写**怎么上线、怎么验、怎么退**。
> 服务器操作照交接文档的三条铁律：命令用 base64 传、耗时任务后台跑、**绝不跑 `docker system df` / `docker builder du`**。
> 生产 DDL、改内核 / swap、新增容器都要站长明确同意；上线前后给其他会话发消息，对方「结束」之前不 build、不重启 app。

---

## 0. 一句话

网站进程里多了一个「机器人中枢」（`src/lib/bot/**`），另起两个容器跑协议服务（`wxpad` = WeChatPadPro、`wxpad-redis`），
小号登录在协议服务里。**`BOT_ENABLED` 不设 = 完全休眠**，现有行为零变化（推送、统计、下单都不受影响），所以代码可以先上、开关后开。

## 1. 组成与开关

| 部分 | 位置 | 说明 |
|---|---|---|
| 中枢 | app 容器 | 旁路采集事件、路由、出队、发送器、指令、日报、后台 `/admin/bot`、补货页 `/bot/x/<令牌>`、渠道快速回复 `/partner-reply/<令牌>` |
| 协议服务 | `wxpad` 容器（compose `profiles: [bot]`） | 闭源，按不可信处理：不映射端口、只授权自己的库、拿不到业务密钥 |
| 协议服务缓存 | `wxpad-redis` 容器（`profiles: [bot]`） | 32MB 上限、RDB 快照（重启不用重新扫码，PoC 第 7 项核实） |
| 定时任务 | `cron/crontab` 两行 | 每分钟 `bot-tick`、每天 00:01 `bot-daily` |
| nginx | `nginx/nginx.conf` | `/api/bot/wxpad/` 对外 404；渠道 Host 的 `/api` 白名单加 `track/view`、`partner-reply` |
| 数据库 | 8 张 `bot_*` 新表 + 3 处加列 | `products.bot_code`、`page_views.tenant_id`、`visitors.tenant_id`（后两个 `NOT NULL DEFAULT 1`，历史行算主站） |

开关（都在 `.env.production`，改完 `up -d app` 生效）：

| 变量 | 作用 | 取值 |
|---|---|---|
| `BOT_ENABLED` | 总开关 | `1` 开；不设 = 休眠 |
| `BOT_ADAPTER` | 适配器 | 缺省 `wxpad`；`console` 只用于本地 |
| `BOT_WXPAD_BASE` | 协议服务地址 | 缺省 `http://wxpad:8080`（Docker 内网），一般不设 |
| `BOT_WXPAD_ADMIN_KEY` | 协议服务管理密钥 | `openssl rand -hex 16`；与 wxpad 容器的 `ADMIN_KEY` 同值（compose 用同一个变量） |
| `BOT_WXPAD_HOOK_SECRET` | 回调路径密钥 | `openssl rand -hex 24`（≥ 32 字符，否则回调接口一律 503） |
| `BOT_WXPAD_RECEIVE` | 收消息方式 | 缺省 `webhook`；PoC 证实只能 WebSocket 时设 `ws`，并加 `NODE_OPTIONS=--experimental-websocket` |
| `BOT_WXPAD_PROXY` | 同城代理 | 站长 Q18：手机登录、不需要，**不设** |
| `BOT_WXPAD_WAKE_PATH` | 唤醒登录接口 | 缺省 `/login/WakeUpLogin`，PoC 以实际为准 |
| `BOT_LINK_ORIGIN` | 推送里链接的域名 | 缺省 `APP_URL` |
| `BOT_TENANT_REPLY` | 分站群留言带渠道快速回复链接 | P1b 再开：`1` |
| `TRACK_CHANNEL_VIEWS` | 分站也记 PV/UV | P1a 开：`1`（nginx 白名单已放行 `track/view`） |
| `BOT_WXPAD_IMAGE` | 协议服务镜像 | **锁 PoC 验证过的 digest**：`wechatpadpro/wechatpadpro@sha256:…` |
| `BOT_WXPAD_REDIS_PASSWORD` | 协议服务 Redis 密码 | `openssl rand -hex 16` |
| `BOT_WXPAD_DB_PASSWORD` | 协议服务数据库账号密码 | `openssl rand -hex 24`（只含 0-9a-f，`sed` 替换不出错） |

后三个只给 compose 插值用，不进 app 容器。另外核对 **`NOTIFY_EVENTS`**：生产若配了白名单，要加上 `bot.offline,bot.online,bot.sensitive`，
否则掉线告警、提卡抄送这些企业微信消息会被白名单吞掉（§16.2 第 0 步）。

## 2. 站长先做的事（§19）

1. 准备小号与备用号：实名、绑手机、各正常用一两周，只加管理员为好友。
2. 同意本次上线动作：新增两个容器与一个数据库账号、DDL、nginx 与 cron 变更、构建前临时放开 swap。
3. PoC 时用小号手机扫码（后台「微信机器人 → 概览 → 登录小号」）。

## 3. 上线步骤（P0 代码 + P1a 部署，一次做完；开关分批开）

> 顺序照交接文档：回滚标签 → 备份 → DDL 预览与闸门 → 执行 DDL → 种子 → 构建 → 只重启 app → nginx / cron → 协议服务 → 冒烟。
> 下面的命令都在服务器 `/opt/beiguo` 下执行，`$MYSQL_ROOT_PASSWORD` 等从 `.env.production` 读（`set -a; . ./.env.production; set +a`）。

**① 协调与回滚标签**（在 build 之前打！）

```bash
docker tag beiguo-shop-app:latest beiguo-shop-app:rollback-$(git rev-parse --short HEAD)
```

**② 备份并校验**（不要直接管道进 gzip）

```bash
docker compose --env-file .env.production exec -T db mysqldump -uroot -p"$MYSQL_ROOT_PASSWORD" --single-transaction --routines --triggers --set-gtid-purged=OFF beiguo_shop > /opt/beiguo/backups/beiguo_shop_$(date +%Y%m%d_%H%M%S).sql
```

```bash
tail -3 /opt/beiguo/backups/beiguo_shop_*.sql | grep "Dump completed" || echo "备份不完整，停手"
```

**③ 预览 DDL 并过闸门**：拉代码后，用临时容器出预览（写法同交接文档，后台跑、等日志里真的出现 CREATE / ALTER 再看）：

```bash
docker run --rm --network beiguo-shop_app-network -v "$PWD/prisma":/work/prisma -w /work -e DATABASE_URL="mysql://root:$MYSQL_ROOT_PASSWORD@db:3306/beiguo_shop" -e PRISMA_ENGINES_MIRROR=https://registry.npmmirror.com/-/binary/prisma node:20-alpine sh -c 'apk add --no-cache openssl >/dev/null; npx -y prisma@5.22.0 migrate diff --from-url "$DATABASE_URL" --to-schema-datamodel prisma/schema.prisma --script' > /tmp/bot-preview.sql 2>&1
```

```bash
sh scripts/ops/ddl-gate.sh /tmp/bot-preview.sql --expect-bot
```

闸门只放行：8 张 `bot_*` 新表、3 处加列、3 个新索引；唯一键逐字核对；**零 DROP / MODIFY / CHANGE / RENAME、无外键**。
预览里若同时出现「多渠道」会话的 DDL（同批上线时），先与对方对齐再一起执行。

**④ 执行审过的 DDL**（旧镜像仍在跑：新表没人读、加的列有默认值，对线上零影响），然后阳性对照：

```bash
docker compose --env-file .env.production exec -T db mysql -uroot -p"$MYSQL_ROOT_PASSWORD" --default-character-set=utf8mb4 beiguo_shop < /tmp/bot-preview.sql
```

```bash
docker compose --env-file .env.production exec -T db mysql -uroot -p"$MYSQL_ROOT_PASSWORD" -N -B beiguo_shop -e "SHOW TABLES LIKE 'bot\_%'; SHOW COLUMNS FROM products LIKE 'bot_code'; SHOW COLUMNS FROM page_views LIKE 'tenant_id'; SHOW COLUMNS FROM visitors LIKE 'tenant_id'"
```

应当看到 8 张表与 3 列。

**⑤ 种子**：提卡专用账号、`bot_config.issueUserId`、自动发货商品预填货号 `P<id>`（可重复执行）：

```bash
docker compose --env-file .env.production exec -T db mysql -uroot -p"$MYSQL_ROOT_PASSWORD" --default-character-set=utf8mb4 beiguo_shop < scripts/ops/bot-seed.sql
```

核对输出：提卡账号 1 行（status 0）、`bot_config` 含 `issueUserId`、AUTO 商品都有货号（撞号的会留空，在后台补）。

**⑥ 协议服务专用库与账号**（密码从 `wxpad.env` / `.env.production` 读，不写进文件）：

```bash
sed "s/__WXPAD_DB_PASSWORD__/$BOT_WXPAD_DB_PASSWORD/g" scripts/ops/bot-wxpad-db.sql | docker exec -i beiguo-db sh -c 'mysql -uroot -p"$MYSQL_ROOT_PASSWORD" --default-character-set=utf8mb4'
```

`SHOW GRANTS` 应当只有 `USAGE ON *.*` 与 `wxpad.*` 两行。

**⑦ 构建并只重启 app**：照交接文档的 `build-with-swap.sh`（先问站长放开 swap；`df -h /` 留够 2G），等构建真的结束、末尾无 ERROR，再：

```bash
docker compose --env-file .env.production up -d app
```

此时 `BOT_ENABLED` 还没设：机器人休眠，冒烟主站即可。

**⑧ nginx 与 cron**：nginx 是单文件 bind mount，`reload` 读不到新文件，必须重建；cron 有新行也要重建：

```bash
docker compose --env-file .env.production up -d --force-recreate nginx
```

```bash
docker compose --env-file .env.production up -d --force-recreate cron
```

**⑨ 冒烟（休眠状态）**

- 外网 `https://bigolab.com/api/bot/wxpad/hook/任意` → 404；`/bot/x/不存在` → 「链接已失效」页；渠道 Host 上 `/api/bot/x/restock` → 404。
- 后台 `/admin/bot` 能打开（显示「BOT_ENABLED 未开」）。
- **后台流量分析的数字与上线前一致**（默认只看主站 `tenant_id = 1`）。
- 首页「实时成交」正常（提卡单以后也不会出现）。
- `node scripts/check-bot-boundary.mjs` 已在构建前跑过（prebuild）。

## 4. PoC：起协议服务、登录小号（§11.6）

**① 写 `wxpad.env` 不必要**：compose 直接用 `.env.production` 里的 `BOT_WXPAD_*`。先锁镜像：在测试机或服务器上 `docker pull wechatpadpro/wechatpadpro:<版本>`，
记下 digest 写进 `BOT_WXPAD_IMAGE`。

**② 启动**（只起这两个，不碰别的服务）：

```bash
docker compose --env-file .env.production --profile bot up -d wxpad wxpad-redis
```

**③ 开机器人并登录**：`.env.production` 设 `BOT_ENABLED=1`、`BOT_WXPAD_ADMIN_KEY`、`BOT_WXPAD_HOOK_SECRET`，`up -d app`；
后台「微信机器人 → 概览」：「刷新状态」应显示协议服务可达；点「登录小号」→ 小号手机扫码确认 → 状态变在线、显示小号昵称与 wxid。

**④ 配回调**：Webhook 模式下，在协议服务里把消息回调地址设成 `http://app:3000/api/bot/wxpad/hook/<BOT_WXPAD_HOOK_SECRET>`
（WeChatPadPro 的回调配置接口以 PoC 时的文档为准）。不支持 Webhook 就改 WebSocket：`BOT_WXPAD_RECEIVE=ws` + `NODE_OPTIONS=--experimental-websocket`，
`up -d app`，中枢每分钟自动连 `ws://wxpad:8080/ws/GetSyncMsg`。

**⑤ 验收清单**（结果记到本文末尾「PoC 记录」）：

1. 免费公开版能否登录（不能就按 Q19 决定是否拿新版）。
2. 24 小时不掉线。
3. 内存与 CPU（空闲、发送时）→ 调 `mem_limit`。
4. 回调字段：群 ID、发送人 wxid、`atuserlist`、消息 ID、入群 / 退群系统消息；录下真实样本补进 `scripts/check-bot-core.ts`。
5. 发群文本：成功率、900 字、换行、链接能否点。
6. 群列表接口（后台「新建绑定」用）；只列「保存到通讯录」的群，没保存的手动填群 ID。
7. 重启 `wxpad` 容器后会话是否保持（决定构建期间要不要停它）。
8. 72 小时稳定性。
9. 补货链接、核销链接在微信内置浏览器里的表现。

## 5. 分批打开（§16.1）

| 阶段 | 动作 | 验收 |
|---|---|---|
| P1a 只推送 | 管理员认领（后台「管理员 → 添加 → 生成认领码」，用自己的微信私聊小号发「认领 XXXXXXXX」）→ 建测试群 `@贝果助手 设为管理群` → `TRACK_CHANNEL_VIEWS=1` | 测试群跑 1–2 天：动态、合并、免打扰、00:02 日报 |
| P1b 开指令与分站群 | 代理群 `@贝果助手 创建 <分站域名>`（新号每天 ≤ 3 个群）；`BOT_TENANT_REPLY=1` | A 站动态只进 A 群；分站群留言带渠道快速回复链接、只在本站域名能打开 |
| P2 提卡补货 | 后台「会话」给管理群勾「允许提卡补货」；先用测试商品 | `提卡 <货号> <价格>` 回执带核销链接、企业微信收到抄送；`补货` 链接 5 分钟、提交后作废；超每日上限被拒 |

## 6. 回滚

- **只关机器人**（最常用）：`.env.production` 去掉 `BOT_ENABLED` → `up -d app`。推送、指令、日报全停，现有功能不受影响；协议服务可留着。
- **停协议服务**：`docker compose --env-file .env.production --profile bot stop wxpad wxpad-redis`。
- **回退镜像**：`docker tag beiguo-shop-app:rollback-<commit> beiguo-shop-app:latest` → `up -d app`。新表与加列留着无害（旧代码不读）；
  `page_views.tenant_id` 有默认值，旧代码照常写入。
- **紧急止损**：群里 `@贝果助手 锁定`（提卡、补货、改设置全停、未用补货链接作废）；解锁只能在后台。
