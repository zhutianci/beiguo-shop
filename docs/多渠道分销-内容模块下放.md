# 多渠道分销 · 内容模块下放（2026-10-10）

站长 10-10 提出：把【AI学习】【AI圈大事记】【IP工具】三个模块下放给分站，目的是增加这些模块的浏览量和推广。超管分发权限，分站管理员决定上架或下架，默认上架。

这份契约修订了设计 7.6 / 11.2「渠道站关闭内容与营销模块」：三个**内容**模块改为按渠道开关，营销模块（券、抽奖、内推、VIP、余额、充值落地页、接码、友链、游戏、订单查询）照旧在渠道站一律关闭。

## 0. 站长拍板（2026-10-10）

| 问题 | 结论 |
|---|---|
| 分站上的「AI学习」开放到什么程度 | **全功能**：浏览、复制、点赞、发帖、评论、收藏、合集、关注、通知、攒积分、申请认证。积分兑换（换的是主站优惠券）与作者内推返现只在主站 |
| 内容页里的「充值广告」与作者返现链接（都指向主站 `/chongzhi`） | **分站上去掉**：渠道站不出这些入口，记录转化的接口在渠道站也照旧 404 |
| 超管授权的默认值 | **默认不授权**，超管在后台逐个渠道、逐个模块开。授权后渠道前台默认上架，渠道可自己下架 |

## 1. 数据模型（只新增，零 DROP / MODIFY）

```sql
ALTER TABLE `forum_posts` ADD COLUMN `source_tenant_id` INTEGER NOT NULL DEFAULT 1;
ALTER TABLE `forum_comments` ADD COLUMN `source_tenant_id` INTEGER NOT NULL DEFAULT 1;
ALTER TABLE `tenants` ADD COLUMN `mod_iptools_granted` BOOLEAN NOT NULL DEFAULT false,
    ADD COLUMN `mod_iptools_on` BOOLEAN NOT NULL DEFAULT true,
    ADD COLUMN `mod_learn_granted` BOOLEAN NOT NULL DEFAULT false,
    ADD COLUMN `mod_learn_on` BOOLEAN NOT NULL DEFAULT true,
    ADD COLUMN `mod_news_granted` BOOLEAN NOT NULL DEFAULT false,
    ADD COLUMN `mod_news_on` BOOLEAN NOT NULL DEFAULT true;
```

- `*_granted`：超管授权，默认 0。`*_on`：渠道上架，默认 1。
- 前台生效 = 授权 && 上架 && 店铺「营业中」或「暂停营业」。筹备中、已停业的渠道一律不开。
- 收回授权时不改上架列：再次授权恢复渠道上次的选择。
- `source_tenant_id`：帖子与评论是在哪个店面发的（1 = 主站）。只用于后台审核列表显示「来自 lulu」，不建外键。
- 三条语句在 MySQL 8 上都是 INSTANT 加列，不锁表、不重写数据。

## 2. 开关的唯一实现

| 位置 | 作用 |
|---|---|
| `src/lib/storefront/modules.ts` | 模块名、说明、列映射；`resolveStoreModules`（授权必须是 true，上架缺省算上架）。零依赖，客户端可用 |
| `resolve.ts` `findTenant` | 6 列与 `status` 同一次主键查询，`Storefront.modules`。改完下一个请求就生效，不需要清缓存 |
| `resolve.ts` `moduleOpen` / `denyUnlessModule` / `notFoundUnlessModule` | 服务端拦截。主站恒开 |
| `public.ts` `storefrontFeatures` | 渠道站的 `features.forum` / `news` / `iptools` 按模块打开（同一口径），其余 features 照旧全关 |

**服务端拦截点**：

- 页面：`learn`、`prompts`、`guides`、`apps`、`collections`、`u`、`forum` 七个 layout 按 `learn` 判断；`news` 与 `iptools` 的 layout 各按自己的模块判断。
- 接口：`/api/forum/*` 与 `/api/content/*`（除 `cta`）、`/api/me/creator-application`、`/api/upload` 按 `learn` 判断；`/api/news/*` 按 `news` 判断。
- `/api/me/*`：以前靠 nginx 渠道白名单挡，现在由 `meOrDeny` 与 `/api/me/summary` 第一行兜底。
- 照旧对渠道站关闭：`/api/me/points-shop`（积分兑换）与 `/api/content/[id]/cta`（作者返现归因）仍是 `denyOnChannel`。

**nginx**：渠道 `/api` 白名单加 `news|content|forum|me|upload`。要不要开由应用按渠道判断，没开的渠道照旧 404。`/api/upload` 在渠道 Host 上只剩发帖配图可用：其余用途要求 ADMIN，而渠道 Host 上 ADMIN 视为未登录。

## 3. 后台

**超管**：渠道详情加「内容模块」卡片（`tenant-modules.tsx`）。

- `GET` / `POST /api/admin/tenants/[id]/modules`，请求体 `{ module, granted }`，strict。
- 写审计 `tenant.module_grant`，并给渠道发站内通知。
- 帖子 / 评论审核列表显示「来自 {渠道代号}」。

**渠道**：设置中心加「内容模块」卡片（`modules-card.tsx`）。

- `GET` / `PUT /api/partner/settings/modules`，请求体 `{ module, on }`。
- 权限 settings.write（仅店主）；暂停营业时只读。
- 没授权的模块返回 409。
- 审计 `settings.module`，`diff` 为 `{ module, on }`。
- 响应键 `modules` 与 `module` / `label` / `granted` / `on` / `live` 已进白名单。

## 4. 渠道站上的展示规则

内容全站共用一份。主站的页面输出一字不变：页面里的分支都写成「渠道才改」。

| 位置 | 渠道站 |
|---|---|
| metadata（`module-meta.ts` `moduleMetadata`） | robots 一律 `noindex, follow`（页面自带的 index 会盖过根布局）；`metadataBase` = 渠道域名（og:url 跟着走）；canonical 指主站同一页（内容原始出处在主站）；白标渠道把「贝果科技」换成渠道站名、分享图换成渠道 logo |
| JSON-LD（`PlatformJsonLd` / `PlatformOnly`） | 不输出。渠道站整站 noindex，结构化数据没有收益，而且写的是贝果的机构与主站地址 |
| 大事记 AI 提示条、分享海报 | 整理者「贝果科技 AI 资讯助手」里的站名换成渠道站名（白标时）；海报顶部站名、兜底域名跟着渠道 |
| 分享链接、海报二维码 | 渠道自己的域名（`channel-url.ts`），顾客扫码回到渠道站 |
| 大事记详情「广告 · 本站服务」 | 不出 |
| 大事记详情「去论坛讨论」 | 只在渠道也开了 AI学习时出 |
| 内容页转化入口（开通 ChatGPT / Claude …）与作者内推码 | 不出 |
| 「贝果认证」徽章提示、作者页「在贝果分享」「加入贝果」、/learn 眉题「Bigo AI Learning」 | 白标渠道换掉 |
| 学习空间 | 「积分兑换」页签与「作者内推返现」段落隐藏（`features.coupon` / `referral` 恒关） |
| 渠道首页 | 开了大事记：热点区块服务端直出；开了 AI学习：加「AI 学习」入口区块 |
| 页头、页脚、手机菜单 | 原本就按 `features.forum` / `news` / `iptools` 显示入口，不用改 |

**计数**：渠道站的浏览、分享、复制、点赞计入同一份内容的全站计数（这正是下放的目的）。

## 5. 测试

`scripts/itest-tenant/mods-modules.ts` 已并入 `run-all`，分 M1–M7 七组：

- **M1**：纯函数。
- **M2**：默认不授权时全关，主站照常。
- **M3**：超管授权 / 收回、站内通知、审计。
- **M4**：渠道上架 / 下架、409、strict、STAFF / 他站拒绝、响应键白名单。
- **M5**：暂停营业照开，筹备中不开。
- **M6**：主站 metadata 与 git 基线逐字相同；渠道站 noindex、canonical 指主站、不出「贝果科技」。
- **M7**：渠道站发评论记来源站；积分兑换与返现归因接口仍 404。

## 6. 部署顺序

1. 先执行第 1 节 DDL（会话级 `lock_wait_timeout=30`），再换镜像。
2. 换镜像后再 `force-recreate nginx`，让白名单生效。nginx 先放行、应用还是旧的，也只是旧应用对这些接口继续返回 404；`/api/me` 这类旧应用没拦的接口，在新镜像之前不会被渠道页面调用。
3. 上线时三个模块默认对所有渠道关闭，前台与上线前完全相同。站长在超管后台逐个渠道授权。
