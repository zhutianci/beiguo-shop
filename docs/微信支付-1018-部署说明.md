# 微信支付接入 + 收款回调加固 —— 部署说明（2026-10-18）

代码：main `26bba51..38a3439`（`659260f` 收款功能与安全、`38a3439` 全站文案）。**无数据库改动**；`docker-compose.yml` 只给 app 加了一个裸变量名 `VMQ_WEBHOOK_ACCEPT_LEGACY`。
原理与配置细节见 `VMQ_SETUP.md` 一～五节。

## 一、改了什么

- **10-18 事故修复**：order#3018 ¥5.40 付了没对上——支付宝通知标题里的推广语「开启收款助手」被旧代码判成微信。现在渠道只按 SmsForwarder 的 `[from]` 包名判。
- **微信支付**：与支付宝共用一个唯一金额池（锁 key 固定 `<分>-2`）；到账只按金额匹配、按实际到账渠道记流水（`WECHAT`）。
- **防伪造**：来源必须是支付宝 / 微信 App；金额必须在系统到账通知的固定位置（防聊天消息冒充，不符进「待人工核实」并推送）；
  回调不再把整个请求体当通知内容，落库与日志前抹掉密钥。
- **收款码分渠道**：后台「收款监控 → 收款码（支付宝）/ 收款码（微信）」；微信默认「未启用」，上传并「设为当前」后结算弹窗与收银台才出现微信支付。
- **结算弹窗**：支付方式移进固定底栏（不用往下滑）；收银台可在支付宝 / 微信之间切换，金额不变。
- **文案**：全站「支持支付宝」→「支持支付宝和微信支付」；接码里叫「扫码支付」；营销邮件写「支付宝等扫码付款」（阿里云禁发「微信」）；
  接码条款版本升到 2026-10-18（买家下次下接码单会重新同意）。

## 二、环境变量（只改 .env.production，不进仓库）

```
VMQ_WEBHOOK_TOKEN=<openssl rand -hex 24，服务器上生成，不出现在任何对话 / 文档里>
VMQ_WEBHOOK_ACCEPT_LEGACY=1   # 过渡期：旧的 VMQ_KEY 也还认
```

原来没设 `VMQ_WEBHOOK_TOKEN`，回调一直用 `VMQ_KEY` 校验；那是 Cloudflare 隧道令牌的前 22 位（弱），10-18 又因手机端微信规则配错被写进了日志。
**两台手机都换成新 token、后台「最近一次被手机使用旧 token」不再更新后**：删掉 `VMQ_WEBHOOK_ACCEPT_LEGACY=1` 这一行，`docker compose --env-file .env.production up -d --no-deps app`（不用构建）。

同一条通知重发 → 忽略。原有问题（与本次无关）：`check-seo-copy` 在未改动的 main 上也报错；`itest-jiema-s2b` 在 tsx 下 `react.cache` 崩。

## 四、回滚

```bash
docker tag beiguo-shop-app:rollback-8568e0c beiguo-shop-app:latest && docker compose --env-file .env.production up -d --no-deps app
```

**注意**：旧代码是「`VMQ_WEBHOOK_TOKEN` 有值就只认它」。回滚时如果手机还没换成新 token，必须同时把 `.env.production` 里新加的两行删掉，
否则旧代码只认新 token，**每一笔真实到账都会被拒**。手机已经换好新 token 的话保留 `VMQ_WEBHOOK_TOKEN`、只删 `VMQ_WEBHOOK_ACCEPT_LEGACY`。
库不用回退：`vmq_payqr_wechat`、`vmq_legacy_token_at` 两行旧代码不读；已经记成 `WECHAT` 的流水旧代码的对账会当成非扫码收款（只影响对账提示）。
