# 发票流程改造 · 部署说明

> 2026-09-24。改的是**钱和税票**，比平时的功能上线更需要按顺序走。

---

## 一、这次改了什么

买家原来只能「先付款 → 再去订单页申请发票 → 再单独付一次 6% 税费」。
公司报销不接受两条付款记录，所以改成：

1. **结算弹窗加「同时开具增值税发票」**，勾了就按 `商品金额 × 1.06` 一次收清，
   可以从已保存的抬头里点选，也可以手填并勾「保存下次用」
2. **个人中心 → 快捷功能 → 抬头管理**（`/profile/invoice-titles`），新表 `invoice_titles`
3. **内推单天然按内推价开票** —— `Order.amount` 建单时就是推广人的专属价，
   开票基准取的就是它，代码里没有也不需要内推分支
4. **付款到账 = 发货 + 提交开票同时发生**（`lib/vmq.ts` 的 `fulfillOrder`）
5. **没勾的仍可事后补开**，流程不变，只是多了抬头快选
6. **后台可手动录入站外客户的发票**，与站内发票一起进批量导出
7. **税号登记时抹掉全部空白**（含全角空格、零宽字符），去空格后超 20 位直接拦

### 一条必须记住的设计线

**`Order.amount` 永远是不含税货款，6% 单独放 `Order.invoiceTaxFee`。**

`amount` 同时是 `Payment.amount`、单卡售价分摊（`splitAmount`）、内推返现、
后台流水与利润的基准。把税折进去，这些数字会**全部虚高 6%**。
收银台收的是 `amount + invoiceTaxFee`，两处口径在
`api/pay/vmq/create` 与 `api/admin/orders/[id]`（改价）各写了一遍，改动时要一起改。

## 二、部署顺序（**先改库，后换镜像**）

新的 Prisma Client 永远会显式列出新列，所以**新镜像跑旧库必挂**（P2022 / P2021）：
`fulfillOrder` 读订单会点名 `invoice_tax_fee`、`invoice_info`，查发票会点名 `user_id`、`source`。
反过来**旧镜像跑新库完全正常** —— 八条 DDL 全是新增，旧代码不读也不写它们。

所以顺序只能是：**先 db push，再 build/up**。`scripts/deploy.sh` 的默认顺序
（up -d 之后才 db push）对这次改动是反的，**不要直接跑它**。

```bash
cd /opt/beiguo/beiguo-shop
git pull origin main

# ① 备份（必须校验，否则可能是个半截文件）
docker compose --env-file .env.production exec -T db mysqldump -uroot -p"$MYSQL_ROOT_PASSWORD" \
  --single-transaction --routines --triggers --set-gtid-purged=OFF beiguo_shop \
  > /opt/beiguo/backups/beiguo_shop_$(date +%Y%m%d_%H%M%S).sql
tail -3 /opt/beiguo/backups/beiguo_shop_*.sql | grep "Dump completed"

# ② 预览 DDL，确认零 DROP（deploy.sh 写死了 --accept-data-loss，不会有任何提示）
docker run --rm --network beiguo-shop_app-network -v "$PWD/prisma":/work/prisma -w /work \
  -e DATABASE_URL="mysql://root:$MYSQL_ROOT_PASSWORD@db:3306/beiguo_shop" \
  -e PRISMA_ENGINES_MIRROR=https://registry.npmmirror.com/-/binary/prisma \
  node:20-alpine sh -c 'apk add --no-cache openssl; npx -y prisma@5.22.0 migrate diff \
    --from-url "$DATABASE_URL" --to-schema-datamodel prisma/schema.prisma --script'

# ③ 确认只有下面这八条（全部 ADD COLUMN / CREATE TABLE / CREATE INDEX）后再 push
#    把上面最后一行换成：npx -y prisma@5.22.0 db push --skip-generate

# ④ 再 build + up（约 6-7 分钟，必须后台跑再轮询，见交接文档第二节）
docker compose --env-file .env.production build app
docker compose --env-file .env.production up -d
```

### 预期的八条 DDL（全部是新增，零 DROP）

| # | 语句 | 说明 |
|---|---|---|
| 1 | `orders` ADD `invoice_tax_fee` DECIMAL(10,2) NULL, ADD `invoice_info` TEXT NULL | 可空、追加在末尾 → INSTANT |
| 2 | `external_orders` ADD `shop_order_id` INT NULL | INSTANT |
| 3 | `invoices` ADD `user_id` INT NULL, ADD `source` VARCHAR(10) NULL | INSTANT |
| 4 | CREATE TABLE `invoice_titles` | 新表 |
| 5 | CREATE INDEX `external_orders_shop_order_id_idx` | INPLACE / LOCK=NONE |
| 6 | CREATE INDEX `invoices_user_id_idx` | 同上 |
| 7 | CREATE INDEX `invoices_source_status_idx` | 同上 |
| 8 | `invoice_titles` ADD FOREIGN KEY → `users(id)` ON DELETE CASCADE | 子表刚建、空表，代价为零 |

**若 diff 里出现任何 DROP，立刻停下**。那说明线上库有 schema.prisma 里没有的对象
（手工加的索引、临时表），`--accept-data-loss` 会把它们静默删掉。

`ON DELETE CASCADE` 是安全的：删用户只会连带删掉他保存的抬头，
历史发票把抬头整份快照在 `invoices` 表里，不受影响；全站也没有批量删用户的地方。

## 三、上线后必须跑一次的回填

```bash
# 先 dry-run 看会改什么
docker compose --env-file .env.production exec -T app node -e "require('child_process')" 2>/dev/null
docker compose --env-file .env.production run --rm app npx tsx prisma/backfill-tax-number.ts
# 确认无误后
docker compose --env-file .env.production run --rm app npx tsx prisma/backfill-tax-number.ts --apply
```

它做两件事：

1. **抹掉存量发票税号里的空格**。登记侧和导出侧都已经兜住了，这一步是让后台看到的
   和导出的一致。**去空格后仍超 20 位的一律跳过不改** —— 那种数据是把公司名也粘进了
   税号框，空格恰恰是人工核对时唯一能看出「税号到哪结束」的线索，抹掉不可逆。
2. **给存量背书外部订单打上「不参与自动提醒」**（`sourceKey` 以 `order:` 开头的那些）。
   它们的 `expireDate` 是「付款日 + 1 个月」硬写的假日期，跟真实订阅周期无关；
   不处理的话，买过一次性卡密的买家一个月后会收到「你的订阅即将到期，请续费」。
   代码里自动提醒与后台提醒都已经加了结构性过滤，这一步只是把存量也洗干净。

## 四、上线后自测清单

前台（用一个测试账号，买最便宜的商品）：

1. 商品页 → 立即购买 → 勾「同时开具增值税发票」→ 应付金额变成 `商品价 × 1.06`，
   并拆出「商品金额 / 发票税费」两行
2. 税号框里敲带空格的（`9111 0108 MAER 0M7A 3L`），能提交；敲 21 位以上，当场红字拦住
3. 勾「保存这个抬头」→ 支付 → 个人中心 → 抬头管理，应该能看到它
4. 付款成功后：卡密照常发出；订单页该单显示「已提交开票」且**不再出现「申请发票」按钮**；
   订单详情里「发票税费 +¥x · 实付 ¥y」这一行在付款后仍然看得见
5. 交易邮件里是「商品金额 / 发票税费 / 实付金额」三行，实付金额与支付宝账单一致
6. 再买一单**不勾**开票 → 付款 → 订单页「申请发票」还在 → 点开，
   顶部应出现刚才保存的抬头，点一下整份填入 → 提交 → 跳转支付 6% 税费（老流程）

后台：

7. 发票管理 → 统计卡多了「手动录入（站外）」；下拉里多了「— 只看手动录入（站外）—」
8. 「手动录入发票」→ 填开票金额（含税）1060 → 下面提示「不含税 1000.00 + 税额 60.00」
   → 录入 → 在「只看手动录入」里能看到，且在「已提交开票」筛选里也能看到
9. 「导出待开发票」→ 打开 xlsx，确认站内单和刚录的站外单都在，税号列里没有空格
10. 企业微信：勾开票的单支付后，应收到两条 —— 「订单已支付」（含商品金额/发票税费/实收金额）
    和「发票可开具」

## 四·补 · 结算弹窗的尺寸约束（改这个组件前必读）

`src/components/purchase-modal.tsx` 勾上开票后会多出一整张表单。上线当天踩过一次：

> 1440×900 实测整卡高 **1220px**，而外层是 `items-center` 居中且**不滚动**，
> 于是上下各溢出 160px，「确认支付」按钮落在 y=943 —— 在屏幕外且滚不到。
> 买家勾了开票就付不了款。

现在的结构必须保持：

- 整卡 `flex flex-col max-h-[88vh]`，中间主体 `min-h-0 flex-1 overflow-y-auto` 自己滚
- 付款按钮在**不随滚动的底栏**里（`shrink-0` + `border-t`），任何时候都看得见
- 勾开票时弹窗放宽到 `sm:max-w-2xl`；`max-w-md` 里每个字段独占一行，高度直接翻倍
- 地址/电话/开户行/卡号默认折叠，选中的已保存抬头带了这些内容时自动展开

实测（勾开票后）：1440×900 → 792px、1366×768 → 676px、375×812 → 715px，三档都完整入屏、
按钮可见、主体可滚、无横向溢出。**往这个弹窗里加东西之后，请重新量一遍这三档。**

## 五、已知的残留项（**不是 bug，是已经权衡过的取舍**）

1. **实收额可能比票面多 1~50 分。** V免签靠「唯一金额」区分是谁付的款，
   `allocateAmount` 在金额被占用时会逐分上浮（最多 50 次）。买家实付 ≥ 票面，
   报销不受影响；结算弹窗的文案已经写明「可能为区分订单微调几分钱」。
   这是收款方案的固有特性，不是这次改动引入的。
2. **CSV 批量导入的外部订单不写 `shop_order_id`。** 那条路是给闲鱼这类站外订单用的，
   理论上如果拿它导入一条恰好对应站内预收单的订阅，买家能从「邮箱查订阅」再开一张票。
   管理员自己控制导入内容，没有做模糊匹配去猜 —— 猜错的代价比漏掉更大。
3. **后台「全部状态」视图看不到手动录入的发票。** 那个视图以订单为主表分页，
   手动录入的没有订单。下拉里有独立入口，统计卡也有单独一格。
4. **发票明细的税率仍是 `0.01`**（`lib/invoice-export.ts`）。
   那是票面的征收率，与向买家收的 6% 服务费是两回事，本次没有改动。

## 六、出问题怎么回退

代码回退不需要回退数据库 —— 八条 DDL 全是新增列/新表，旧代码不读它们：

```bash
git checkout <上一个 commit>
docker tag beiguo-shop-app:rollback-xxx beiguo-shop-app:latest
docker compose --env-file .env.production up -d
```

唯一要注意的是：回退后，**已经勾选开票并付过款的订单**，其 `invoice_tax_fee` 仍在库里
但旧代码不读，收银台会按纯货款收钱。回退前先确认没有这类待支付订单：

```sql
SELECT id, order_no, amount, invoice_tax_fee FROM orders
WHERE invoice_tax_fee IS NOT NULL AND pay_status = 'UNPAID';
```

## 七、这次改动顺带修掉的既有缺陷

都是围绕发票链路查出来的，与新功能无关但同属一条链：

| 缺陷 | 位置 | 影响 |
|---|---|---|
| `POST /api/invoices/[id]/pay` **零鉴权** | 同名路由 | 发票 id 是自增整数，遍历即可探出每张待付发票的税费（= 订单金额），还能占掉唯一金额锁 |
| 税费与票面**差一分钱** | `lib/invoice.ts` | `round(p×1.06)` 与 `round(p×0.06)` 两次独立取整，2030 个价格（.25/.75 结尾）对不上账。已改为按分算、税费由减法导出 |
| `fulfillInvoice` 不是 CAS | `lib/vmq.ts` | 补单与真实到账并发时会重复推送企业微信，每条还各带一个免登录财务台链接 |
| 后台「标记已完成」那条路**不核销优惠券** | `api/admin/orders/[id]` | 闸门判的是请求体里的 `payStatus`，而前台从不发这个字段 —— 这个分支一直是死代码 |
| 导出的税号**只 trim 首尾** | `lib/invoice-export.ts` | 中间的空格原样进 xlsx，税局报「长度不能超过20」并退回整批 |
| 手动录入的发票在后台**查无此人** | `api/admin/invoices` | 列表以订单为主表，无订单的发票进得了导出、却在后台看不见 |
| 背书外部订单会触发**续费提醒** | `lib/reminder.ts` | 买一次性卡密的客户一个月后收到「你的订阅即将到期」 |
