# 渠道站成交弹窗 + 主站注册 / 下单 IP（2026-10-31）

## 改了什么

**渠道站成交弹窗**（`features.liveOrders`：只在 ACTIVE 的渠道打开）

- 数据：`/api/orders/recent` 的渠道分支 = 主站单 + 本店单，只含本店在售商品，不含其他渠道的单。
- 时间：`relativeOrderTime(order.createdAt)`，服务端算好下发 `timeLabel`，不下发精确时间。
- 地点：订单的 `create_city`，没有记录就不下发、不显示。
- 不补示例订单；每条之后重新抽 8–15 秒的间隔。
- 主站弹窗与主站接口的返回没有改。

**主站 IP 记录**

- `users.register_ip`、`orders.create_ip`、`orders.create_city`，全部可空。历史数据为 NULL，不回填。
- 只写主站（`sf.kind === 'PLATFORM'` 的注册、`/api/orders` 主站分支）。接码、充值、机器人建单和渠道单不写。
- 后台查看：用户详情页「注册 IP」，订单详情「下单信息」。
- 不进买家接口和渠道后台（`BUYER_FORBIDDEN`、`PARTNER_FORBIDDEN_KEYS`）。
- 保存 3 年，`api/cron/cleanup` 到期清成 NULL。隐私政策已写明，`PRIVACY_UPDATED_AT` 升到 2026-10-31。

## 城市的前提

`create_city` 来自 Cloudflare 的 `cf-ipcity` 请求头，要在 Cloudflare 打开 **Rules → Settings → Managed Transforms → Add visitor location headers**。
没打开时城市一律为空，弹窗只显示时间；IP 不受影响。自定义域名所在的每个 Cloudflare 站点都要各开一次（只影响在该域名上下的主站单，主站是 bigolab.com）。

处理：`docker stop jishi-cloudflared`（restart=unless-stopped，保持停止）；wrapper 改为只拉起 `app nginx`。
验证时不要只从容器内测：内部请求不经过隧道，发现不了分流。切换后要从外网连续请求几次首页，核对标题。
