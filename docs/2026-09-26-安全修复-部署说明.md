# 2026-09-26 安全修复版本：改了什么、怎么部署、怎么回滚

> 审计 9 个维度、108 条原始报告 → 归并 54 组 → 逐组对抗核实（结论与修复方案存档于会话 scratchpad `verified/Gxx.json`），
> 实施后经过三轮审查（分包审查、跨包审查、上线前四视角终审）。这是渠道分站（`docs/多渠道分销-设计.md`）之前的「P0 前置安全加固」。

## 一、最要紧的几处（线上此前就在漏）

| 问题 | 以前 | 现在 |
|---|---|---|
| 找回密码验证码可穷举 | 6 位码不限次数、接口不限流：知道邮箱就能改任何人的密码（含唯一的后台管理员） | 每张码最多试 5 次、按 IP 限提交、CAS 消费 |
| 凭邮箱查订阅 / 改提醒 / 开票开收据 | 「说出邮箱就算本人」：同行拿客户邮箱就能看全部订阅、收据（含付款人抬头）、提醒手机号，改发票抬头、抢开盖章收据 | 必须先用邮箱验证码证明归属（`lib/email-proof.ts`，30 分钟有效）；站内订单只认下单本人登录 |
| 绑定任意邮箱 | 绑上就能看对方订阅与手机号 | 绑定须验证；未验证的只显示「待验证」 |
| 客户名单枚举 | 注册 / 发码 / 登录三处响应不同 | 响应、状态码、时延统一；实情只写在邮箱本人收到的信里 |
| JWT 密钥缺失 | 回落公开默认值 `your-secret-key` | fail closed（`lib/jwt-secret.ts`） |
| 会话吊销 | 改密码后旧 token 仍有效 30 天 | `User.sessionEpoch`：重置密码 / 禁用账号即失效 |
| 登录 redirect | `javascript:` 可在本站执行脚本、可跳外站 | `lib/safe-redirect.ts` |
| 后台 CSRF | 兄弟子域可对后台发简单 POST | `adminGuard` 与 `requireAdmin` 都做同源校验（`lib/same-origin.ts`） |
| 精确库存 | API 与页面源码给精确张数 | 只给档位代表值（`publicStock`） |
| 收款链路 | 履约失败订单永停「待支付」、同金额错标、单账号占满金额池、webhook 令牌可走 URL 等 | 对账 cron 补履约、翻转带金额 CAS、每人待付上限、令牌只认头/正文（见 VMQ_SETUP.md） |
| 其他 | 上传、论坛游戏刷量、SSRF、企业微信注入、Next 14.2.3 CVE、安全头、日志轮转、cron 密钥走 query… | 见各文件注释 |

## 二、部署要点（顺序不能改）

**schema：只新增 3 列**（`migrate diff` 预览必须恰好是这些、零 DROP）：
```
ALTER TABLE `user_accounts` ADD COLUMN `verified_at` DATETIME(3) NULL;
ALTER TABLE `users` ADD COLUMN `email_verified_at` DATETIME(3) NULL,
                    ADD COLUMN `session_epoch` INTEGER NOT NULL DEFAULT 0;
```
新镜像的 `getCurrentUser` 会读 `session_epoch`：**必须先 db push 再换镜像**，反过来全站登录态接口 500。

**回填**（db push 之后执行一次）：2026-06-10 起注册强制验码，生产核实这 664 个用户都有已用的注册码 → 记为邮箱已验证；
更早的 47 个与全部「非本人邮箱」的绑定保持未验证（设计如此：需要验证一次）。
```sql
UPDATE users u SET email_verified_at = u.created_at
 WHERE u.email_verified_at IS NULL AND u.created_at >= '2026-06-10 10:05:16'
   AND EXISTS (SELECT 1 FROM email_codes c WHERE c.email = u.email AND c.purpose = 'REGISTER' AND c.used = 1);
```

步骤：打回滚标签 → 备份并校验 `Dump completed` → `git pull` → 临时容器 `migrate diff` 预览 → `db push`（不带 `--accept-data-loss`）→ 回填
→ 按 `docs/nginx-真实IP修复-部署说明.md` 重建 nginx（端口 80:8080，本版本也在它的基础上加了安全头、cron 屏蔽等）
→ 构建期临时 `vm.swappiness=60` + buildkit 内存组 swappiness=60（构建完改回 0）→ `up -d --no-deps app` → `up -d --no-deps --force-recreate cron`（crontab 改成请求头带密钥）→ 冒烟。

上线前已只读核实：隧道经容器网络连 `nginx:80`；SmsForwarder 用 POST 且令牌不在 URL；通知来源 `com.eg.android.AlipayGphone`；
binlog ROW；镜像内外 `.env.production` 一致；无「到账未履约」卡单；JWT_SECRET 非空非占位；管理员密码不是种子默认值。

**新增可选 env**（都有默认值，不配也行）：`VMQ_REUSE_COOLDOWN_MIN`(15)、`VMQ_MAX_OPEN_PER_USER`(3)、`ORDER_PAY_WINDOW_MIN`(1440)、
`UPLOAD_MIN_FREE_MB`(2048)、`COUPON_CLAIM_SALT`（轮换 JWT_SECRET 时才需要）。若以后给 `NOTIFY_EVENTS` 配白名单，要带上
`payment.fulfill_failed`、`payment.duplicate`、`vmq.unmatched`。

## 三、上线后买家与站长会看到的变化

- 邮箱查订阅多一步验证码（30 分钟内不用再验）；本站订单的开票 / 收据 / 付税费请登录后在「我的订单」操作。
- 个人中心的绑定账户：绑的是本人已验证的登录邮箱直接生效，其余显示「待验证」、各验一次。
- 注册页发码后，已注册的邮箱收到的是「请直接登录」说明信；找回密码输入未注册邮箱会收到「本站没有该账号」说明信。
- 单次最多买 10 件；同一账号最多 3 笔同时在等付款的订单。
- 后台：取消已付订单后会逐条提示需人工处理的事项；收款监控页有「待人工核实的到账」队列；订单利润已扣内推返现。

## 四、回滚

- 镜像：`docker tag beiguo-shop-app:rollback-<旧HEAD> beiguo-shop-app:latest && docker compose --env-file .env.production up -d --no-deps app`。
  新增的 3 列旧代码不读，**不用回退 schema**；**绝不要**用旧 schema 跑 db push（会 DROP 这 3 列）。
- nginx / compose：`git checkout <旧HEAD> -- nginx/nginx.conf docker-compose.yml cron/crontab`，再重建 nginx、cron。
- 应急进后台（站长忘记密码又收不到码时）：在服务器上用 node 生成 bcrypt 哈希后直接 `UPDATE users SET password_hash=…, session_epoch=session_epoch+1 WHERE id=1`。
