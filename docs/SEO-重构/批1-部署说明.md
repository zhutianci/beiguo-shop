## 一、改了什么

### A · 技术止血

- `src/lib/seo/og.ts` 新增 `pageOg()` 工厂：公开页的 og:title / twitter:title 与 `<title>` 同一个字符串，并且必带 og:site_name、og:locale 与分享图。
  首页、/about、/support、/news、/terms、/privacy、/links、/iptools、/forum、/games、/chongzhi/claude-zhuce 改用它；大事记详情页补 `OG_SITE`。
- 根 layout（`src/app/layout.tsx`）：兜底的 title / description 改成品牌中性的一句（「贝果科技 BigoLab - AI 订阅充值与 AI 行业动态」），删掉 keywords；
  渠道站兜底另用一份 `CHANNEL_TITLE / CHANNEL_DESCRIPTION`（不写主站域名，也不提大事记）。rebase 时把 main 10-05 渠道白标的 `brandedMetadata` 也改成用渠道版兜底，并且不再补一个空的 keywords。
- 白标渠道首页（渠道设了浏览器标题时）og:site_name 换成渠道站名（rebase 后 pageOg 带进来的「贝果科技」，mods-brand 抓到）。
- 新增中文 404（`src/app/not-found.tsx`）：带导航入口，robots 为 noindex（设计 §6.8 已记为已知）。
- 大事记详情页：商品入口改成干净的 `/products`，原来的 `?n=` 去掉，并包进一个「广告 · 本站服务」区块。
- /forum、/games 改成 `noindex,follow`，并且从 sitemap 移出。
- /about 按 §3.2-J 重写，改成服务端组件，首帧可见；事实口径来自 `about-context.ts`，开票写明 6%。
- /support 的 title 有两版，按接码是否开放出；仍外包 main 的 `brandMetadata`，渠道改了站名时照样替换。
- robots 主站 `*` 组加 `Allow: /lookup$`：`/lookup?x=1` 仍被 `Disallow: /lookup` 挡住，按最长匹配规则判定。
- 新增 `scripts/check-seo-copy.ts`：文案 lint，带基线与 `--base` 参数。

### B · 公告提示条、LCP、首帧、站标

- **左下角成交弹窗：按站长 2026-09-30 的决定保留，不改。** `live-order-notification.tsx`、`/api/orders/recent`（含 city）、`itest-security.ts` 都与 origin/main 逐字相同。
- 公告：首次访问不再弹全屏窗，改成页面底部一条可关闭的提示条（标题 + 查看详情 + 关闭），全文仍在原来的弹层里看。
  - 已读键沿用 `announce_seen_<id>`；强提醒每次进站都出提示条。
  - 在 /jiema/* 页面让位，不挡下单确认条。
  - 提示条的高度写进 `--announce-bar-h`，右下角客服据此上抬。
  - main 10-05 的渠道分站公告原样保留：公告 id 可以是字符串，渠道站也挂公告。
  - 主站后台「站点公告」和渠道后台「店铺公告」的说明文字都改成提示条的说法。
- 页头：改成普通 `<header>`；首帧可见的修复 main 10-01 已经上线，这里不重复改。导航高亮和移动菜单的动效改用 CSS。
  Logo 链接加 `aria-label="<站名>首页"`，菜单按钮补上可读名称。
- 站标：生成 `public/logo-mark.webp`（80x80，3.5KB）和 `public/logo-full.webp`（261x256，19.6KB）。主站页头页脚改用它们，加 `loading="lazy"`，`<head>` 里不再 preload PNG 站标。
  白标渠道的 logo 不动；PNG 文件不删，邮件、JSON-LD、分享图仍在用。
- 大事记详情的微信缩略图：加 `object-cover` 和 `fetchPriority="low"`，格式仍是 PNG。
- framer-motion：页头、公告、右下角客服、客服弹窗都不再引用它，改用 `globals.css` 里新增的 `ui-*` keyframes（含 prefers-reduced-motion）。
  **但成交弹窗保留了，它仍引用 framer-motion，所以共享 JS 里还有 framer-motion**，§6.6-5 的包体收益这次拿不到。
- 首页 hero 打字机：电脑端那一行按最长的短语占位，换句时 H1 不再上下跳。手机端轻量模式沿用 main 的做法（整句单独一行）。
  短语改为「可开增值税发票（开票另付 6%）」。商品页的描述模板改成「标价不含税，开票另付 6%」。
- 手机端轻量模式：`use-lite.ts`、`tailwind.config.ts` 的 `lite` 变体、`globals.css` 末尾的 @media 块都没改，三处检测仍逐字相同。
  header / floating-contact / contact-modal / announcement 里的 `lite:*` 与 `lite-blob` 全部保留；home-client 只在打字机那一行加了 `lite:block lite:before:hidden`，让手机端回到 main 的版式。

## 四、上线步骤

顺序照交接文档：回滚标签 → 拉代码 → 构建 → 只重启 app → 冒烟。**无 DDL，所以不用备份后 db push**；按惯例做一次备份也无妨。

1. 回滚标签（**在 build 之前打**）：`docker tag beiguo-shop-app:latest beiguo-shop-app:rollback-$(git rev-parse --short HEAD)`
2. `git pull origin main`（合并后），确认 `git log -1` 是本批的提交。
3. 构建：照交接文档的 `build-with-swap.sh`。
   - 构建前先问站长，临时放开 swap；`df -h /` 要留够 2G。
   - 构建堆用 Dockerfile 默认的 832MB；构建前看 `free -m` 的 available，低于约 800MB 时先停协议服务（见微信机器人部署说明）。
   - 构建完把 swappiness 还原成 0。**绝不跑 `docker system df`。**
4. `docker compose --env-file .env.production up -d --no-deps app`
5. 第六节的冒烟检查。
