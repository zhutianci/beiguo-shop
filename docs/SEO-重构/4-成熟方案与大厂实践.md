## 1. Google Search Central 现行规则

### 1.1 有用内容与 E-E-A-T（文档 2025-12-10）[S2]

- 自评按「Who / How / Why」三问：谁写的（署名、背景）、怎么做的（**用了自动化或 AI 要说明**）、为什么做（为用户，不为排名）。
- **Trust 最重要**，其他三项（经验、专业、权威）都服务于它。涉及钱的页面（YMYL，含交易）标准更高。
- 文档里明确点名的「搜索引擎优先」信号：**大量追热点、重度自动化、人为改发布日期**。第三条直接关系到标题里写「2026 年 9 月更新」这种做法：只有内容真的改过才能改日期。
- 评估员指南（2025-01）：主体内容几乎全是 AI 生成、又几乎没有增量价值的页面，直接评「最低」；新加了 filler（凑字数）和 scaled content abuse 两节 [S26]。

### 1.2 垃圾内容政策（文档 2026-08-28）[S1]

| 政策 | 官方定义要点（原文见 [S1]） | 对本站程序化页的边界 |
|---|---|---|
| **Scaled content abuse** | 主要目的是操纵排名而不是帮用户的大批量页面。例子有：「用生成式 AI 批量生成页面却不增加价值」「抓取 feed / 搜索结果拼页面」「对读者没意义、只含关键词的页面」 | 大事记薄页 noindex 的做法是对的（第二十四节）。接码不能按「服务 × 国家」全量铺页 |
| **Doorway abuse** | 为一批相近查询做页面，把用户导向中间页。例子有：「针对地区 / 城市的多个域名或页面把人导到一处」「生成页面只为把人导进站点真正可用的部分」 | 接码服务页只有能**就地预选、就地下单**，并且带独有数据时才不算门页；同一意图（接码 / 虚拟号 / 收验证码）只做一页 |
| **Site reputation abuse** | 第三方内容借宿主站的排名信号发布；2025-01 并入正文，2026-08 调整了欧洲经济区的执行方式 [S5] | 渠道分站（lulu.*）必须保持现状：整站 noindex、屏蔽 AI 爬虫、sitemap 为空。**永远不要放开收录** |
| **Keyword stuffing** | 原文举例：「**Lists of phone numbers without substantial added value**」「列城市和地区名的文本块」 | 直接点名了「号码列表」。**不做公开号码页或「今日可用号码」列表页**（免费接码站那种） |
| **Thin affiliate / Scraping** | 照搬商家描述、转载不加价值 | 大事记只写自己的摘要、外链原文（现在就是这么做的） |
| **Misleading functionality** | 声称能提供其实提供不了的服务 | 灰度期接码页不能对外宣称「可下单」（第三十四节已用 noindex 挡住） |
| **Link spam** | 买卖链接、「过度的友链交换」；带 `rel=sponsored/nofollow` 就不违规 | /links 的付费位已经带 sponsored（`link-card.tsx`）。**友链交换页不能大规模互换** |
| **Back button hijacking**（2026-04-13 新增）| 操纵浏览器历史，让用户退不回来源页 | 支付 / 接码流程里不要用 `history.pushState` 去拦「返回」 |
| 举报可能直接触发人工处罚（2026-04-14）| — | 同行举报的风险变高了，规则要按字面执行 |

### 1.4 Core Web Vitals

- INP 在 2024-03-12 取代 FID [S17]。阈值：LCP < 2.5s、INP < 200ms、CLS < 0.1 [S18]。按 CrUX 真实用户数据的第 75 百分位算。
- 官方说法是 CWV「与核心排名系统想奖励的东西一致」，没有给出权重 [S18]。**[本站]** 流量小的页面通常没有 CrUX 数据，只按整站评估，所以 CWV 不是现在的主要矛盾。重点做两件事：
  - `/jiema` 是重客户端组件：搜索框要防抖或用 `useTransition`，服务列表要虚拟化，防止 INP 超标。
  - 落地页保持零 `'use client'`（第二十四节）。

### 1.5 标题链接与摘要

- Google 用来生成标题链接的来源：`<title>`、页面上的主标题、`<h1>`、`og:title`、醒目的大字、锚文本、外链文字、WebSite 结构化数据 [S19]。
- 常见的改写原因：标题半空、**年份过时**（原文：同一页面年年复用、`<title>` 却没更新日期）、与内容不符、样板化、「微样板」（相似页只差一个关键区别词）、语言不一致、页面上有多个同样醒目的标题 [S19]。
- 原文特别提醒「**避免在 `<title>` 里放机票价格**」，因为这类价格变化太快 [S19]。本站的推论：**变化快的价格（接码）不进标题**；稳定的起步价可以进（见 §5）。
- 摘要**主要来自正文**，只有 meta description 更准确时才会用它；商品页应该在描述里写价格、规格等关键事实 [S20]。
- 2026-04-20 新增「read more」深链：正文要默认可见，不要用 JS 劫持滚动，保留 URL 的 `#hash` [S20]。**[本站]** FAQ 手风琴默认折叠会影响深链定位。关键答案的第一句要默认可见。

### 1.6 Sitemap、lastmod、IndexNow

- `lastmod` 只有「一贯、可核验地准确」时才会被采用。只有正文、结构化数据或链接变了才更新它，改版权年份不算。`changefreq` 和 `priority` 被忽略。单个文件上限 5 万条 URL 或 50MB（文档 2026-07-08）[S21]。
- **IndexNow**：支持方是 Bing、Yandex、Naver、Seznam、Amazon、Yep，**Google 不支持**；提交一次会共享给所有参与方 [S22]。
- Bing 2025-07 的博客：sitemap 加上准确的 lastmod 是 **AI 搜索（Copilot）接地（grounding）**的基础信号，建议和 IndexNow 一起用 [S23]。
- **[本站]** 目前 IndexNow 只推新闻的首发。**建议扩到商业页**：`/chongzhi/*`、`/products/*`、`/jiema*` 在价格或正文变化时也推，lastmod 取真实的变更时间。Bing（国际版和 cn.bing）是本站第二大搜索来源，也是 ChatGPT 的检索来源之一（§4）。

### 1.7 带筛选参数的 URL（faceted navigation）

- Google 建议：不需要收录的筛选 URL 用 robots 挡掉，或者改用 `#fragment`；也可以 canonical 指回无参数页；筛选组合没有结果时返回 404（文档 2025-12-18）[S25]。
- **[本站]** `/jiema?s=&c=&op=` 已经 canonical 到 `/jiema`，robots 也有 `Disallow: /*?s=`，两者一致，保持。
- ⚠️ **P2 做 `/jiema/[slug]` 时有个坑**：`src/app/(shop)/jiema/layout.tsx` 在 layout 里写了 `alternates: { canonical: '/jiema' }`，子路由会继承这条 canonical。这正是第二十四节第 8 条④说的规矩（「canonical 不能写在带子路由的 layout 里」）。`/jiema/terms` 已经自己覆盖了；`records`、`order` 页是 noindex 加继承来的 canonical，信号混杂但无大碍。**以后每个服务页都必须自己写 canonical**，否则会集体自称是 `/jiema` 的副本。最好直接把 canonical 从 layout 挪到 `page.tsx`。

### 1.8 Discover 与「首选来源」

- Discover 不需要任何标记。图片要宽 ≥1200px 并开启 `max-image-preview:large`，不要用 logo 或文字很多的图；标题不要做标题党；流量本来就不稳定（文档 2026-03-09）[S27]。
- **[本站]** 大事记按规定**不能用原文配图**（SKILL §1.1），自制文字图又是 Discover 不推荐的，所以对 Discover **不要有期望**。
- Preferred Sources（首选来源，按钮 2026-08-20 上线，能在 Top Stories / AI Overviews / AI Mode 里生效）[S28]：面向新闻源，要先出现在来源偏好工具里。**和「不是新闻站」的定位冲突，不做。**

### 1.9 AI Overviews / AI Mode（Google 官方口径）

- 「出现在 AI Overviews 或 AI Mode 没有额外要求，也不需要特殊优化」；页面只要被收录、能展示摘要即可；AI 功能带来的流量计入效果报告的「网页」类型 [S29]。
- GEO 指南（2026-05-15）：做**非大路货内容**（有第一手经验或独特数据，不是 AI 随手能写出来的东西）；「llms.txt 既不帮忙也不伤害，Google 搜索忽略它」；不需要切块、不需要 Markdown 版本、不需要专门的 schema；刷「虚假提及」没用；Search Console 有生成式 AI 效果报告；智能体方面提到了 UCP 协议 [S7][S8]。

## 2. 百度搜索资源平台

**算法与规范一览** [S32][S33]：

| 名称 | 打击什么 | 与本站的关系 |
|---|---|---|
| 飓风 3.0 | 恶劣采集、站群、跨领域内容 | 大事记只做自写摘要，不采集正文（现状合规） |
| **劲风** | 恶劣聚合页，四类：内容与站点领域不符或站点没有专注领域；题文不符；**站内搜索生成的静态结果页**；**空短、无有效信息、失效的聚合页** [S34] | 大事记标签页、接码服务页、`/chongzhi` 总览都属于「聚合页」，**必须带有效信息，不能是纯链接列表** |
| 清风 | 标题作弊（1.0）；下载站欺骗（3.0） | 标题规范见下 |
| 惊雷 2.0 | 刷点击、超链作弊 | 不刷点击 |
| 细雨 2.0 / 蓝天 | B2B 采集和软文 / 售卖目录、软文 | /links 的付费位要控制数量和相关性 |
| 信风 / 烽火 2.0 | 虚假翻页、诱导跳转 / 跳转劫持、**回退劫持** | 与 Google 的 back button hijacking 相同 |
| 冰桶 5.0 | 移动落地页体验：广告遮挡、强制登录或下载才能看 | 接码目录和价格要**不登录也能看**（现状：目录匿名可读） |
| 极光 / 时间因子 | 落地页时间标注不清 | 大事记详情页显示发布时间，可选加 `pubDate`/`upDate` 的 JSON-LD [S24] |

- **《百度搜索网页标题规范》** [S35]：推荐「核心词 + 修饰词」，**修饰词不超过 3 个**。
  - 首页：「品牌 - 首页/官网/slogan」
  - 列表页：「频道 - 上级频道 - 站点名」
  - 内容页：「标题 - 频道 - 站点名」
  - 聚合页：「主题 - 属性1 - 属性2 - 站点名」
  - 禁止：堆砌、非官方站自称「官网」、emoji、**不规范括号**、题文不符。
  - 过度优化的首页标题会被直接改写成站点名。
- **《违规低质页面问题说明》（2023-08-29）** [S36] 列出的问题：内容拼接、题文不符、空短或死链、功能失效、**首屏主体内容占比 <50%**、同屏重复功能 ≥2 个、页面不适配、加载慢。
- **没备案的现实**：业内普遍观察是百度照样收录未备案站，但抓取优先级低、收录慢 [S37]，这不是官方口径。**[本站]** 实测（第二十八节）：Baiduspider 只来过 6 次；推送配额每天 10 条；未备案站点的 sitemap 每天只能提交 1 个；百度至今没带来过一单。
- **结论**：百度只做「顺手零成本」的事：服务端直出、标题按规范、时间可见、不写「官网」。**不为百度单独做任何页面**。同等精力优先投 Bing（第二大搜索来源，而且会给 Copilot 和 ChatGPT 供数）。

## 3. 同类成熟站点的 SEO 结构

### 3.1 接码类

7. **商标或非隶属声明**（「本站与 OpenAI 无隶属关系，商标归各自所有者」），以及条款或合规链接（`/jiema/terms`）。
8. 「更新时间」**必须跟着数据真实刷新**。5SIM 那种看起来像是自动生成的日期不要学（Google 点名过人为改日期 [S2]）。

**开页门槛**（防止 scaled / doorway）：只给「本站近 30 天有真实订单、上面 1–3 条数据都拿得到」的服务开独立页；其余服务只在 `/jiema` 的目录里出现。总数先控制在 10–20 个，按 Search Console 的曝光再扩。

## 4. GEO：让 ChatGPT / Perplexity / AI Overviews 引用

### 4.1 证据

- **普林斯顿 GEO 论文（KDD 2024）**[S55][S56]：在生成式引擎里的可见度，「**加引语** +41%」「**加统计数字** +33%」「**引用来源** +28%」「提升流畅度 +29%」；「**关键词堆砌**」反而约 −9%。**排名靠后的网站收益更大**（第 5 名用「引用来源」后提升 115%）。按指标 Position-Adjusted Word Count 计，分领域效果不同。
- **Google**：GEO 不需要特殊处理，llms.txt 被忽略 [S7][S8]；**操纵 AI 回答算垃圾内容** [S1][S31]。
- **ChatGPT**：
  - 必须允许 **OAI-SearchBot**，屏蔽它就进不了 ChatGPT 搜索的答案；GPTBot（训练用）、ChatGPT-User（用户触发）、OAI-AdsBot（广告审核）各自独立 [S57]。
  - 想彻底不出现，需要 noindex，光靠 robots Disallow 不够；来访自带 `utm_source=chatgpt.com` [S58]。
  - ChatGPT 搜索用自己的索引加第三方搜索（文档点名了 Bing）[S59]，所以**在 Bing 排得好，ChatGPT 引用本站的概率也会升**。
- **Bing**：2026-02-11 在 Webmaster Tools 里上线 **AI Performance 报告**，能看到 Copilot 引用了本站哪些页、被引用多少次、对应的 **grounding queries**（AI 内部检索用的查询词）[S60]。这是**目前唯一的官方「被 AI 引用」反馈回路**，站长应该尽快启用（仓库里已有 `BING_SITE_VERIFICATION`）。
- **llms.txt**：采用率约 10%；多份服务器日志研究显示主流 AI 爬虫几乎不请求它（Ahrefs：97% 的 llms.txt 在 2026 年 5 月零请求）；真正读它的是编程智能体（Cursor、Claude Code 等）[S61]。**结论：可做可不做，零成本就做一份事实索引，但不要指望带来引用。**
- **OpenAI 商品 feed**（ChatGPT 购物）[S62]：推送制，要求 9 个字段；服务对象是海外电商。**本站只收支付宝的数字服务不适用，不做。**

### 4.2 AI 流量的量级提醒（第三方研究）

- 出现 AI Overview 时，排第一的页面平均点击率低 58%（Ahrefs，2025-12 数据）；信息类查询的自然点击率从 1.76% 降到 0.61%（Seer，2024-06 至 2025-09）。**被 AIO 引用的品牌，自然点击比没被引用的多约 35%** [S63][S64]。
- 推论：**「被引用」本身就是点击率策略**，GEO 和 CTR 是同一件事。

### 4.3 本站的 GEO 做法（全部落在「真实、可核验、带日期」上）

1. **首屏放「事实卡」**（每个商业页一份，数据全部实时取库或取代码常量，不手写）：
   - 价格：¥X，截至 YYYY-MM-DD，**不含税，开票另付 6%**
   - 交付：卡密自动发货 / 自动取号接码 / 人工办理
   - 付款：仅支付宝，下单需登录
   - 售后：退款按剩余未使用天数
   - 经营主体：XX 有限公司
   - 更新于：YYYY-MM-DD

   这正对应论文里「加统计数字」那一项，也是 ChatGPT 最常摘的句子类型。
2. **问题式 H2，首句直接给答案**（例：「国内怎么充 ChatGPT Plus？——用支付宝在本站买卡密，登录 chatgpt.com 兑换，约 X 分钟完成。」）。不需要把页面切碎 [S8]，但每一节的第一句要能单独成立。
3. **引官方来源**：官方价格、政策链到 OpenAI / Anthropic 的官方页面（对应「引用来源」），并写明「以官网为准」。
4. **中性的对比表**：官方订阅、礼品卡、本站卡密三种方式，按价格、付款方式、是否需要外币卡、风险对比。不贬低同行，不编数字。
5. **口径单一来源**：同一事实全站只有一个出处（`landing/registry.ts`、`lib/invoice.ts` 等），避免 AI 读到两套说法。第二十八节 claude-max FAQ 那次写错就是反例。
6. **主体可核验**：关于页、页脚和 Organization 结构化数据写同一个 `legalName`、`taxID`、联系方式。
7. **不要做的**：「2026 最好的 10 个充值平台」这类把自己排第一的榜单（Google 点名的 biased listicles）；到知乎或贴吧批量刷「贝果科技靠谱」（Google 说虚假提及没用、而且会被垃圾系统挡掉 [S8]）；隐藏文字给 AI 看（hidden text 政策）。
8. **反馈回路**：Search Console 的生成式 AI 报告、Bing 的 AI Performance 报告、站内埋点 `source='ai'`（第二十七节）、nginx 日志按爬虫 UA 分组（第二十八节），**每月复盘一次**，把被引用最多的页面结构复制到其他页。

## 5. CTR：标题与描述

| 维度 | 证据 | 本站写法 |
|---|---|---|
| 长度 | Zyppy 研究（8 万个标题）：Google 改写了 **61.6%** 的标题；51–60 个英文字符时被改写最少，超过 70 字符时 99.9% 被改写 [S65] | 中文标题建议 **≤30 个汉字**（按 Google 约 600px 截断估算，未实测），核心词放前 15 个字 |
| 括号 | 带方括号 `[]` 的标题被改写 77.6%（其中 32.9% 整段删掉），圆括号是 61.9% [S65]；百度标题规范点名「不规范括号」[S35] | **不用【亲测】这类方头括号**，用「｜」「-」分隔 |
| 品牌 | 品牌放开头或结尾，用分隔符；不要全站样板标题 [S19] | 统一用「… - 贝果科技」结尾；站点名称结构化数据和它一致 |
| 年份 / 日期 | 年份过时是被改写的原因之一 [S19]；人为改日期是负面信号 [S2]；竞品普遍写「2026年」 | 只在**按月真实维护的教程型页面**上写「2026」，并由代码按当前年份渲染，`dateModified` 同步；商品页不写年份 |
| 价格 | 文档只点名「变化快的价格（机票）」别进标题 [S19]；商品页的描述应该写价格 [S20] | 充值 SKU 可以写「¥X 起」（价格稳定、从数据库取，改价时 IndexNow 加 lastmod 同步）；**接码价格不进标题**（每小时都在变），在描述里写「低至 ¥X（截至 MM-DD）」，请求时渲染 |
| 疑问句 / 情绪 | Backlinko（400 万条结果）：疑问句标题和普通标题的点击率差异不显著；正面情绪约 +4%；前 3 名拿走 54.4% 的点击 [S66] | 不必改成疑问句；用「即时发卡」「支付宝」「可开发票」这类正面、具体、真实的词 |
| 富结果 | 现在能拿到的只有：商品摘要（价格、库存）、桌面端面包屑、站点名称加 favicon、站点链接 | FAQ 和 HowTo 已经没了，别再为富结果写 FAQ |

**标题模板**（关键词必须先用下拉建议验证，下面只是结构示意）：
- 充值 SKU：`{产品} 充值 - {档位} 国内购买，支付宝付款 - 贝果科技`
- 接码服务：`{服务} 接码 - 海外手机号接收 {服务} 验证码 - 贝果科技`（标题和描述里不出现国内平台名，D25 / Q6）
- 日报：`AI 日报 9月30日：{要点1}；{要点2}；{要点3} - 贝果科技`
- 首页（百度首页格式「品牌 - slogan」）：`贝果科技 - ChatGPT Plus / Claude Pro 充值 · 短信接码 · AI 大事记`。现在的首页标题「…充值代充 - 卡密自助兑换 - 贝果科技」里有「代充」。按第二十四节，「代充」只承接信任审查意图，是否留在首页标题由关键词报告定。

**描述**：每页都不一样，写 3 个具体事实（价格或起步价、交付方式、付款或开票口径），中文约 80–120 字。Google 多半会从正文取摘要，所以**首屏正文比 meta 更重要**。
