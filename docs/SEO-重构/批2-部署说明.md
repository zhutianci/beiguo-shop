## 五、没做的（与原因）
- **D1b（chongzhi 各页与 /products 的 title / description 换词）、AI 引用页第一步**：设计排在批 3（AI 基线满 4 周、与批 2 间隔 ≥2 周，便于归因）；hub、chatgpt-plus、claude-pro、grok-super 的「代充」title 仍在基线里。
- **F2 接码服务页（/jiema/google 等）**：闸门要「近 30 天已付款单 ≥20、内部收码成功率 ≥50%」，本机拿不到线上数据，盲建就是 doorway 风险；先用 hub 的「常用服务」表与「美国手机号」一节承接。
- **F1 目录懒加载**：/jiema 首包仍带完整目录（含 Telegram 等名字，check-seo-copy 基线 `sensitive-names /jiema` 留着），属 INP / 下单路径改动，留给接码会话。
- **Ha 数据层缓存**：只给首页新增的热点区块用了 `storefrontCached`；落地页快照等交给性能那条线，避免两边同时改 `lib/landing/products.ts`。
- **E1 / E2**（分类分页、话题页、日报补全条目、H1 改「AI 动态速览」）：批 3 / 批 4；本批没有新建任何 /news 路由。
- 学习平台 `loading.tsx` 下的软 404：不存在的条目已在 metadata 阶段 notFound，但带 loading 边界的流式响应状态码仍是 200（页面是「页面不存在」+ noindex）。要真 404 得把详情路由移出 loading 边界，属内容平台的结构改动，未做。
- 接码开放状态变化时推 IndexNow（改接码后台配置接口，接码会话的文件）未做；backfill 脚本里有 /jiema。
