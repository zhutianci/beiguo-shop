## 0. 一页速查（给写文案 / 改结构的人）

1. **AI 大事记不能叫「新闻」**：页面文字、title、H1、描述、结构化数据一律不用「新闻 / 快讯 / 头条 / 要闻 / 报道 / 突发」；结构化数据用 `Article` 不用 `NewsArticle`。稳妥的说法是「AI 动态」「AI 行业动态」「AI 圈大事记」；「AI 资讯」只能当次要说法，不能当站点或栏目定位。
2. **站长需求里的「AI 会员代充」「AI 大事记新闻」是业务内部叫法，不能直接当关键词**：「代充 / 代开 / 代购 / 代订阅 / AI 会员代充 / AI 代充」都是零需求词（09-19 实测），「新闻」有资质风险。对外主词：充值 / 购买；AI 动态；短信接码 / 接收验证码。
3. **不能冒充官方**：「官方」只能用来指 OpenAI / Anthropic 自己（例如「官方定价 20 美元」），绝不能用来形容本站（官方渠道、官方直充、官方授权、官方合作、正版授权等一律不写）。不用对方 logo，站名、子域名、产品名里不带 GPT / ChatGPT / Claude。
4. **接码不能写出违法用途**：「批量注册 / 养号 / 绕过（或免）实名 / 过风控 / 租号 / 卖号 / 匿名 / 不留记录 / 接码 API / 多开」都属于禁用词，其中「批量接收提供短信验证」几乎就是反电诈法第十四条第（三）项的原文。可以写的是「在线接收短信验证码」「海外手机号收验证码」「没收到短信整单退回余额」。
5. **不能出现任何上游名称**：HeroSMS、hero-sms、SMS-Activate 在买家页面和 SEO 文案里都不能出现，也不能拿它们的品牌词做关键词。
6. **数字与承诺只写代码里做得到的**：不写成功率（历史只有 31%）、不写「秒到 / 包过 / 100% / 不封号 / 全网最低」；价格、成交数、服务数从库里实时取，不写死。
7. **别动已经在被引用的东西**：`/chongzhi` 下 9 个落地页的 URL 与主体结构不要重构（第二十八节已明确叫停）；不要对 news / digest 整体加 noindex，也不要收缩新闻 sitemap；薄页 noindex 保持现状。
8. **lulu 渠道站永远 noindex**，不参与 SEO；不要为关键词开子域名（通配 `*.bigolab.com` 会自动进入渠道模式并带上 noindex）。

## 1. AI 大事记：能用、不能用的措辞与结构化数据

### 1.1 定性（全部设计都从这一条推出来）

- 契约原文（SKILL.md §1）：这是**「信息聚合工具」，不是新闻站**。《互联网新闻信息服务管理规定》第二条把「新闻信息」限定为政治、经济、军事、外交等社会公共事务以及社会突发事件的报道和评论；第五条要求取得许可。站点的策略是**让内容不落入这个定义**，而不是去拿许可证。
- 已经写进代码的配套措施：只写自写摘要、全部外链原文（`rel=noopener noreferrer nofollow`）、不转载、不用原文配图；作者硬编码为 Organization「贝果科技 AI 资讯助手」；选题黑名单在分诊阶段直接拦截（监管立法、出口管制与制裁、国家战略与军事、大规模裁员与诉讼、监管处罚与约谈下架、政治人物与地缘话题）；禁词回查 `score.ts` 的 `FORBIDDEN_WORDS`（记者、编辑部、独家、爆料、本站原创、本网讯、本报讯、特约撰稿）；AI 生成标识 6 处（《人工智能生成合成内容标识办法》第四、五条）。
- **对 SEO 的直接含义**：定性靠的是「内容是什么」加上「站点怎么自我描述」两件事。title、H1、导航、结构化数据都属于「自我描述」，而且是最容易被当作证据引用的那一部分。

### 1.2 称呼：能不能叫「新闻」「资讯」「动态」

| 说法 | 结论 | 理由 |
|---|---|---|
| 新闻、AI 新闻、新闻站 / 网 / 中心 / 频道、新闻资讯 | **禁用** | 等于书面自认在提供「新闻信息服务」，正好落进第二条的定义。`seo.ts` 文件头也把结构化数据里自称 NewsArticle 定性为「最容易被引用的一份不利证据」 |
| 快讯、头条、要闻、突发、时事、早报 / 晚报、报道、本站报道、首发、独家解读、社评、评论员 | **禁用** | 这些是新闻采编与发布的行业用语；「突发」还直接对应第二条里的「社会突发事件」 |
| 记者、编辑部、独家、爆料、本站原创、本网讯、本报讯、特约撰稿 | **禁用（代码已拦）** | SKILL §1.1，`score.ts` 禁词表，命中后摘要进复核、全文层直接丢弃 |
| AI 圈大事记（品牌名） | 可用 | 现行导航与 title 就是这个名字 |
| **AI 动态、AI 行业动态、AI 动态聚合、每日 AI 动态速览** | **推荐** | 与「行业动态聚合工具」的定位一致，也是 `/news` 现行 title「AI 圈大事记 - 每日 AI 动态聚合」的用词 |
| 模型发布、产品更新、AI 工具、AI 论文、开源项目、融资动态 | **推荐（做分类或长尾）** | 与 SKILL §1.3 允许的选题、固定 6 个分类（模型 / 产品 / 行业 / 论文 / 工具 / 观点）一一对应 |
| AI 资讯 | **慎用**：可以在正文或次要位置出现（作者名本来就叫「AI 资讯助手」），**不要当 title 主词，也不要自称「资讯平台 / 资讯网」** | 「资讯」本身不构成定性，但「新闻资讯类平台」是监管里的常见归类，拿它做站点定位会离「新闻」更近一步；拿「动态」做主词没有任何损失 |
| 日报 / 周报 | **慎用**：现有的汇总页标签可以保留（导航已经写作「速览与周报」），**不要做成「贝果 AI 日报」这种报刊式的站点级名称** | 报刊名称的形态 |
| 权威、第一手、最全、最快、零幻觉、100% 准确 | **禁用** | 广告法绝对化用语；SKILL §7 明写「不能对外宣称零幻觉」 |

> **URL `/news` 保留不改**：400 多条已收录的 URL，加上 OAI-SearchBot 与 ClaudeBot 在持续回访（第二十八节），改路径的代价远大于收益。定性看的是内容与自我描述，路径里的英文单词不构成自称。只是**不要在任何可见文字里加「新闻」二字**（目前前台可见文字里一处都没有，只有后台出现过）。

### 1.3 结构化数据类型

| 类型 / 做法 | 结论 | 说明 |
|---|---|---|
| `Article`（详情页，现行） | **可用** | `lib/news/seo.ts`：author 是 Organization，`citation` 列出全部信源，`disambiguatingDescription` 放 AI 免责声明。Google 的文章结构化数据文档把 Article、NewsArticle、BlogPosting 并列为同一种富结果的可用类型，Top stories 也不以 NewsArticle 标记为前提，**换成 NewsArticle 没有任何 SEO 收益** |
| `BreadcrumbList`、`ItemList`（列表 / 归档 / 汇总页）、`CollectionPage` / `WebPage` | 可用 | 汇总页适合用 ItemList 挂当期事件；前提是页面上能看到对应的面包屑与列表 |
| `isBasedOn` / `citation` 指向原文 | 可用，而且是加分项 | 进一步表明「本页是对公开信源的聚合摘要」 |
| `NewsArticle` 及其子类型（`ReportageNewsArticle`、`AnalysisNewsArticle`、`OpinionNewsArticle`、`BackgroundNewsArticle`、`ReviewNewsArticle`） | **禁用** | 自认新闻 |
| `LiveBlogPosting`、`NewsMediaOrganization`、`publishingPrinciples` / `masthead` / `ethicsPolicy` 这类新闻出版者属性、`dateline`、`SpeakableSpecification` | **禁用** | 都是新闻出版者专用的形态或属性 |
| Google News sitemap（`xmlns:news`、`<news:publication>`）、在 Google Publisher Center 以新闻出版物身份申请 | **禁用** | 同样是自认新闻出版物 |
| `author` 写成 `Person` / 真人署名 | **禁用** | SKILL §1.1，§10 第 5 条列为改动前必须先确认的事项 |
| `ClaimReview`（事实核查） | 禁用 | 属于编辑判断型的内容形态，而且站点对事实准确性做不了保证（SKILL §7） |
| `aggregateRating` / `Review` | 禁用 | 没有真实评价体系，第十九节第 4 条 |
| `og:type=article` | 可用 | OG 协议里的 article 不等于新闻 |
| `<meta name="ai-generated" content="true">` | **必须保留** | 6 处 AI 标识中的第 4 处，四个新闻路由都在输出 |

### 1.4 为了点击率也不能做的事（大事记）

- **标题党**：compose 契约要求 headline ≤40 字、「不做标题党」；《网络信息内容生态治理规定》第七条第（一）项把「使用夸张标题，内容与标题严重不符」列为不良信息。所以「震惊 / 重磅 / 炸裂 / 刚刚 / 突发 / 紧急 / 必看 / 速看」都不能用。推荐写法是「主体 + 动作 + 关键事实」，例如「Anthropic 发布 Claude X：上下文扩到 N」（数字必须能在材料里找到，数字回查会拦）。
- **追热门的黑名单话题**：AI 监管、芯片出口管制、裁员、下架约谈之类，搜索量再高也不做，SEO 不能倒逼放宽黑名单（SKILL §10 第 1 条，必须先确认才能改）。
- **为了停留时长加「问 AI / AI 解读 / AI 搜索框」**：一旦上线就落入《生成式人工智能服务管理暂行办法》，需要备案（SKILL §1.1）。
- **为了 UGC 开评论**：会触发安全评估重做，讨论一律用按钮导流到论坛。
- **用原文配图拿图片搜索或 Discover 流量**：侵权索赔风险。图片只用分类底图与分享海报。
- **为了「干净」去掉 AI 标识或免责声明**：属于法定义务，6 处一处都不能少（SKILL §6、§10 第 2 条）。
- **随手造标签页 / 话题页**：标签只能从 60–80 个白名单词里选，分类固定 6 个（SKILL §4）。给每个自由词开一个话题页，就是「几千个只有 1 条内容的页」。

### 1.5 大事记的收录状态（不要改动的部分）

- 没有全文层的薄页：`noindex, follow`，同时从 sitemap 排除（`lib/news/thin.ts`，开关 `NEWS_THIN_NOINDEX`，默认开）。这是 Google scaled content abuse 的止血措施，**保持现状**。
- **不要**给 `/news`、`/news/digest`、`/news/archive` 整体加 noindex，**不要**再收缩新闻 sitemap（第二十八节「审计明确叫停」第 2 条）：这批页面是 OAI-SearchBot（347 次）与 ClaudeBot（134 次）回访的理由，也是落地页站内入链的主要来源。
- sitemap 与详情页 noindex 必须共用同一个判定函数 `shouldNoindexEvent`（第二十四节第 8 条⑤）。

## 2. 广告法绝对化用语、虚假宣传与商标红线

### 2.1 适用范围

本站自己的页面（商品页、落地页、首页、关于页）都属于「利用网站、网页……直接或者间接地推销商品或者服务的商业广告活动」（《互联网广告管理办法》第二条），适用广告法。**title、meta description、og 文案、结构化数据里的 FAQ 文字都算在内**，它们还是最常被搜索结果和 AI 答案直接引用的部分。

### 2.2 绝对化用语（广告法第九条第（三）项；罚则第五十七条：对广告主处 20 万元以上 100 万元以下罚款）

- 禁用（用来形容本站或本站商品时）：最、最佳、最好、最低价、最便宜、全网最低、史上最低、第一、No.1、TOP1、首选、唯一、顶级、顶尖、极致、王牌、国家级、世界级、全球领先、100%、百分百、绝对、永久（除非就是商品本身的有效期事实）、万能、零风险、无风险、必过、包过、秒到、秒充、秒收。
- 市场监管总局《广告绝对化用语执法指南》（2023 年第 6 号公告）给出的**不适用情形**可以放心用：表明服务态度、经营理念或目标追求的（例如「宁可少写，也不骗你」）；同一品牌或同一企业商品之间的自我比较（例如「本站最便宜的一档」「先买最便宜的一档试」——现有落地页就是这么写的，没问题）；使用方法、时间、保存期限这类消费提示。
- **原则**：正文里做「本站档位之间」的比较可以；**title、description、H1 不放任何最高级**。这些位置脱离上下文单独展示，「最便宜」会被读成「全网最便宜」。

### 2.3 虚假或引人误解的宣传

依据：广告法第二十八条；反不正当竞争法（2025 年修订，2025-10-15 施行）第九条；电子商务法第十七条。

- **引证数据必须真实并注明出处**（广告法第十一条）：「累计成交 N 笔」只能来自库里的实时数字，最好注明「本站订单统计」。「1000+ 用户」「99.9% 成功率」「最快 10 分钟到账」都是被删掉的编造内容（第二十八节），不能写回来。
- **与代码行为不一致就是虚假宣传**（第二十四节第 8 条②，同一类错误出现了 7 处）：收银台只有支付宝（不能写微信）；下单强制登录、不填邮箱；接码是 SMS 交付、没有卡密；KYC 是 MANUAL 交付；订单页没有卡密输入框。**改任何买家看得到的说明之前，先去代码里确认这个动作真的存在。**
- **价格口径**：标价不含税，开票需另付 6%（`lib/invoice.ts`）。凡是把「可开增值税发票」当卖点写的地方，都要带上「（标价不含税，开票需另付 6% 税费）」（第二十四节第 10 条）；**接码单与余额充值暂不支持自助开票**（D37），接码相关文案里不能出现「可开票」。
- **价格数字不写死**：blurb 与静态 meta 里写死的价格，调一次价就成了假话（`registry.ts` grok-super 段的注释）。meta 里写「￥135 起」的，只能取自 `withLivePrice` 或在调价时同步改。
- **原价 / 划线价**：只能用本站真实的历史成交价（《明码标价和禁止价格欺诈规定》要求被比较价格真实）。「官方价 20 美元」这类第三方价格可以写，但必须写「以官方页面为准」并与实际对得上（claude-max 页现有写法）。**不要在 SEO 片段里写「比官方便宜 X%」**。
- **评价**：不能编造评价，也不能输出假的 `aggregateRating`（电子商务法第十七条；Google 人工处罚会作用于整个域名，第十九节第 4 条）。`sales` 是销量，不能冒充评分。
- **不能承诺做不到的结果**：「不封号 / 防封 / 保证可用」不能写，全站口径是「质保订阅，不质保封号」。「包过、不成功不收费」只能**原样引用商品页的承诺**并注明是哪一档，不能推广到整个品类，也不进 title。
- **不贬低同行**（广告法第十三条）：落地页讲「怎么判断卖家靠不靠谱」时只写判断标准，不点名同行。

### 2.4 OpenAI / Anthropic / ChatGPT / Claude 商标，以及「不得冒充官方」

- **可以做的（指示性使用）**：用对方的商标说明本站服务的对象，例如「ChatGPT Plus 充值」「Claude Pro 会员充值」。必须用文字、必要、不引人误认。服务条款第一节已经写明：「我们不是 OpenAI、Anthropic……的官方代理、经销商或合作伙伴……本站使用这些名称仅用于说明所代充值服务的对象」。**这一段不能删**，它既是买家纠纷的防线，也让站点避开 Google 的品牌冒充处罚（第二十四节第 5 条①）。
- **禁止**：
  - 用本站指代「官方」：官方渠道、官方直充、官方授权、官方合作伙伴、官方认证、授权经销商、代理商、正版授权、官方旗舰；
  - 站名、产品名、子域名里带 GPT、ChatGPT、Claude、OpenAI、Anthropic（例如 chatgpt.bigolab.com、「贝果 GPT」）。OpenAI 的品牌规范不允许在产品或 App 名称里用「GPT」，也不允许暗示合作或背书；Anthropic 的商标规范同样禁止暗示赞助、背书或合作关系。反不正当竞争法第七条与《网络反不正当竞争暂行规定》第七条把「擅自将他人有一定影响的商业标识作为域名主体部分」「设置为搜索关键词，引人误认」都列为混淆行为；
  - 使用对方 logo 或近似图形（目前 `public/` 下只有本站的站标，保持这样）；
  - 「ChatGPT 中文版 / ChatGPT 国内版 / ChatGPT 官网 / ChatGPT 镜像 / Claude 中文版」这类说法：搜索量大，但会让人以为本站就是对方的产品，属于混淆；「镜像站」还会引出境外 AI 服务访问的另一类监管问题；
  - 「翻墙、梯子、VPN、节点、机场、科学上网、免翻墙、国内直连」：涉及未经许可的跨境访问，全站都不要出现。落地页里「家宽 IP / 机房 IP」属于解释注册失败原因的说明，可以保留，但不能进标题；
  - 竞价或 SEO 里拿竞品品牌、上游品牌（HeroSMS、SMS-Activate）当关键词。

## 3. 短信接码的 SEO 措辞红线

### 3.1 依据

- 《反电信网络诈骗法》第十四条第（三）项：任何单位和个人不得非法制造、买卖、提供或者使用「批量账号、网络地址自动切换系统，**批量接收提供短信验证、语音验证的平台**」。第三十一条第一款：不得非法买卖、**出租**、出借电话卡、**短信端口**、互联网账号，**不得提供实名核验帮助**。最高检公开过「易码」接码平台以帮信罪定罪的案例（调研 §5.3）。
- 法发〔2025〕12号第 5 条第（1）项把「批量接收提供短信验证、语音验证的平台」列为「可以认定明知」的情形（设计 §8.6「内部参考」，只供律师评审，**不对买家展示，也不要写进任何页面**）。第（3）项「事先准备应对调查的话术口径」——所以条款只写能核实的事实，SEO 文案同样如此。
- 站点自己的《短信接码服务条款》（`JIEMA_TERMS_VERSION = 2026-10-01`）：用途限定为「仅限用于学习交流、软件开发测试，以及为你本人合法注册、验证账号等合法用途」；禁止批量注册、养号、囤号、出售账号、为他人规避实名核验与风控、转售号码与验证码、脚本或接口批量调用、接入其他接码平台；自身服务写「临时分配号码并转发短信」，**不写「租用 / 出租」**；平台留存账号、订单、同意记录（IP / UA）、短信内容，并依法报告。
- **SEO 文案必须与条款一致**。营销页如果写着条款明令禁止的用途，就是在给「明知」提供证据，比条款写得再严都更有分量。

### 3.3 接码页面结构上的硬约束

- **收录条件**（D28、§1.3、Q6）：`/jiema` 与 `/jiema/terms` 只有在 `jiemaPublicOpen`（配置有效、总开关开、受众为全部用户）时才能 index 并进入 sitemap。灰度期输出 noindex，导航项也不显示。**SEO 方案不能要求提前收录「即将开放」页。**
- **FAQPage 只在 `v.access === 'OPEN'` 时输出**，文字必须和页面上看得到的一致（`jiema/page.tsx` 页尾）。FAQ 每一条都要能在代码里找到出处（§8.3）。
- **title / description 不主动出现国内平台名**（Q6）；中文关键词在对全部用户开放前，要用 Google 下拉建议接口实测（站点惯例）。现行 title「短信接码 - 海外手机号在线接收验证码」、description「……没收到短信整单退回站内余额，收码前可免费换号」在措辞上是合规的，关键词本身还需要实测。
- **`/jiema?s=<服务>` 不可能成为服务级 SEO 入口**：主站 robots.txt 有 `Disallow: /*?s=`（原本是为分享参数设的），canonical 也固定指回 `/jiema`。页面上「热门服务」链接用的正是 `?s=`，爬虫不会跟进。服务级长尾只能走设计里的 P2 `/jiema/[slug]`（白名单 slug + 服务端渲染 + 真实价格与下单入口 + 按第二十四节第 3 条的 doorway 四条自查）。
- **不做「服务 × 国家」批量页**（例如 700 个服务 × 185 个国家/地区）：这正是 doorway 与 scaled content abuse 的典型形态，而且 Google 的判定是站点级的，会连带商品页一起掉下去。
- 号码页、记录页一律 noindex；渠道站整组 404（`notFoundOnChannel`，D11），接码与钱包只在主站提供。
- 视觉与素材：不用上游的图标 CDN（不盗链）；不模仿它「白底 + 紫色主按钮 + 左侧抽屉」的外观（§1.13）。

### 3.4 相邻风险（不属于接码板块，SEO 扩张时需要知道）

- **账号类商品**（`/chongzhi/google-zhanghao` 的「成品号」、`claude-zhuce` 里的「普号」）与**KYC 代办**（`/chongzhi/claude-kyc`「活人认证代办」）：反电诈法第三十一条第一款同时覆盖「非法买卖互联网账号」和「提供实名核验帮助」，站点自己的接码条款也禁止用户「为他人规避实名核验」。这两类是否构成「非法」、KYC 代办的具体做法是否涉及他人身份，本文判断不了，**需要站长或律师确认**。SEO 上的建议是：**不把它们作为本轮扩张方向**，不新增「XX 账号购买」类页面；KYC 页的措辞保持现在的「协助完成、你本人需同步配合」，**不写「代过 / 代实名 / 代刷脸 / 借用身份 / 包过 KYC」**。
- 推荐返现、抽奖：营销文案不写「躺赚 / 稳赚 / 月入」（广告法第二十五条禁止对收益作保证性承诺），也不写「必中 / 百分百中奖」。

## 4. 之前轮次踩过的坑与禁改项（带出处，改之前先核对）

**关键词**
1. 词先实测，再进标题：用 Google 下拉建议接口（`suggestqueries.google.com/complete/search?client=firefox&hl=zh-CN&q=`）。「代开」就是凭感觉放进来的零需求词（第二十四节第 1 条）。
2. 零需求词不进 title / H1：代开、代购、代订阅、AI 会员代充、AI 代充、gemini 代充；同义词排序为「购买 > 充值 > 代充」。「代充」只接信任审查意图。「会员」对 Claude 成立，对 ChatGPT 不成立。**不要建「AI 会员代充」品类聚合页**。
3. 同一意图只做一页（「代充 / 充值 / 怎么充值 / 多少钱」拆成四页就是 doorway），加页面前对照第二十四节第 3 条的四条判定。

**落地页与结构化数据**

4. 落地页一律不加 `'use client'`；商品按规则匹配、不写死 ID（线上 ID 已经断号）；Plus 页的规则必须带 `nameNone: ['pro']`。
5. 落地页只输出 BreadcrumbList、FAQPage、ItemList，**不输出 Product**（Product / Offer 只放在 `/products/[id]`），也不输出 HowTo。
6. **`/chongzhi` 的 9 个落地页现在不要重构**（第二十八节「审计明确叫停」第 3 条）：可能正在被 ChatGPT 引用的就是最厚的那几页，而我们还不知道具体是哪一页。已给出的方向是**把 chatgpt-plus 的结构复制到 claude-pro 和 claude-max**，属于增量改动，不改 URL。
7. 不把 `cardUsage` 原文渲染进正文（里面有「封号99%的原因……」这类负面素材，会被 LLM 摘走）。
8. FAQ 不会跟着库更新（价格表会）。改商品档位时要回头核对 FAQ（claude-max 曾写错「本站上架的是 Max 5x 档」，这句话还进了 FAQPage）。
9. `lib/seo/jsonld.tsx` 的转义用 ``String.raw`\u` ``，改完必须跑 `scripts/check-jsonld.ts`；源码里不要写 `\u2028` / `\u2029` 转义。
10. 结构化数据里引用和被引用的节点必须在同一页输出（Offer.seller 用 `@id` 引用时，同页要有 organizationJsonLd）。

**canonical、robots、meta**

11. 根 layout 不写 canonical；**带子路由的 layout 里也不写 canonical**（`games`、`forum` 都犯过）。canonical 只写在页面自身。
12. `?ref=` 靠 canonical 处理，不要加进 robots Disallow（加了就读不到 canonical）；结构化数据里的价格只认公开价。
13. Disallow 与 noindex 互斥：私密页用 `noindex, follow`，不用 Disallow，也不用 nofollow（第二十八节）；只有带 token 或邮箱的 `/receipt/`、`/pay/`、`/lookup` 等保持 Disallow。
14. Next 的 metadata 是按顶层键整块替换，不是深合并：子页写了 `openGraph` 就会把根 layout 的 images 顶掉，所以统一用 `lib/seo/og.ts` 的 `OG_IMAGES`。
15. meta description 兜底按「够不够用」判断（阈值 40 字），不能有什么简介就直接用。
16. 首页的 H1 与数字必须由服务端直出真值（Typewriter、CountUp 曾让服务端 HTML 变成空 H1 和「0 用户」，而 ChatGPT-User 抓首页抓了 29 次）。
17. 新增环境变量必须列进 docker-compose 的 app `environment:`，否则静默失效（第十九节第 6 条）；compose 里写裸变量名。
18. IndexNow 只对必应等生效，Google 不支持；Google 的收录只看 sitemap 与 Search Console。

**GEO（被 AI 引用）**

19. 主站 robots 对 OAI-SearchBot、ChatGPT-User、ClaudeBot **不能封**（chatgpt.com 是最大的外部来源，第二十七节）；想被引用，就要结构化、给具体数字、有可核验的主体。
20. 来源归类：域名按点切分匹配，不用子串（`chatgpt.com` 曾被 `t.co` 规则误判）；会话归因。改埋点前先看第二十七节。

**大事记**

21. 薄页 noindex 保持；不给 news / digest 整体加 noindex；不收缩新闻 sitemap；六处 AI 标识与选题黑名单改动前必须先确认（SKILL §10）。

**接码**

22. 导航不加「余额充值」（导航里的「充值」指 `/chongzhi`，D16）；接码导航文案「短信接码」，窄屏显示「接码」。
23. 条款正文与版本号同进同退：改 `jiema-wallet.ts` 或 `jiema-legal.ts` 里任何一个字都要升版本并更新指纹（`scripts/check-jiema-terms.ts`）。**SEO 不要去改条款文字。**
24. 站长已拍板、不许加回来的限制：默认屏蔽名单（Q2）、上游余额停售线（Q4）、充值总额上限（Q5）。SEO 文案也不要写「不支持 XX 平台」来暗中屏蔽。

**其他**

25. 营销邮件是 opt-out（站长已拍板），与 SEO 无关，别顺手改。
26. 收据页有自己的中性标题（第二十九节第 7 条），不要给它加品牌或商品字眼的 title。
27. `/forum` 要先限流再对爬虫开放（第二十八节叫停第 4 条）。
28. 百度：裸域注册，每日配额 10 条留给商业页；站点未备案，百度至今没有带来过订单，优先级低。**文案里不要宣称「已备案」或挂备案号。**

## 5. 渠道分站 lulu 与 SEO 的关系

- **定位**（多渠道设计 D1、§4.8）：lulu.bigolab.com 对买家来说也是「贝果科技」，外观与文案逐字相同，差异只在可售商品、售价和客服。它是**同一内容、不同价格**的副本，所以**永远不参与索引**：
  - 根布局在渠道站输出 `robots: noindex, follow`，子页面全部继承；nginx 另外加 `X-Robots-Tag: noindex, follow`，形成第二道保险；
  - robots.txt 对 GPTBot、OAI-SearchBot、ChatGPT-User、ClaudeBot、PerplexityBot、Google-Extended、CCBot、Bytespider **整站 Disallow**，理由是不给答案引擎一份「另一个价格」；对其他 UA 不写 `Disallow: /`，否则爬虫读不到 noindex；
  - sitemap 返回空数组，不输出 sitemap 行，不输出站长平台验证 meta，商品页不输出 Product JSON-LD；
  - 新闻、论坛、游戏、友链、`/chongzhi`、IP 工具、`/jiema`、`/wallet` 在渠道站一律 404。
- **SEO 上的含义**：
  1. 全部 SEO 权重只集中在 bigolab.com，**不要试图让 lulu 获得排名**，不要去掉它的 noindex，也不要给 lulu 做 hreflang 或跨域 canonical（跨域 canonical 会把渠道价与主站页绑在一起，而 D1 的决定是 noindex）。
  2. **不要开关键词子域名**（chatgpt.、jiema.、ai.bigolab.com）：nginx 已经把 `*.bigolab.com` 通配到渠道模式，新开的子域名会自动 noindex，而且第二十四节第 3 条明确把「为关键词变体开多个域名 / 子域」列为 doorway 的判定之一。
  3. 主站页面不要链接到渠道站（会把买家带去看价差，D1 第 2 条的比价问题）。
  4. SEO 改动如果涉及 `layout.tsx`、`robots.ts`、`sitemap.ts`、`lib/seo/graph.ts`，必须同时保持渠道分支的行为不变（这些文件都按店面分支；`robots.ts` 依靠 `getStorefront()` 转成动态，**不能包进 try**）。回归用 `scripts/itest-tenant/*`。
  5. `TENANT_DATA_KEY` 不要动；「停业」不可逆（记忆条目），与 SEO 无关，但别在调试时误操作。

## 7. 顺带发现的现存问题（只读，未改动；交给写方案的人或站长决定）

1. **`/about` 的 title 含零需求词**：`about/layout.tsx:15` 为「关于贝果科技 - AI 会员代充服务商 - 贝果科技」，与「零需求词不进 title」的结论冲突，建议改成「……AI 会员充值服务商……」或其他实测过的词。同页 `about/page.tsx:137` 的「全球顶尖的 AI 服务」属于绝对化用语（指的是第三方服务，风险低，但改掉没有成本）。
2. **隐私政策第一节写着「你在下单时填写的邮箱地址」**（`privacy/page.tsx:71`），与「下单强制登录、不填邮箱」的事实口径不一致（外部渠道订单的 `/lookup` 场景可能用得上，但原文没有区分）。AI 可能把这句话抽出来引用，建议改成「账号邮箱」或写明适用场景。改隐私政策需要同步 `PRIVACY_UPDATED_AT`。
3. **`/jiema/layout.tsx` 在带子路由的 layout 里写了 `canonical: '/jiema'`**：`/jiema/order/[orderNo]` 与 `/jiema/records` 会继承这个 canonical（`/jiema/terms` 自己覆盖了）。这两页都是 noindex，实际影响很小，但它正是第二十四节第 8 条④所说的问题，建议把 canonical 挪到 `jiema/page.tsx`。
4. **`/jiema/order`、`/jiema/records` 用的是 `noindex, nofollow`**，与第二十八节「私密页改成 noindex, follow」的口径不一致（登录墙后面，影响小）。
5. **`/jiema` 没有自己的 openGraph**，于是整块继承根布局：og:title 和 og:description 是首页的「ChatGPT Plus / Claude Pro 充值与代充」，微信分享卡片会显示错。建议补上 `openGraph: { images: OG_IMAGES, title, description, url: '/jiema' }`（同第二十八节的 og 那个坑）。
6. **`/jiema?s=` 被 `Disallow: /*?s=` 挡住**，热门服务链接爬虫跟不进去（见 §3.3）。这不是 bug，但做接码长尾之前必须先有 `/jiema/[slug]`。
7. **全站页脚只有主体名称，没有营业执照信息或链接**：电子商务法第十五条要求在首页显著位置持续公示营业执照信息（或链接）。它同时也是「主体可核验」这张信任牌与 E-E-A-T 的最强证据，建议站长决定是否补上。
8. **账号类商品与 KYC 代办**的措辞风险，见 §3.4，需要站长或律师确认。

## 8. 需要站长或律师拍板的事

- 「AI 资讯」能不能当 `/news` 的主关键词：本文建议不要，用「AI 动态」。如果搜索数据显示「AI 资讯」的量远高于「AI 动态」，可以放在 description 或次标题里，**但不要做 title 主词，也不要自称「资讯平台」**。
- 接码服务 slug 落地页的白名单：只列境外服务，每个 slug 都要过下拉实测与 doorway 自查。
- 账号类商品与 KYC 代办的合规判断（§3.4）。
- 是否在页脚公示营业执照（§7 第 7 条）。
