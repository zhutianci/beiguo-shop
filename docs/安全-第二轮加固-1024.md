# 第二轮安全加固（2026-10-24）

> 站长 10-24：攻击越来越频繁，要求加强①支付接口与回调接口（很多 IP 在试探回调）②管理员账户风控（防盗号）
> ③越权检测（下单、发货等必须是已登录且有权限的账户），并补充其它该加强的。
> 本文 = 线上证据 + 现状盘点 + 方案。第一轮见 `docs/安全-攻防加固设计-1015.md`。

## 一、这 9 天线上实际发生了什么（生产库 audit_events + nginx 日志）

| 日期 | 蜜罐：不存在的接口 | 蜜罐：盲猜支付回调 | 自动封 IP |
|---|---|---|---|
| 10-15 ~ 10-21 | 每天 10~23 次 | 0~2 次 | 每天 0~5 个 |
| **10-22** | **76 次 / 24 个 IP** | **15 次 / 5 个 IP** | **55 次** |
| 10-23 ~ 10-24 | 31 次 / 31 个 IP | 0 | 1 |

- 10-22 那一波来自 AWS（2600:1f14…、44.245.200.65）、Tor 出口（185.220.239.50）、国内移动（111.34.74.113）等，**一个 IP 被封就换下一个**。
  封禁全部生效（被封 IP 的登录 / 下单 / 付款都被挡），但「封 IP」本身追不上分布式扫描。
- **10-22 16:29–16:39（UTC）199.102.218.24 暴力破解验证码**：先发找回密码码，再 8 分钟内试了 61 次重置密码（第 31 次起全被限流）、
  30 次「邮箱查订阅」验证码。目标是一个 `tes***@gmail.com`，**不是管理员**。限流守住了，但这个 IP 没被封，可以反复来。
- 真实回调 `/api/pay/sms-notify` 在日志窗口里只有 57 次、全部 200、全部来自站长两台手机；盲猜回调的都打在不存在的路径上（蜜罐）。
- **旧的回调 key 还在被接受**：`VMQ_WEBHOOK_ACCEPT_LEGACY=1` 没删，而旧 key 最后一次合法使用是 10-18 11:51——6 天来它只是一扇开着的后门（旧 key 强度不足、10-18 进过日志）。
- 10-21 08:25 管理员在新设备输对密码、触发了邮箱验证码但没完成登录（站长确认是本人）。上线以来**还没有一次走新流程的管理员登录**——站长一直在用 10-15 之前签的 30 天老 token。
- **仍然没有自动数据库备份**（备份任务 10-15 起没跑成）。
- 依赖：Next 14.2.35 是 14.x 最后一版，npm audit 报 1 个严重 + 若干高危，绝大部分只在 15.5+ 修复。
  逐条核对：图片优化 RCE（`images.unoptimized`，/_next/image 404）、Server Action 相关（nginx 见 `Next-Action` 头一律 400）、
  WebSocket SSRF（nginx 清空 Upgrade）、Pages Router i18n 绕过（本站是 App Router）都**已被现有配置挡住**；剩余主要是 RSC 拒绝服务类，靠限流兜底，升级 Next 15/16 另立项。

## 二、方案

### 2.1 支付与回调（站长重点①）

现状：回调 token 常量时间比较、只收 POST、不认 URL 里的 token、来源 App 白名单 + 通知格式五行锚定、金额全站唯一只匹配待付单、正文抹掉密钥后才落库——
**单条请求伪造不了，唯一的命门是 token 本身**：谁拿到它，就能伪造一条「你已成功收款 X 元」把自己的待付单标成已付、白拿卡密。

| # | 改动 | 要构建吗 | 站长要做的 |
|---|---|---|---|
| P1 | **立刻关掉旧 key**：删 `VMQ_WEBHOOK_ACCEPT_LEGACY`（6 天没被合法使用过） | 否，重启 app 约 5 秒 | — |
| P2 | **签名模式**：SmsForwarder 自带「Secret」签名——每次请求带 `timestamp` 与 `sign = HMAC-SHA256(timestamp + "\n" + secret)`，**secret 本身不再出现在请求里**。服务端只认 10 分钟内的时间戳、每个签名只能用一次（重放无效）。过渡期 token 与签名都认，两台手机改完后关掉 token | 是 | 两台手机 SmsForwarder：填 Secret、把请求体模板换成后台给的新模板 |
| P3 | **回调只收中国大陆来源**（Cloudflare 的 `CF-IPCountry`）：10-22 那批全是海外 / Tor。可配置，手机出国或开 VPN 时可临时放开 | 是 | 确认收款手机不开 VPN |
| P4 | 回调 token / 签名连续错误 → 该 IP 封 1 小时并推告警（现在只告警、不封） | 是 | — |
| P5 | 后台「收款监控」不再每 10 秒把明文 token 发给浏览器；要看密钥须二次验证（见 2.2 M3） | 是 | — |

### 2.2 管理员账户（站长重点②）

现状：密码 + 新设备邮箱验证码 + 受信设备 30 天 + 管理员 token 12 小时 + 新 IP 告警（10-15 上线）。缺口：
**第二因素就是邮箱**——gmail 被盗 = 找回密码 + 收验证码一条龙，后台整个拿走；敏感操作（导出卡密、手工标已付、改余额、改收款码）只要登录态，
登录态（cookie）被偷就能直接做；10-15 之前签的 30 天管理员 token 还活着。

| # | 改动 | 说明 |
|---|---|---|
| M1 | **身份验证器（TOTP）**：后台「安全」里扫码绑定（微软 / 谷歌身份验证器、1Password 等都行），之后管理员登录 = 密码 + 6 位动态码；附 10 个一次性恢复码 | gmail 被盗也进不了后台；邮箱验证码只在没绑身份验证器时用（过渡） |
| M2 | 上线时作废所有老的管理员登录态（会话版本 +1） | 站长重新登录一次 |
| M3 | **敏感操作二次验证**：导出 / 查看明文卡密、手工标已付 / 补单 / 退入余额、改余额 / 提现、改收款码、改用户角色、绑定机器人管理员、查看回调密钥 → 10 分钟内要再输一次动态码（或密码） | 偷到登录态也做不了这些事 |
| M4 | 每次管理员登录成功都推告警（现在只在新 IP 推）；管理员密码连续输错 3 次推告警 | 被盗号能第一时间知道 |
| M5 | `JWT_SECRET` 轮换（现 26 位，偏短）| 全站用户要重新登录一次，建议与上线同一晚做 |

### 2.3 越权（站长重点③）

（全量路由审计结果见第三节）另加两道「以后也漏不了」的机制：
- **构建期强制检查**：每个后台接口必须调 `adminGuard` / `requireAdmin`、每个定时任务接口必须 `assertCronAuth`、每个渠道后台接口必须走 `partnerRoute`——
  漏写一个，构建直接失败（挂进现有的构建前检查，和 tenant-boundary 同一处）。
- **运行时越权探测**：买家去取别人的订单 / 接码单（对象存在但不属于他）时记一次；10 分钟 5 次 → 封号 + 告警。现在这类请求只回 404、不留痕。

## 四、实施记录（分支 `sec/hardening-1024`）

**支付与回调**
- `api/pay/sms-notify`：签名优先、token 次之（`VMQ_WEBHOOK_ACCEPT_TOKEN=0` 关 token）；`lib/security/webhook-sign.ts` 是算法、时间窗、防重放（单测）。
  签名模式开着时仍用 token 的，记 `settings.vmq_token_auth_at`（10 分钟最多写一次），后台据此显示「还有手机在用 token」。
  认证失败计入 `lib/security/abuse.ts` 的 `WEBHOOK_AUTH`（10 分钟 5 次封 IP 1 小时 + 审计 + 告警）；**回调本身不看 IP 封禁**（配错又改好的手机不会漏单）。
- 后台「收款监控」：显示认证模式（签名 / 签名 + token / 仅 token）、手机最近一次用 token 的时间；Webhook 模板按模式给（签名模式用 `[timestamp]` / `[sign]` 占位符，不含任何密钥）。

**管理员**
- `lib/security/sudo.ts` + `POST /api/admin/security/sudo`：再输一次登录密码 → 10 分钟的 `adm_sudo` cookie（绑 userId + 会话版本，httpOnly、SameSite=Strict）。
  同一管理员 10 分钟最多试 5 次，第 3 次错推告警。`components/admin/sudo-gate.tsx` 在后台全局拦 `403 needSudo` → 弹框要密码 → 自动重放原请求（各页面不用改）。
- 要二次验证的接口：卡密明文 / 导出 / 新增 / 删除 / 批量；订单标已付、改金额、退款、取消已付单（`orders/[id]` PUT 按字段判）、补发、重新结算、售后；
  补单 / 未匹配到账处理 / 退入余额；改余额、推荐返现；机器人管理员与绑定；发票导出；渠道结算（打款、凭证、退回…）、渠道押金 / 调账 / 核销 / 收款账户；
  删外部订单；改用户角色；安全设置（名单、解封）；看回调密钥。应急：`ADMIN_SUDO=0`。
- `lib/security/admin-2fa.ts`：每次管理员登录成功都推告警（新 IP 在标题里标出）；管理员密码 15 分钟错 3 次推告警（每小时 1 条）。

**越权**
- `lib/security/probe.ts` 新信号 `IDOR`：登录买家取「存在但属于别人」的订单（`orders/[id]/{invoice,receipt,sms,sms/retry,messages}`、`pay/vmq/create`），
  10 分钟 5 张不同的 → 封号 + 封 IP（响应照旧 404，不暴露订单存在）。
- 构建规则（`scripts/check-tenant-boundary.mjs`，`prebuild` 里跑）：**19** cron 每个 handler 必须 `assertCronAuth(`；**20** 用登录态的写 handler 必须路由内同源校验。

**其它**
- `lib/security/abuse.ts` 的 `AUTH_THROTTLED`：登录 / 发码 / 验证码 / 邮箱查订阅被限流，同一 IP 10 分钟 15 次 → 封 1 小时。
- nginx（`nginx/nginx.conf`「第二轮加固」段）：扫描器路径 404 不进 Node；`limit_req` 三档（登录 30/分 突发 20、写接口 120/分 突发 60、全站 20/秒 突发 200，
  收款回调 / 外部发卡 API / 后台写接口不归写接口档）、429 回 JSON；安全日志 `data/nginx-sec/security-YYYY-MM-DD.log`（**日期按 UTC**；
  记：扫描路径、400/405/413/429/444、写请求与后台路径的 401/403、auth / pay / admin 的写请求、/api 下的 404）。
- `lib/news/rate-limit.ts` 新增 `rateFull`（只看不记）。

**测试**：`scripts/check-security-1024.ts`（52 条，不连库）；`scripts/itest-security-1015.ts` 加了二次验证、密钥、改角色、卡密打码几段；
nginx 用临时容器做了 28 条行为验证（扫描路径、三档限流、回调豁免、日志落盘）。

## 五、部署步骤

1. 通知其他会话；打回滚标签；`git pull`。
2. `.env.production` 加 `VMQ_WEBHOOK_SECRET=$(openssl rand -hex 24)`（**不进聊天、不进文档**；不要 chmod 600）。`VMQ_WEBHOOK_ACCEPT_TOKEN` 先不设（过渡期 token 照认）。
3. `mkdir -p data/nginx-sec && chown 101:101 data/nginx-sec`；宿主机 crontab 加
   `17 4 * * * find <仓库>/data/nginx-sec -name 'security-*.log' -mtime +30 -delete`。
4. wrapper 构建（停 jishi，约 3 小时，`build_exit=4` 是正常）→ `up -d --no-deps app` → `up -d --no-deps --force-recreate nginx`。
5. 冒烟：首页 200、`/wp-login.php` 404、`/zh-hk/api/cron/x` 404、登录、收款回调用 token 仍 200、后台打开卡密明文要输密码。
6. 站长：两台手机 SmsForwarder → Webhook 填 Secret（后台「收款监控 → 显示密钥」）、请求体换成后台给的签名模板；
   后台显示「最近一次用 token」不再更新后，`.env.production` 加 `VMQ_WEBHOOK_ACCEPT_TOKEN=0` 再 `up -d app`。
