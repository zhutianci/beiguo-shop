# 后台仪表盘重做 / 后台流畅性 / 成交弹窗去价格 / 付款后引导 —— 部署说明（2026-10-13）

三项改动一次构建上线。**没有数据库与环境变量改动**，只换 app 镜像。代码：main `acbf4d8..6f07584`（三个提交）。

## 一、改了什么

### 1. 首页成交弹窗不再显示成交价（`fd5548d`）

站长要求：各人成交价不同（内推专属价、优惠券、改价），弹窗里摆价格只会引来「为什么他更便宜」。

- `components/live-order-notification.tsx` 去掉价格；`/api/orders/recent` 不再下发 `amount`（响应只剩 `id / productName / displayName / city`）。
- `scripts/itest-tenant/wp2.ts` 里「成交滚动只含主站单」原来靠金额 140 区分渠道单，现在接口没有金额，改为断言「可用且不含金额字段」；
  「只取本店」仍由接口 where 里的 `tenantId` 保证（代码未动）。

### 2. 付款后引导（`af0fb89`）

起因：很多买家付完款回到订单列表，不知道卡密和充值入口在「发货详情」里。

- **付完款直接打开这一单的发货详情**：收银台状态接口对普通商品单多返回 `next=/orders?paid=<订单号>`（`lib/pay-next.ts` 的白名单加了这一种格式）；
  收银台「支付成功」页写明「正在打开这笔订单的发货详情」并给「立即查看」按钮；订单页读到 `?paid=` 后在列表第一次拉回来时自动打开那一单，
  随后把地址栏参数去掉（刷新、后退不会再弹）。接码单 / 充值单 / 税费单的去向不变。
- **发货详情**：顶部「支付成功」提示（仅自动打开那一次）；卡密区提到最上面，带三步指引（复制卡密 → 点「去充值 / 兑换」→ 按页面提示完成），
  复制按钮有「已复制」反馈，底部给「联系客服」（切到这一单的在线沟通）。
- **订单卡片**：已发卡密的单，提示从「服务已交付」改为「卡密已发放。还没充值的话，点『去充值 / 兑换』…」，并直接给绿色主按钮：
  一单一卡且有兑换地址 → 直达兑换页（站内兑换已带好卡密）；多张卡或没有兑换地址 → 打开发货详情。原「发货详情」按钮保留（有卡密时写作「发货详情（卡密）」）。
- 兑换入口的判断收成一个 `redeemEntry()`，卡片与弹窗共用。没有改任何服务端的发卡 / 兑换逻辑。

### 3. 后台仪表盘重做 + 流畅性（`6f07584`）

**仪表盘（`/admin`）**

- 新接口 `GET /api/admin/stats/overview?days=7|30|90`，聚合在 `lib/admin/overview.ts`（纯函数，自检 `scripts/check-admin-overview.ts`）。
- 页面：深色「经营概览」（今日流水 / 今日利润 / 近 N 天流水 / 近 N 天利润，各带环比与迷你走势）→ 流水曲线、利润曲线（各自纵轴，悬停看某天明细）
  → 每日成交单数、商品流水排行 → 待办与累计（待发货 / 待支付 / 今日充值 / 累计收入 / 累计订单 / 用户 / 商品）→ 短信接码 → 最近订单 → 明细分析。
- **口径**（页面上有同样的说明）：
  - 流水 = 站内订单实收（已付款未取消、不含余额充值，按到账日）+ 外部导入订单的报价（按开通日，不含 SHOP / WEB 批次）。
  - 利润 = 卡密利润（按发出日；已取消 / 已退款的单不计、不扣内推返现——沿用 10-12 定的口径）+ 外部导入订单的利润。
  - 人工服务单与短信接码没有逐单成本，不在利润曲线里。日切点北京时间 0 点。
- 图表是手写 SVG（`components/admin/dashboard/charts.tsx`），没有引图表库——这台机器的构建内存已经很紧。
- 原来的「外部订单导入分析」「卡密数据分析」两块保留，收进页面底部「明细分析」的两个标签里，滚到附近才加载。

**流畅性**

| 改动 | 原因 |
|---|---|
| `app/admin/loading.tsx` 骨架屏 + 后台挂上路由进度条 | 根布局按请求渲染、后台又没有 loading 边界：点菜单后要等服务端返回，期间页面不动，像「没点上」 |
| 仪表盘首屏请求从 5 个减到 2 个；上次的数据先显示、后台静默刷新（sessionStorage） | 进后台第一屏、也是来回切得最多的一屏 |
| `/api/admin/stats` 的几段统计改为并发 | 原来先后 await 五段 |
| 订单列表「只翻页」时不重算合计（`totals=0`，页面沿用上一份） | 合计要取出筛选范围内全部订单 id 再去三张表聚合，是这个接口最重的一段，而它与页码无关 |
| 收款监控的 10 秒轮询：标签页在后台时不拉；定时刷新不再闪「加载中」 | 这个接口一次十几条查询，忘关的标签页会一直打库 |
| 侧栏红点不再每次切页都拉（改为进后台、每 60 秒、切回标签页时） | 每点一次菜单多两个请求，和新页面自己的数据请求抢数据库连接 |
| 卡密页「按批次精确筛选」加 350ms 防抖 | 原来每敲一个字打一次列表接口 |

排查时确认**不是**问题的：鉴权（每请求一次主键查询）、卡密解密（密钥已缓存）、索引、数据量（订单与卡密都只有两三千行）。
